## 10. 技术选型与 ADR

### ADR-001: 原型衔接协议载体——内嵌 design-stage-execution vs 独立技能文档

| 维度 | 内容 |
|:-----|:------|
| **决策标题** | 原型 IN/OUT 衔接协议写入哪个技能文档 |
| **上下文** | RT-217-001 需要定义外部原型导入规范，涉及 design/coding/testing 三个阶段 |
| **备选方案 A** | 内嵌 design-stage-execution（主控技能承载协议主体 + 其他技能补充小节）。优点：与既有 Step 2 流程天然衔接，AI 执行 Step 2 时自动加载；缺点：design-stage-execution 文档增长 |
| **备选方案 B** | 独立"原型衔接规范"技能文档。优点：文档独立；缺点：多一层引用，AI 执行时不会自动加载，与 DevFlow"技能自包含"原则冲突 |
| **决策** | **方案 A：内嵌 design-stage-execution（+2 个技能补充小节）** |
| **理由** | 与 v2.15.0/v2.16.0 ADR 决策一致（技能自包含）。原型衔接是 Step 2 设计的固有组成部分，应内嵌于 Step 2 主控技能 |
| **已知后果** | design-stage-execution 增长 ~35 行；coding/testing 各增长 ~15/~10 行 |

### ADR-002: 原型导入场景组织——统一流程 vs 分场景独立流程

| 维度 | 内容 |
|:-----|:------|
| **决策标题** | 3 种原型导入场景（Figma/独立设计/已有原型）的流程组织方式 |
| **上下文** | RT-217-001 需定义 3 种场景的导入流程，场景间存在公共步骤（RT-ID 映射/coverage 检查）|
| **备选方案 A** | 统一流程 + 场景差异说明：定义标准导入流程（5 步），3 场景通过差异点适配。优点：避免重复，结构清晰；缺点：场景差异大时说明冗长 |
| **备选方案 B** | 3 个独立流程段落：每个场景完整描述。优点：各自完整；缺点：公共步骤重复 3 次，文档冗长 |
| **决策** | **方案 A：统一流程 + 场景差异说明** |
| **理由** | 3 场景共享"建立 RT-ID 映射 + prototype-coverage 检查 + 缺口补充"核心步骤，仅入口不同。统一流程减少重复，差异说明控制篇幅 |
| **已知后果** | 读者需对照差异说明理解场景，通过"场景入口表"缓解 |

### ADR-003: 预研交付形式——设计阶段预研 vs 开发阶段预研

| 维度 | 内容 |
|:-----|:------|
| **决策标题** | V216-004 网络层巡检自动化预研的执行时机 |
| **上下文** | RT-217-004 为预研型需求，验收标准要求产出预研报告 |
| **备选方案 A** | Step 3 开发阶段执行预研：编码开始后预研。优点：可结合实际环境验证；缺点：若不可行会浪费开发窗口 |
| **备选方案 B** | Step 3 开发阶段开头执行预研（Phase 3 对应）：设计阶段只设计预研输出格式。优点：预研结论指导后续开发方向，避免浪费；缺点：预研本身不产出代码 |
| **决策** | **方案 B：开发阶段开头执行预研（Phase 3 前置），设计阶段确定输出格式** |
| **理由** | 预研结论（可行/不可行）决定 V216-004 是否实施，应在开发投入前获得结论。设计阶段先锁定输出格式保证可验收 |
| **已知后果** | Phase 3 需预留预研时间窗口；若不可行 V216-004 降级，Phase 3 剩余工作量仅剩 RT-217-005 |
