## 1. 设计概述

本版本为 **Hotfix 版本**，聚焦于现有技能文件（.md）和脚本文件（.ps1）的修复、增强与标准化，**不涉及系统架构变更**，**不引入新服务、新 API 或新数据模型**。

### 设计目标

| 目标 | 说明 |
|------|------|
| **修复 BUG** | 修复 validate-install.ps1 中 PowerShell 5.1 兼容性语法错误 |
| **增强质量管控** | 强化验证证据要求、新增偏执级代码审查维度、新增 TDD 合规检查 |
| **标准化格式** | 按 skill-md-writing-standards 规范统一 22 个旧版技能文件格式 |

### 变更范围总览

| 变更类型 | 数量 | 说明 |
|----------|------|------|
| BUG 修复 | 1 项 | VR-001 validate-install.ps1 语法修复 |
| 规则增强 | 1 项 | VR-002 coding-stage-execution.md 验证证据强制化 |
| 检查项新增 | 2 项 | VR-003 code-logic-review.md 偏执级检查；VR-004 testing-stage-execution.md TDD 合规检查 |

| 功能增强 | 1 项 | VR-006 check-skill-format.ps1 自动填充能力 |

## 2. 需求到设计的映射

### VR-001 BUG 修复（优先级：P0）

| 项目 | 内容 |
|------|------|
| **需求描述** | 修复 validate-install.ps1 中 PowerShell 5.1 兼容性语法错误 |
| **设计思路** | 脚本第 133 行使用 `Test-Path ... -and ...` 语法，在 PowerShell 5.1 中因 `-and` 运算符优先级问题导致语法错误。将复合条件拆分为两个独立的 `Test-Path` 调用，再用 `-and` 连接，确保在 PS5.1 和更高版本中均能正确执行。 |
| **涉及文件** | `scripts/validate-install.ps1` |
| **修改类型** | BUG 修复 |
| **影响范围** | 仅限脚本文件内单行语法调整，不影响外部接口和行为逻辑 |

### VR-002 验证证据强制化（优先级：P0）

| 项目 | 内容 |
|------|------|
| **需求描述** | 在 coding-stage-execution.md 中增强验证证据要求，确保完成前必须强制验证 |
| **设计思路** | 在 "强制规则" 章节中增强第 6 条规则，补充以下内容：<br>1. "完成前必须强制验证"的详细说明：明确验证时机（代码合并前）、验证主体（开发者自验）、验证范围（所有新增/修改的功能）<br>2. 验证证据格式模板：定义标准化的验证证据记录格式，包括验证人、验证日期、验证结论、验证截图/日志路径等必填字段<br>3. 验证不通过的阻断机制：验证未通过时不得提交代码 |
| **涉及文件** | `skills/L2/coding-stage-execution.md` |
| **修改类型** | 规则增强 |

### VR-003 偏执级代码审查（优先级：P1）

| 项目 | 内容 |
|------|------|
| **需求描述** | 在 code-logic-review.md 中新增偏执级（Paranoid Level）代码审查检查项 |
| **设计思路** | 在现有审查维度基础上新增 3 项偏执级检查项：<br>1. **N+1 查询检测**：检查数据库访问代码中是否存在循环内执行 SQL 查询的模式，要求使用批量查询或延迟加载优化。检查规则：遍历所有循环体内的数据访问调用；通过标准：零 N+1 查询模式。<br>2. **竞态条件检测**：检查共享资源访问是否存在未加锁或非原子操作导致的竞态条件。检查规则：识别所有共享变量/资源的并发访问路径；通过标准：所有共享资源访问均通过原子操作或锁机制保护。<br>3. **信任边界违规检测**：检查是否在未验证身份/权限的上下文中执行了敏感操作。检查规则：识别所有跨越信任边界的操作（文件读写、网络请求、权限提升等）；通过标准：所有跨信任边界操作均经过身份验证和授权检查。 |
| **涉及文件** | `skills/L3/code-logic-review.md` |
| **修改类型** | 检查项新增 |

### VR-004 TDD 证据链（优先级：P1）

| 项目 | 内容 |
|------|------|
| **需求描述** | 在 testing-stage-execution.md 中新增 TDD 合规检查行项 |
| **设计思路** | 在测试规范矩阵中新增 "TDD 合规检查" 行项，要求：<br>1. 验证每个 feat/fix 类型的 Git 提交是否包含先于生产代码编写的测试文件<br>2. 检查测试文件与生产代码文件的提交时间戳顺序<br>3. 通过 Git 日志和文件变更列表自动或人工核查 TDD 合规性<br>4. 不合规的提交需补充测试后方可进入下一阶段 |
| **涉及文件** | `skills/L2/testing-stage-execution.md` |
| **修改类型** | 检查项新增 |

### VR-005 格式标准化（优先级：P2）

| 项目 | 内容 |
|------|------|
| **需求描述** | 按 skill-md-writing-standards 规范标准化 22 个旧版技能文件 |
| **设计思路** | 对 22 个旧版技能文件逐一补充缺失的标准章节，包括但不限于：<br>1. 元信息（文件名、版本、描述、分类标签）<br>2. 定位说明（技能在 DevFlow 体系中的层级和角色）<br>3. 触发条件（何时调用该技能）<br>4. 输入/输出定义<br>5. 使用示例<br>仅补充格式和元信息，不改动原有语义逻辑和功能内容 |
| **涉及文件** | `skills/` 下 22 个旧版文件（具体路径列表待 Step 3 编码阶段确认） |

### VR-006 自动填充能力（优先级：P2）

| 项目 | 内容 |
|------|------|
| **需求描述** | 为 check-skill-format.ps1 增加自动检测缺失标准章节并填充模板内容的能力 |
| **设计思路** | 1. 在现有格式检查逻辑基础上，增加对标准章节头部的正则匹配检测<br>2. 检测到缺失章节时，从预定义的模板库中取出对应章节模板内容<br>3. 按文件原有结构顺序，在合适位置插入缺失的章节模板<br>4. 支持 dry-run 模式（仅报告缺失不实际填充）和实际填充模式<br>5. 提供操作日志记录所有自动填充操作 |

| **修改类型** | 功能增强 |

## 3. 设计约束

### 技术约束

| 约束项 | 具体要求 |
|--------|----------|
| **PS5.1 兼容性** | 所有 `.ps1` 脚本必须兼容 PowerShell 5.1，避免使用仅在 PowerShell 7+ 中支持的语法和 cmdlet |
| **技能文件格式** | 所有技能文件必须遵循 `skill-md-writing-standards` 规范中定义的文件结构、元信息格式和章节组织方式 |
| **无架构变更** | 本版本不引入新服务、新组件、新外部依赖，不修改项目目录结构 |
| **无破坏性变更** | 不改动技能文件的语义逻辑和功能行为，仅做修复、增强和格式标准化 |
| **向后兼容** | 脚本修改后必须保持与现有调用方（如 CI/CD 流水线）的兼容性 |

### 设计准则

- **最小改动原则**：在满足需求的前提下，尽可能减少对现有文件的修改范围
- **显式优于隐式**：验证规则、检查标准和格式要求均以显式文本记录，避免依赖隐式约定
- **可验证性**：每项修改均应附带明确的验证方法和通过标准

## 4. 适用范围与排除项

### 适用范围

本设计文档覆盖 v2.4.1 版本全部 6 项需求（VR-001 ~ VR-006）对应的文件修改设计。

### 排除项

以下设计领域在本版本中 **不涉及**，无需评审：

| 排除领域 | 说明 |
|----------|------|
| API 设计 | 本版本不涉及新 API 或现有 API 的变更 |
| 数据库设计 | 本版本不引入新数据模型或修改现有数据模型 |
| UI/UX 设计 | 本版本不涉及用户界面或交互体验变更 |
| 部署架构 | 本版本不修改部署拓扑、环境配置或发布策略 |
| 安全设计 | 本版本不涉及安全机制变更（信任边界检查仅作为审查维度而非安全架构变更） |
| 性能设计 | 本版本不涉及性能优化或容量规划 |
| 可观测性设计 | 本版本不涉及日志、指标或链路追踪的变更 |
