## 1. 概述

### 1.1 设计范围

本文档定义 DevFlow v2.4.0 所有用户界面（UI）的设计规范与交互原型。DevFlow 的 UI 不是传统 Web 应用，而是 **CLI 终端交互界面 + HTML 文档输出** 的组合形态，其界面体验主要体现在以下四个需求项中：

| 需求编号 | 需求名称 | 交互类型 | 设计章节 |
| --- | --- | --- | --- |
| VR-001 | 交互式安装向导 | CLI 终端交互 | [第 3 章](#3-vr-001-安装向导界面设计) |
| VR-002 | 项目初始化向导增强 | CLI 终端交互 | [第 4 章](#4-vr-002-初始化向导界面设计) |
| VR-005 | 安装验证测试 | CLI 终端输出 | [第 5 章](#5-vr-005-验证测试输出设计) |
| VR-003 | 快速入门指南 | HTML 文档页面 | [第 6 章](#6-vr-003-快速入门-html-页面设计) |

### 1.2 设计原则

DevFlow 的 UI 设计遵循以下核心原则：

| 原则 | 说明 | 适用范围 |
| --- | --- | --- |
| **CLI 优先** | 所有交互以终端命令行为主界面，不依赖 GUI 框架，保证在最小环境即可运行 | 安装向导、初始化向导、验证测试 |
| **信息清晰** | 状态信息使用颜色 + 图标 + 文字三重编码，确保关键信息一目了然 | 所有 CLI 输出、HTML 文档 |
| **操作简单** | 采用向导式交互，每步仅问一个问题，提供默认选项减少用户决策负担 | 安装向导、初始化向导 |
| **错误友好** | 错误信息包含原因描述和可操作的恢复建议，避免技术术语堆砌 | 所有错误场景 |
| **风格一致** | CLI 交互界面与 HTML 文档输出共享统一的设计语言和视觉规范 | 全部界面 |

## 2. 设计规范

### 2.1 CLI 视觉规范

#### 2.1.1 边框样式

CLI 交互界面使用 Unicode 框线字符构建结构化容器，分为双线框和单线框两种样式：

**双线框** — 用于标题、重要信息、结果汇总等需要强调的场景：

```
╔══════════════════════════════════════════════════╗
║  标题内容                                          ║
╠══════════════════════════════════════════════════╣
║  内容区域                                          ║
║  内容区域                                          ║
╚══════════════════════════════════════════════════╝
```

**单线框** — 用于次要信息、补充说明等场景：

```
┌──────────────────────────────────────────────────┐
│  内容区域                                          │
│  内容区域                                          │
└──────────────────────────────────────────────────┘
```

**分隔线** — 用于章节之间的视觉分隔：

```
─── 章节标题 ──────────────────────────────────────
```

**字符集**：

| 字符 | 用途 |
| --- | --- |
| `╔` `╗` `╚` `╝` | 双线框四角 |
| `╠` `╣` | 双线框水平分隔（顶部/底部横线与竖线交汇） |
| `║` | 双线框竖线 |
| `═` | 双线框横线 |
| `┌` `┐` `└` `┘` | 单线框四角 |
| `│` | 单线框竖线 / 表格竖线 |
| `─` | 单线框横线 / 分隔线 / 表格横线 |
| `├` `┤` `┬` `┴` `┼` | 单线框交汇点 / 表格交汇点 |

**使用规则**：
1. 以 80 字符宽度为基准设计，兼容最小 60 字符宽度的终端窗口
2. 中英文混排时，一个中文字符占 2 个字符宽度，框线宽度计算需按实际显示宽度对齐
3. 内容文本与边框竖线之间保留 1 个字符的间距

#### 2.1.2 颜色映射（ANSI）

DevFlow CLI 使用 ANSI 转义码实现终端色彩，色彩分配遵循语义一致性原则：

| 色彩类别 | 色值 | ANSI 转义码 | 用途 | 使用场景 |
| --- | --- | --- | --- | --- |
| **成功绿** | `#00FF00` | `\033[32m` | 表示通过、完成、正常状态 | 环境检测通过、安装完成、验证通过 |
| **警告黄** | `#FFFF00` | `\033[33m` | 表示可选缺失、建议注意 | 可选依赖未安装、版本升级提示 |
| **错误红** | `#FF0000` | `\033[31m` | 表示失败、错误、必需项缺失 | 环境不满足、安装失败、验证不通过 |
| **信息蓝** | `#00BFFF` | `\033[34m` | 表示标题、提示、引导信息 | 步骤标题、菜单项、提示文本 |
| **进度灰** | `#808080` | `\033[90m` | 表示进度条背景、次要信息 | 进度条底色、分隔线、说明文字 |
| **高亮白** | 白色加粗 | `\033[1m\033[37m` | 表示当前步骤、重点强调 | 当前步骤指示器、关键数据 |
| **重置** | 默认 | `\033[0m` | 恢复默认颜色 | 每段色彩输出后必须调用 |

**使用规则**：
1. 每段带颜色的输出结束后 **必须** 调用颜色重置 `\033[0m`
2. 同一行避免使用超过 2 种颜色
3. 不使用闪烁、反色等可能干扰阅读的特殊效果
4. 脚本启动时检测终端 ANSI 支持能力，不支持时自动禁用色彩

#### 2.1.3 字符图标

DevFlow CLI 使用 Unicode 字符图标辅助状态识别，同时提供 ASCII 降级方案：

| Unicode 图标 | ASCII 替代 | 含义 | 颜色 |
| --- | --- | --- | --- |
| `✓` | `[OK]` | 成功 / 通过 | 绿色 |
| `✗` | `[FAIL]` | 失败 / 错误 | 红色 |
| `⚠` | `[WARN]` | 警告 / 注意 | 黄色 |
| `ℹ` | `[INFO]` | 信息 / 提示 | 蓝色 |
| `→` | `>` | 当前步骤 / 指向 | 白色加粗 |

**降级策略**：
- 脚本启动时自动检测终端 Unicode 支持能力
- 不支持 Unicode 时降级为 ASCII 文字替代方案
- 两种模式均可正确传达状态信息，不依赖单一编码方式

#### 2.1.4 进度条

进度条使用纯文字字符实现，不依赖 ANSI 光标控制或全屏刷新：

**格式规范**：

```
[=====>          ] 25%
```

| 属性 | 规范 |
| --- | --- |
| 总宽度 | 20 个字符 |
| 已完成部分 | `=` 字符填充 |
| 当前位置 | `>` 字符，指向最后一个已完成位置 |
| 未完成部分 | 空格字符 |
| 百分比 | 显示在进度条右侧，格式为 `N%` |
| 前缀 | 步骤描述，显示在进度条左侧 |

**进度阶段示意**：

```
[                    ]   0% - 等待开始
[=>                  ]   5% - 初始化中
[====>               ]  25% - 复制技能文件
[========>           ]  50% - 复制模板文件
[============>       ]  75% - 生成配置文件
[==================>] 100% - 完成
```

#### 2.1.5 输入方式规范

DevFlow CLI 支持四种标准输入交互方式：

| 输入方式 | 格式说明 | 使用场景 |
| --- | --- | --- |
| **单选菜单** | 数字编号 + 选项文本 + 默认标记 `[推荐]` | 项目类型选择、分支策略选择 |
| **多选菜单** | 数字编号 + 选项文本 + 空格分隔输入 | 模板选择、技能选择 |
| **文本输入** | 提示文字 + `>` 光标 + 格式说明 | 仓库名称、项目名称输入 |
| **确认提示** | Yes/No 选项 + 默认标记 `(Y/n)` 或 `(y/N)` | 危险操作确认、覆盖确认 |

#### 2.2.3 响应式断点

| 断点名称 | 宽度范围 | 适配说明 |
| --- | --- | --- |
| **桌面端** | >= 1024px | 标准布局，侧边导航水平展示，步骤导航水平排列 |
| **平板端** | >= 480px 且 < 1024px（含 768px） | 侧边导航折叠为顶部标签栏，内容区域缩窄，代码块可水平滚动 |
| **移动端** | < 480px（含 480px） | 侧边导航折叠为汉堡菜单，代码块全宽显示，字号缩小 |

**响应式断点规则**：
- 代码块在小屏幕下允许水平滚动，不自动换行
- 步骤导航在移动端转为垂直堆叠布局
- 顶部标题区域在移动端缩小字号
- FAQ 折叠区域全宽适配所有断点
- 布局转换使用 CSS Media Query 实现

## 3. VR-001 安装向导界面设计

### 3.1 界面流程

安装向导共 5 个步骤，按顺序执行：

```
欢迎页 → 环境检测 → 配置引导 → 安装执行 → 结果汇总
```

| 步骤 | 名称 | 用户交互类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 欢迎页 | 确认提示（按 Enter 继续） | 展示版本信息，等待用户确认开始 |
| 2 | 环境检测 | 仅输出（自动） | 自动检测运行环境并展示结果 |
| 3 | 配置引导 | 单选菜单 + 文本输入 | 引导用户选择分支策略和配置远程仓库 |
| 4 | 安装执行 | 仅输出（自动） | 展示安装进度 |
| 5 | 结果汇总 | 仅输出（自动） | 展示安装结果摘要和下一步指引 |

### 3.2 步骤 1 — 欢迎页

**行为描述**：安装脚本启动后展示欢迎界面，显示版本基本信息，等待用户按 Enter 开始安装。按 Ctrl+C 可随时退出。

**终端原型**：

```
╔══════════════════════════════════════════════════╗
║  DevFlow Plugin Installer v{version}              ║
║  软件开发工程规范插件 一键安装向导                  ║
╠══════════════════════════════════════════════════╣
║  版本: {version} ({totalLines} 行代码)            ║
║  技能: {skillCount} 个                            ║
║  模板: {templateCount} 个                         ║
║                                                  ║
║  按 Enter 开始安装，或按 Ctrl+C 退出               ║
╚══════════════════════════════════════════════════╝
```

**设计说明**：
- 标题行使用蓝色（信息色）显示
- 版本统计信息使用灰色（进度色）显示
- 操作提示使用白色加粗（高亮色）显示
- 动态变量（`{version}`、`{totalLines}`、`{skillCount}`、`{templateCount}`）在脚本执行时替换为实际值

### 3.3 步骤 2 — 环境检测

**行为描述**：用户确认开始后自动执行环境检测，逐项检查操作系统、Git、PowerShell/bash、Node.js（可选）、网络连通性，并检测是否已安装旧版本。检测结果使用带状态图标的列表展示。

**终端原型 — 检测中**：

```
╔══════════════════════════════════════════════════╗
║  → 环境检测中...                                   ║
╠══════════════════════════════════════════════════╣
║  ✓ 操作系统: Windows 11 (x64)                    ║
║  ✓ Git: 2.45.0                                  ║
║  ✓ PowerShell: 5.1.19041                         ║
║  ✗ Node.js: 未安装 (可选)                         ║
║  ✓ 网络连通性: 正常                               ║
║  ℹ 已安装版本: v2.3.2 (将升级到 v2.4.0)           ║
╚══════════════════════════════════════════════════╝
```

**状态标记说明**：

| 标记 | 颜色 | 含义 | 示例 |
| --- | --- | --- | --- |
| `✓` | 绿色 | 检测通过 | `✓ Git: 2.45.0` |
| `✗` | 红色 | 必需项缺失或失败 | `✗ Git: 未安装` |
| `⚠` | 黄色 | 可选项缺失 | `⚠ Node.js: 未安装 (可选)` |
| `ℹ` | 蓝色 | 信息性提示 | `ℹ 已安装版本: v2.3.2` |
| `→` | 白色加粗 | 当前正在执行的步骤 | `→ 环境检测中...` |

**终端原型 — 环境检测失败（必需项缺失）**：

```
╔══════════════════════════════════════════════════╗
║  ✗ 环境检测失败                                     ║
╠══════════════════════════════════════════════════╣
║  ✗ Git: 未安装                                   ║
║                                                  ║
║  Git 是 DevFlow 的必需依赖。请先安装 Git 后重试。   ║
║                                                  ║
║  下载地址: https://git-scm.com/downloads          ║
╚══════════════════════════════════════════════════╝
```

**异常处理**：
- 必需项（操作系统不兼容、Git 未安装、PowerShell/bash 版本过低）缺失 → 显示错误提示并提供安装指引后退出
- 可选项缺失 → 显示黄色警告但允许继续安装

### 3.4 步骤 3 — 配置引导

**行为描述**：环境检测通过后，引导用户选择分支策略和配置远程仓库。用户通过输入数字编号进行选择，提供默认推荐选项。

**终端原型 — 分支策略选择（单选菜单）**：

```
─── 配置引导 ─────────────────────────────────────

请选择分支策略:
  [1] git-flow       (推荐，适合正式项目)
  [2] feature-branch (适合敏捷团队)
  [3] trunk-based    (适合持续部署)

请输入选项 [1-3] (默认: 1): _
```

**终端原型 — 远程仓库配置（文本输入）**：

```
─── 远程仓库配置 ─────────────────────────────────

请输入 DevFlow 远程仓库地址 (可选，直接回车跳过):
> _
提示: 格式为 https://xxx 或 http://xxx
```

**终端原型 — 确认提示**：

```
─── 配置确认 ─────────────────────────────────────

  分支策略:     git-flow
  远程仓库:     (未配置)

确认以上配置并开始安装? (Y/n): _
```

**输入验证与错误反馈**：

```
⚠ 无效输入，请输入 1-3 之间的数字
请输入选项 [1-3] (默认: 1): _
```

```
⚠ 格式不正确，仓库地址应以 https:// 或 http:// 开头
请重新输入 (直接回车跳过):
> _
```

### 3.5 步骤 4 — 安装执行

**行为描述**：配置确认后开始执行安装。安装过程中使用纯文字进度条实时展示安装状态，每个步骤完成后更新进度。

**终端原型**：

```
─── 正在安装 DevFlow v2.4.0 ──────────────────────

  [====>                ] 25% - 复制技能文件
  [========>            ] 50% - 复制模板文件
  [============>        ] 75% - 生成配置文件
  [================>] 100% - 完成
```

**安装步骤定义**：

| 进度范围 | 步骤名称 | 说明 |
| --- | --- | --- |
| 0%-25% | 复制技能文件 | 将 skills/ 目录下所有 SKILL.md 复制到目标路径 |
| 25%-50% | 复制模板文件 | 将 templates/ 目录下所有模板文件复制到目标路径 |

## 7. 状态设计

本章定义 DevFlow 在各类交互场景下的状态展示规范，覆盖空态、加载态、错误态和成功态四种通用状态。

### 7.1 空态（首次使用）

**适用场景**：用户首次安装或首次运行 DevFlow 时，尚未进行任何配置。

**CLI 空态展示**：

```
╔══════════════════════════════════════════════════╗
║  ℹ 欢迎使用 DevFlow                                ║
╠══════════════════════════════════════════════════╣
║                                                  ║
║  检测到当前项目尚未初始化 DevFlow。                  ║
║                                                  ║
║  请先运行以下命令初始化项目:                          ║
║    → 调用 devflow-init 技能                        ║
║                                                  ║
║  初始化完成后，DevFlow 将自动推断项目阶段并引导       ║
║  你进入正确的开发流程。                               ║
║                                                  ║
╚══════════════════════════════════════════════════╝
```

**HTML 空态展示**：
- 显示欢迎引导卡片
- 包含快速开始按钮（如 "安装 DevFlow"）
- 提供简要功能介绍（3-4 条要点列表）

**设计要点**：
- 使用友好语气，避免技术术语堆砌
- 明确告知用户下一步操作
- 提供直接可执行的引导路径

### 7.2 加载态

**CLI 加载态**：

```
─── 正在处理，请稍候... ──────────────────────────

  [========>           ] 40% - 正在分析项目结构
```

**设计规范**：
- 使用进度条展示加载进度（见 [2.1.4 进度条](#214-进度条)）
- 进度条下方显示当前步骤的文字描述
- 超过 5 秒的加载操作应显示进度百分比
- 无法估算进度的操作显示旋转等待指示：

```
─── 正在分析项目结构... ──────────────────────────
  (o_o) 正在处理中，请稍候
```

**HTML 加载态**：
- 使用 CSS 动画实现旋转加载图标
- 加载区域使用半透明遮罩
- 超过 3 秒显示 "加载中..." 文字提示

### 7.3 错误态

**CLI 错误态**：

```
╔══════════════════════════════════════════════════╗
║  ✗ 操作失败                                       ║
╠══════════════════════════════════════════════════╣
║  错误: {错误类型}                                  ║
║  原因: {错误原因描述}                               ║
║                                                  ║
║  建议操作:                                        ║
║    1. {恢复选项 1}                                 ║
║    2. {恢复选项 2}                                 ║
║    3. {恢复选项 3}                                 ║
║                                                  ║
║  相关文档: {文档路径或链接}                         ║
╚══════════════════════════════════════════════════╝
```

**HTML 错误态**：
- 红色边框 + 浅红色背景的错误提示框
- 包含错误描述文字
- 提供可点击的 "重试" 按钮
- 提供修复建议的折叠区域

**设计要点**：
- 错误信息使用非技术性语言描述
- 每个错误必须包含至少 1 条可操作的恢复建议
- 提供重试机制，避免用户陷入死胡同

### 7.4 成功态

**CLI 成功态**：

```
✓ 操作完成

下一步: {下一步操作描述}
  → {具体操作或命令}
```

**HTML 成功态**：
- 绿色边框 + 浅绿色背景的成功提示框
- 包含确认文字和下一步操作引导
- 提供可点击的下一步链接或按钮

**设计要点**：
- 成功信息简洁明确，使用绿色图标和颜色
- 始终提供下一步操作引导，帮助用户继续流程
- 避免冗余的成功确认信息

## 8. 无障碍设计

### 8.1 CLI 终端无障碍

| 规范项 | 要求 | 实现方式 |
| --- | --- | --- |
| **不依赖颜色传达信息** | 状态信息不能仅通过颜色区分，必须同时使用图标 + 文字描述 | 使用 `✓`/`✗`/`⚠`/`ℹ` 图标 + 文字描述双重编码 |
| **图标降级方案** | 在不支持 Unicode 图标的终端中，使用 ASCII 文字替代 | `[OK]` 替代 `✓`，`[FAIL]` 替代 `✗`，`[WARN]` 替代 `⚠`，`[INFO]` 替代 `ℹ` |
| **高对比度** | 文字与背景的对比度不低于 4.5:1 | ANSI 颜色搭配默认终端背景色 |
| **屏幕阅读器兼容** | 输出文本应可被屏幕阅读器正确朗读 | 避免使用纯装饰性字符序列，状态图标后跟随文字描述 |
| **输入提示清晰** | 所有需要用户输入的位置必须有明确的提示 | 使用 `> _` 或 `请输入: _` 明确标识输入位置 |

**自动检测与降级策略**：
1. 脚本启动时检测终端 Unicode 支持能力
2. 不支持 Unicode 时自动切换为 ASCII 图标集
3. 检测终端 ANSI 色彩支持能力
4. 不支持 ANSI 色彩时自动禁用所有颜色输出

### 8.2 HTML 文档无障碍

快速入门指南 HTML 文档遵循 **WCAG 2.1 AA** 级别无障碍要求：

| WCAG 准则 | 要求 | 实现方式 |
| --- | --- | --- |
| **1.1.1 非文本内容** | 所有图片和图标必须有 alt 文本 | 装饰图标添加 `aria-hidden="true"`，功能性图标添加 `aria-label` |
| **1.3.1 信息和关系** | 使用语义化 HTML 标签 | `<nav>` 导航、`<main>` 主内容、`<section>` 章节、`<h1>`-`<h4>` 层级标题 |
| **1.3.2 有意义的顺序** | DOM 顺序与视觉顺序一致 | 步骤内容按逻辑顺序排列，CSS 布局不改变阅读顺序 |
| **1.4.3 对比度** | 文字与背景对比度 >= 4.5:1 | 主文字色 `#E2E8F0` 在主背景 `#0A1628` 上对比度 11.7:1 |
| **2.1.1 键盘** | 所有交互可通过键盘完成 | FAQ 折叠支持 Enter/Space 键，步骤导航支持 Tab 键切换 |
| **2.4.1 跳过区块** | 提供跳过导航链接 | 页面顶部提供 "跳到主内容" 链接（`<a href="#main">`） |
| **2.4.3 焦点顺序** | 焦点顺序符合逻辑 | Tab 顺序: 导航 → 步骤标签 → 内容 → FAQ |
| **2.4.6 标题和标签** | 标题清楚描述内容 | 每个步骤使用描述性标题，FAQ 使用问题作为标题 |
| **3.1.1 页面语言** | 声明页面主要语言 | `<html lang="zh-CN">` |
| **4.1.2 名称和角色** | 自定义组件有正确的 ARIA 角色 | FAQ 折叠使用 `role="button"` + `aria-expanded` |

**对比度验证**：

| 组合 | 前景色 | 背景色 | 对比度 | 是否达标 |
| --- | --- | --- | --- | --- |
| 主文字 | `#E2E8F0` | `#0A1628` | 11.7:1 | 达标 (>= 4.5:1) |
| 次要文字 | `#94A3B8` | `#0A1628` | 6.2:1 | 达标 (>= 4.5:1) |
| 强调色文字 | `#00B4D8` | `#0A1628` | 7.8:1 | 达标 (>= 4.5:1) |
| 代码文字 | `#E2E8F0` | `#1A1A2E` | 10.5:1 | 达标 (>= 4.5:1) |
