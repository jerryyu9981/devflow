## 1. 概述

### 1.1 文档目的

本文档是 DevFlow v2.4.0 版本的**非功能设计说明**，作为 Step 2 架构与设计阶段的专项设计文档。本文档合并了安全设计、性能设计、兼容性设计、可维护性设计和可观测性设计五个维度，将 Step 1 开发需求文档中定义的非功能需求（NFR-001 ~ NFR-023）转化为具体的设计方案和实施策略，为后续编码（Step 3）和测试（Step 4）提供非功能维度的设计输入和验收依据。

### 1.2 适用范围

- 安装脚本（install.bat、install.ps1、install.sh）

- 构建脚本（build.ps1）
- 全部 SKILL.md 技能文件（L1/L2/L3/Orchestrator 四层）
- 全部模板文件
- 全部 HTML 文档（用户指南等）
- 配置文件（config.json、state.json、version.json）

## 2. 性能设计

### 2.1 性能目标

| 指标 | 目标值 | 度量方式 | 对应需求 ID |
|---|---|---|---|
| 安装到首次运行时间 | < 10 分钟 | 端到端计时测试（从运行安装脚本到安装完成并可使用） | NFR-001 |
| 安装脚本执行时间 | < 60 秒 | 脚本计时（不含用户交互等待时间） | NFR-001 |
| 技能加载时间 | 无感知延迟 | AI 平台加载测试（用户主观评估无明显等待） | NFR-002 |
| 质量检查脚本执行 | < 30 秒 | 脚本计时（全量检查场景） | NFR-003 / NFR-005 |
| 引用检查脚本执行 | < 15 秒 | 脚本计时（全量检查场景） | NFR-004 |
| 格式检查（单文件） | < 1 秒 | 脚本计时 | NFR-005 |
| 初始化向导全流程 | < 2 分钟 | 端到端计时测试 | NFR-006 |

### 2.2 性能设计策略

#### 2.2.1 技能文件按需加载

DevFlow 技能文件以 SKILL.md 格式存储，加载机制由 AI 平台控制（非 DevFlow 可控）。设计要求：

- **单文件体积控制**：单个 SKILL.md 文件不超过 2000 行，确保 AI 平台可在合理时间内完成解析
- **分层加载**：L1（编排层）仅引用 L2（阶段执行层）入口，L2 按需引用 L3（专项参考层），避免一次性加载全量技能
- **内容精炼**：技能文件内容聚焦核心指令和规则，避免冗余描述，减少 token 消耗

#### 2.2.2 检查脚本串行执行

- 所有检查脚本（质量检查、引用检查、格式检查）采用串行执行策略，避免引入并发复杂度
- 每个检查脚本内部按文件顺序处理，逐文件输出结果
- 检查脚本提供 `--verbose` 参数控制输出详细程度

#### 2.2.3 安装脚本串行步骤化

- 安装脚本按步骤串行执行：环境检测 -> 交互配置 -> 文件安装 -> 配置生成 -> 安装验证
- 每个步骤完成后立即输出进度反馈（步骤编号、进度百分比、操作描述）
- 关键步骤设置前置条件校验，失败时快速终止避免无效等待

#### 2.2.4 HTML 文档轻量化

- HTML 文档无 JavaScript 框架依赖，采用纯 CSS 实现交互效果（动画、折叠、主题切换）
- 外部依赖仅限于必要的图表库（ECharts、Mermaid），采用按需加载策略
- 文档体积控制在 2 MB 以内，确保浏览器快速渲染

### 2.3 性能验收标准

| 验收场景 | 验收条件 | 通过标准 |
|---|---|---|
| 全新安装 | Windows 11 / macOS 14 / Ubuntu 24.04 各执行一次 | 安装脚本执行 < 60 秒 |
| 全量质量检查 | 检查全部技能文件和模板文件 | 执行时间 < 30 秒 |
| 全量引用检查 | 检查全部技能文件的交叉引用 | 执行时间 < 15 秒 |
| 初始化向导 | 新项目执行 devflow-init | 全流程 < 2 分钟 |
| 技能加载 | TRAE IDE 环境加载全部技能 | 用户感知无明显延迟 |

## 3. 安全设计

### 3.1 威胁模型

| 威胁编号 | 威胁描述 | 影响等级 | 攻击向量 | 缓解措施 | 对应需求 ID |
|---|---|---|---|---|---|
| THR-001 | 脚本执行恶意代码 | 高 | 用户安装时通过篡改的仓库地址引入恶意脚本 | 安装脚本不执行未授权网络请求，所有操作限于本地文件系统 | NFR-017 |
| THR-002 | 仓库地址注入 | 中 | 用户在交互式安装中输入恶意仓库地址 | 用户输入的仓库地址仅用于 Git clone，不解析执行任何内容 | NFR-017 |
| THR-003 | 路径遍历攻击 | 低 | 通过用户输入构造路径访问系统敏感文件 | 脚本固定操作目录（~/.trae-cn/skills、项目 .devflow/），不使用用户输入构造路径 | NFR-018 |
| THR-004 | 敏感信息泄露 | 低 | 配置文件或日志中包含用户敏感信息 | 无用户个人信息收集，配置文件不含密码、密钥等敏感信息 | NFR-020 |
| THR-005 | 权限提升 | 中 | 安装脚本被利用获取系统级权限 | 安装过程不要求 root/管理员权限，所有操作在用户权限下完成 | NFR-018 / SEC-001 |
| THR-006 | 数据篡改 | 低 | 审查/检查脚本意外修改项目文件 | 审查和检查脚本为只读操作，不修改任何文件 | NFR-019 |
| THR-007 | 备份数据外泄 | 低 | 自动备份的数据被传输到外部服务 | 安装覆盖时自动备份到本地目录，不传输到外部服务 | SEC-005 |

### 3.2 安全措施

#### 3.2.1 操作范围限制

| 措施 | 说明 |
|---|---|
| 固定操作目录 | 安装脚本仅操作以下目录：`~/.trae-cn/skills/`（技能文件安装目标）、`项目目录/.devflow/`（项目配置目录） |
| 最小权限原则 | 不要求 root/管理员权限，仅需用户目录写权限 |
| 网络请求白名单 | 安装脚本的网络请求仅限于 Git clone 用户指定的仓库地址，不发起其他网络请求 |
| Git 凭据隔离 | Git 凭据由 Git 自身管理（~/.git-credentials 或系统凭据管理器），DevFlow 不存储、不读取 |

#### 3.2.2 输入安全处理

| 措施 | 说明 |
|---|---|
| 编码安全 | 脚本使用 UTF-8 编码，避免编码注入攻击 |
| 输入验证 | 用户输入的仓库地址进行基本格式验证（以 `https://` 或 `git://` 开头） |
| 路径隔离 | 不将用户输入直接用于构造文件系统路径，所有路径基于固定目录拼接 |
| 参数转义 | Shell 脚本中的变量引用使用双引号包裹，防止 glob 展开和分词 |

#### 3.2.3 脚本安全规范

| 规范 | 说明 |
|---|---|
| 无 eval | 脚本中禁止使用 `eval`、`Invoke-Expression` 等动态执行命令 |
| 无未声明依赖 | 脚本执行前检查必要工具（Git、Node.js）是否可用，未安装时给出明确提示而非静默失败 |
| 只读操作保证 | 审查和检查脚本仅使用读取命令（`Get-Content`、`cat`、文件读取 API），不使用写入命令 |
| 日志脱敏 | 日志输出不包含用户路径中的用户名部分（仅显示目录结构） |

### 3.3 安全验收标准

| 验收场景 | 验收条件 | 通过标准 |
|---|---|---|
| 权限验证 | 在非管理员/非 root 用户下执行安装 | 安装全程不要求提权 |
| 网络请求验证 | 安装过程中监控网络请求 | 仅存在 Git clone 请求，无其他外发请求 |
| 输入安全测试 | 输入包含特殊字符的仓库地址 | 脚本正常处理或拒绝，不产生路径遍历 |
| 只读验证 | 执行审查/检查脚本前后对比文件系统 | 文件系统无变更 |

## 6. 可观测性设计

### 6.1 脚本输出规范

#### 6.1.1 日志格式

安装/验证/检查过程输出结构化日志，格式定义如下：

```
[时间戳] [级别] [模块] 消息
```

**示例**：

```
[2026-07-02 10:30:15] [INFO]  [install] 开始环境检测...
[2026-07-02 10:30:16] [INFO]  [detect]  操作系统: Windows 11
[2026-07-02 10:30:16] [INFO]  [detect]  PowerShell 版本: 5.1.22621.3880
[2026-07-02 10:30:17] [SUCCESS] [detect] 环境检测完成
[2026-07-02 10:30:20] [WARN]  [network] GitHub 仓库不可达，将使用本地文件
[2026-07-02 10:30:25] [ERROR] [install] 技能文件复制失败: skills/L3/security-design-review.md
```

#### 6.1.2 日志级别

| 级别 | 用途 | 输出流向 |
|---|---|---|
| INFO | 正常操作信息（步骤开始/完成、检测结果等） | stdout |
| WARN | 警告信息（非致命错误、可选组件跳过等） | stdout |
| ERROR | 错误信息（操作失败、异常终止等） | stderr |
| SUCCESS | 成功确认（关键步骤完成确认） | stdout |

#### 6.1.3 输出分流原则

- **stdout**：面向用户的关键操作输出（进度信息、结果摘要、成功/警告消息）
- **stderr**：面向诊断的错误消息和调试信息
- **日志文件**：安装过程同时输出日志到 `.devflow/logs/install-{timestamp}.log`

### 6.2 验证报告格式

验证和检查脚本输出结构化报告，格式为 Markdown 表格，支持机器解析和人类阅读。

#### 6.2.1 报告模板

```markdown
## 验证报告

| 检查项 | 结果 | 详情 | 修复建议 |
|--------|------|------|----------|
| 技能文件完整性 | PASS | 全部 15 个技能文件存在 | — |
| 模板文件完整性 | PASS | 全部 4 个模板文件存在 | — |

```

#### 6.2.2 报告内容要求

| 字段 | 说明 |
|---|---|
| 检查项 | 被检查的维度或文件 |
| 结果 | PASS / FAIL / WARN |
| 详情 | 检查结果的具体描述 |
| 修复建议 | FAIL/WARN 时的修复操作建议 |

### 6.3 错误追踪设计

| 错误信息要素 | 说明 | 示例 |
|---|---|---|
| 错误码 | 结构化错误标识 | `E001`（文件复制失败）、`E002`（权限不足） |
| 错误上下文 | 触发错误的操作和环境信息 | `安装技能文件时复制 L3/security-design-review.md 失败` |
| 修复建议 | 用户可执行的修复步骤 | `请检查目标目录权限，或重新运行安装脚本` |
