## 1. 性能设计

### 1.1 性能目标

v2.9.1 为 DevFlow 框架的架构精简 + 流程质量增强版本，性能设计围绕安装脚本、更新脚本和产出验证三个核心路径设定明确的性能指标。

| 指标类别 | 性能目标 | 测量基准 | 说明 |
|---------|:------:|:--------:|------|
| install.ps1 首次安装 | **≤ 30 秒** | 从脚本启动到验证通过 | 含框架下载、文件部署、IDE 集成功效 |
| update.ps1 增量更新 | **≤ 5 秒** | 从脚本启动到验证通过 | 不含下载时间，仅本地文件同步与配置更新 |
| package 模式验证（download 后） | **≤ 3 秒** | 从验证触发到结果输出 | 8 项检查，仅扫描下载包 |
| install 模式验证 | **≤ 3 秒** | 从验证触发到结果输出 | 11 项检查 |
| update 模式验证 | **≤ 4 秒** | 从验证触发到结果输出 | 13 项检查，含迁移验证 |
| init 模式验证 | **≤ 1 秒** | 从验证触发到结果输出 | 6 项检查，仅项目配置 |
| 单阶段产出验证 | **≤ 10 秒** | 从验证触发到结果输出 | 每个阶段门禁验证（OAV-Gate） |
| 配置文件读写 | **≤ 1 秒** | 单次读写操作 | JSON 配置文件解析与写入 |
| 技能文件加载 | **≤ 2 秒** | L1+L2 全量加载 | 技能文件读取与解析 |

### 1.2 性能瓶颈分析

#### 1.2.1 install.ps1 性能瓶颈

| 瓶颈点 | 预估耗时 | 占比 | 优化策略 |
|--------|:--------:|:----:|---------|
| 框架包下载 | 15-20s | ~60% | CDN 加速、断点续传、本地缓存 |
| 文件解压与部署 | 3-5s | ~15% | 增量部署、跳过已存在文件 |
| IDE 技能注册 | 3-5s | ~15% | 批量注册、异步处理 |
| 安装验证 | 2-3s | ~10% | 精简验证项、并行检查 |

**下载优化策略**：

| 优化项 | 具体措施 | 预期收益 |
|--------|---------|:--------:|
| CDN 加速 | 框架包托管于 CDN，多节点分发 | 下载时间降低 40% |
| 增量下载 | 对比本地缓存版本，仅下载差异部分 | 二次安装时间降低 60% |
| 断点续传 | 支持下载中断后续传 | 大文件下载可靠性提升 |
| 镜像源 | 支持官方源 / 镜像源切换 | 区域访问速度优化 |

#### 1.2.2 update.ps1 性能瓶颈

| 瓶颈点 | 预估耗时 | 占比 | 优化策略 |
|--------|:--------:|:----:|---------|
| 版本差异计算 | 0.5-1s | ~20% | 版本清单预计算、缓存差异结果 |
| 技能文件同步 | 1-2s | ~40% | 按差异同步、批量操作、并行复制 |
| 配置迁移 | 0.5-1s | ~20% | Schema 版本检测、按需迁移 |
| 更新验证 | 0.5-1s | ~20% | 增量验证、仅验证变更部分 |

**增量更新优化策略**：

1. **版本差异预计算：`devflow-config.json` 中包含技能版本清单，更新时仅对比版本号差异
2. **批量文件操作**：使用 PowerShell 批量复制替代逐文件复制
3. **并行处理**：技能文件复制与配置迁移并行执行
4. **验证精简**：仅验证变更的技能和配置项，而非全量验证

#### 1.2.3 产出验证性能瓶颈

| 瓶颈点 | 预估耗时 | 占比 | 优化策略 |
|--------|:--------:|:----:|---------|
| 文件存在性检查 | 2-3s | ~30% | 批量 Glob 搜索、缓存目录索引 |
| 内容关键字检查 | 3-5s | ~40% | 流式读取、关键词批量匹配 |
| 格式合规检查 | 1-2s | ~20% | Schema 缓存、增量校验 |
| 追溯关系检查 | 1-2s | ~10% | 索引预构建、增量追溯 |

**验证性能优化策略**：

| 优化项 | 具体措施 | 预期收益 |
|--------|---------|:--------:|
| 批量文件检索 | 单次 Glob 匹配替代多次 LS 调用 | 检查时间降低 50% |
| 流式内容检查 | 逐行扫描替代全量加载 | 大文件检查内存占用降低 80% |
| 验证缓存 | 相同文件哈希校验，未变更跳过 | 重复验证时间降低 90% |
| 并行验证 | 多检查项并行执行 | 总时间降低 30-40% |

## 2. 安全设计

### 2.1 安全范围评估

v2.9.1 涉及配置文件重构、脚本架构重构和产出验证门禁三大变更，安全设计覆盖以下领域：

| 安全类别 | 评估结论 | 说明 |
|---------|:--------:|------|
| 配置文件安全 | ✅ 涉及 | 敏感信息不写入配置、配置文件完整性校验 |
| 脚本执行安全 | ✅ 涉及 | 签名执行策略、BOM 修复安全、路径注入防护 |
| 权限控制 | ✅ 涉及 | IDE 系统目录写入权限、项目目录写入权限 |
| 数据安全 | ✅ 涉及 | 迁移备份数据保护、配置数据不泄露 |
| 用户鉴权 | ❌ 不涉及 | DevFlow 为本地框架，无用户认证体系 |
| 网络安全 | ⚠️ 部分涉及 | 框架下载 HTTPS 传输校验 |
| 输入校验 | ⚠️ 部分涉及 | 脚本参数校验、路径参数安全过滤 |
| 审计日志 | ✅ 涉及 | 安装/更新/迁移/验证全链路可追溯 |
| 威胁建模 | ❌ 不涉及 | 无网络暴露面，本地执行框架 |

### 2.2 配置文件安全

#### 2.2.1 敏感信息保护原则

| 原则 | 说明 | 实施方式 |
|------|------|---------|
| 最小化原则 | 配置文件仅存储必要的元数据和配置信息 | 字段白名单机制 |
| 零敏感原则 | 不存储任何密码、令牌、密钥等敏感信息 | 敏感字段黑名单校验 |
| 脱敏原则 | 如需引用外部凭据，仅存储引用路径而非实际值 | 环境变量 / 密钥管理系统引用 |

**禁止写入配置文件的敏感信息清单**：

| 类别 | 示例 | 替代方案 |
|------|------|---------|
| 认证凭据 | 密码、API Key、Token | 环境变量、系统凭据管理器 |
| 个人信息 | 邮箱、手机号、姓名 | 运行时从 Git 配置获取 |
| 私有地址 | 内部服务器地址、内网 URL | 环境变量配置 |
| 密钥材料 | 私钥、证书密码 | 系统密钥链 / 证书存储 |

#### 2.2.2 配置文件完整性校验

| 校验项 | 校验方式 | 触发时机 | 失败处置 |
|--------|---------|---------|---------|
| JSON 格式合法性 | JSON Schema 校验 | 读取配置时 | 输出错误，使用默认值 |
| Schema 版本匹配 | schemaVersion 字段比对 | 读取配置时 | 执行迁移 / 降级处理 |
| 必填字段存在性 | 必填字段检查 | 读取配置时 | 输出警告，填充默认值 |
| 字段类型正确性 | 类型校验 | 读取配置时 | 类型转换 / 默认值 |
| 版本号一致性 | 多文件版本交叉校验 | 安装/更新验证 | 输出不一致警告 |

### 2.3 脚本安全

#### 2.3.1 签名执行策略

| 策略项 | 设计 | 说明 |
|--------|------|------|
| 执行策略要求 | RemoteSigned | 本地脚本可执行，远程脚本需签名 |
| 脚本签名 | 发布版本数字签名 | 官方发布脚本附数字签名 |
| 执行前校验 | 脚本启动时验证签名 | 防止脚本被篡改 |
| BOM 处理 | UTF-8 BOM 安全修复 | 确保编码一致性，防止注入 |

**BOM 修复安全设计**：

| 风险点 | 风险描述 | 防护措施 |
|--------|---------|---------|
| 编码不一致 | 不同编辑器保存时编码不一致导致脚本执行异常 | 统一 UTF-8 BOM 检测与修复 |
| 恶意 BOM 注入 | 通过 BOM 字符隐藏恶意代码 | BOM 修复时校验脚本内容哈希 |
| 编码嗅探攻击 | 利用多字节编码注入恶意字符 | 严格 UTF-8 编码校验 |

#### 2.3.2 脚本参数安全校验

| 参数 | 校验规则 | 校验方式 | 失败处置 |
|----|---------|---------|---------|
| -ProjectPath | 必须为合法路径，不包含路径穿越字符 | 正则匹配 + Test-Path | 终止执行，输出参数错误 |
| -Version | 必须为合法版本号格式 (vX.Y.Z 或 latest) | 语义化版本正则校验 | 终止执行，输出参数错误 |
| -SkipValidation | 布尔开关，无值 | 参数类型校验 | 类型转换失败时默认 false |
| -Force | 布尔开关，无值 | 参数类型校验 | 类型转换失败时默认 false |

**路径注入防护**：
- 所有路径参数经过 `Resolve-Path` 规范化
- 禁止 `..` 路径穿越
- 路径必须位于项目根目录范围内
- 特殊字符过滤：`*?[]` 等通配符禁止用于路径参数

### 2.4 权限控制

#### 2.4.1 目录写入权限矩阵

| 目录 | 写入操作 | 权限要求 | 验证方式 |
|------|---------|:--------:|---------|
| 项目根目录 | 创建 devflow-config.json | 用户读写 | Test-Path + 写入测试 |
| .devflow/ 目录 | 配置、状态、技能文件 | 用户读写 | 目录存在性 + 写入测试 |
| doc/ 目录 | 文档产出文件 | 用户读写 | 目录存在性 + 写入测试 |
| IDE 全局目录 | 技能注册、配置副本 | 用户读写 | 目录存在性 + 写入测试 |
| 系统目录 | 无 | 无 | 不写入系统目录 |

#### 2.4.2 IDE 系统目录写入安全

| 风险点 | 防护措施 |
|--------|---------|
| 误写系统目录 | 严格限定写入路径范围，仅写入 `~/.trae-cn/skills/` 下的 devflow 子目录 |
| 权限不足 | 安装前检测目录权限，不足时提前报错并给出指引 |
| 覆盖用户文件 | 仅写入 devflow 专属子目录，不触碰其他目录 |
| 批量删除风险 | 删除操作限定在 devflow 专属目录内，使用白名单机制 |

### 2.5 数据安全

#### 2.5.1 迁移备份数据保护

| 保护项 | 措施 | 说明 |
|--------|------|------|
| 备份位置 | `.devflow/backup/` 目录 | 仅项目内可见 |
| 备份内容 | 旧配置文件、旧技能文件 | 不含敏感信息 |
| 备份权限 | 继承项目目录权限 | 与项目文件同权限 |
| 备份保留 | 至少保留最近 3 个版本 | 自动清理旧备份 |
| 备份加密 | 不加密 | 本地文件，与项目同级安全级别 |

#### 2.5.2 数据泄露防护

| 泄露途径 | 防护措施 |
|---------|---------|
| 配置文件泄露 | 配置文件不含敏感信息，泄露不影响安全 |
| 日志文件泄露 | 日志中不输出敏感字段，路径信息脱敏 |
| 错误信息泄露 | 错误信息仅包含必要的错误码和描述，不含内部路径详情 |
| 临时文件泄露 | 临时文件使用后立即清理，使用随机命名 |

## 3. 可观测性设计

### 3.1 日志规范

#### 3.1.1 日志输出格式

所有脚本和技能均采用结构化日志输出，格式统一为：

```text
[YYYY-MM-DD HH:mm:ss] [LEVEL] [MODULE] Message
```

**日志级别定义**：

| 级别 | 标识 | 使用场景 | 输出目标 |
|:----:|:----:|---------|---------|
| DEBUG | DEBUG | 调试信息，详细执行流程 | 调试模式 / 日志文件 |
| 信息 | INFO | 正常执行信息 | 控制台 + 日志文件 |
| 警告 | WARN | 非阻断性异常 | 控制台 + 日志文件 |
| 错误 | ERROR | 阻断性错误 | 控制台 + 日志文件 |
| 致命 | FATAL | 致命错误，需立即终止 | 控制台 + 日志文件 |

#### 3.1.2 日志输出渠道

| 组件 | 控制台输出 | 日志文件 | 状态记录 |
|------|:----------:|:-------:|:--------:|
| install.ps1 | ✅ | ✅ (.devflow/logs/install-{timestamp}.log) | state.json |
| update.ps1 | ✅ | ✅ (.devflow/logs/update-{timestamp}.log) | state.json |
| 迁移流程 | ✅ | ✅ (install/update 日志中) | state.json.migrationLog |
| 产出验证 | ✅ | ✅ (.devflow/logs/verify-{step}-{timestamp}.log) | state.json.verificationLog |
| 阶段技能 | ✅ | 🔵 不适用 | state.json |

#### 3.1.3 日志文件管理

| 管理项 | 策略 |
|--------|------|
| 日志位置 | `.devflow/logs/` 目录 |
| 命名规范 | `{operation}-{timestamp}.log` |
| 保留数量 | 最多保留 20 个日志文件 |
| 清理策略 | 超过数量上限时删除最旧的日志 |
| 日志级别 | 默认 INFO，可通过参数调整为 DEBUG |

### 3.2 错误码设计

#### 3.2.1 错误码体系

错误码采用 `DF-XXXX 格式，分为 4 位数字，首位表示错误类别：

| 错误码范围 | 类别 | 说明 |
|:----------:|------|------|
| DF-1000 ~ DF-1999 | 安装类错误 | install.ps1 执行过程中的错误 |
| DF-2000 ~ DF-2999 | 更新类错误 | update.ps1 执行过程中的错误 |
| DF-3000 ~ DF-3999 | 迁移类错误 | 配置迁移过程中的错误 |
| DF-4000 ~ DF-4999 | 验证类错误 | 产出验证门禁的错误 |
| DF-5000 ~ DF-5999 | 配置类错误 | 配置文件读写校验错误 |
| DF-9000 ~ DF-9999 | 通用类错误 | 通用系统级错误 |

## 4. 可靠性设计

### 4.1 容错机制

#### 4.1.1 脚本失败回滚

**install.ps1 失败回滚**：

| 失败阶段 | 回滚动作 | 回滚完整性 |
|---------|---------|:----------:|
| 环境检测失败 | 无改动，直接退出 | 100% |
| 前置检查失败 | 无改动，直接退出 | 100% |
| 下载失败 | 清理临时文件，退出 | 100% |
| 部署失败 | 删除已部署文件，恢复原状 | 95%（部分文件可能已部署） |
| IDE 集成失败 | 核心功能可用，输出警告 | 无需回滚（非核心功能） |
| 验证失败 | 可选：保留部署文件，输出失败报告 | 用户可选回滚 |

**update.ps1 失败回滚**：

| 失败阶段 | 回滚动作 | 回滚完整性 |
|---------|---------|:----------:|
| 状态检测失败 | 无改动，直接退出 | 100% |
| 版本获取失败 | 无改动，直接退出 | 100% |
| 备份失败 | 终止更新，退出 | 100% |
| 下载失败 | 无改动，退出 | 100% |
| 技能同步失败 | 从备份恢复 .devflow/ 目录 | 100% |
| 配置迁移失败 | 从备份恢复配置文件 | 100% |
| 验证失败 | 从备份完整恢复 | 100% |

#### 4.1.2 迁移失败保护

迁移流程设有五级保护机制，确保迁移过程数据安全：

| 保护层级 | 措施 | 触发条件 | 失败影响 |
|:-------:|------|---------|---------|
| L1 备份保护 | 迁移前全量备份所有旧配置 | 迁移开始前自动执行 | 无影响 |
| L2 原子写入 | 新文件先写临时文件，校验通过后原子替换 | 所有写入操作 | 无影响 |
| L3 回滚机制 | 迁移失败自动从备份恢复 | 任意步骤失败 | 自动恢复 |
| L4 手动确认 | 迁移涉及破坏性操作时要求用户确认 | 检测到字段冲突无法自动解决 | 用户决策 |
| L5 迁移日志 | 完整记录迁移过程到 state.json.migrationLog | 每次迁移 | 可追溯 |

**迁移失败检测点**：

```text
迁移流程
  ├── 备份失败 → 终止迁移，输出错误，不改动任何文件  [DF-3001]
  ├── 旧文件解析失败 → 回滚到备份状态，输出解析错误详情  [DF-3002]
  ├── 字段冲突 → 警告，尝试自动解决，无法解决则手动确认  [DF-3003]
  ├── 新文件 Schema 校验失败 → 回滚，输出校验错误  [DF-3004]
  ├── 写入失败 → 回滚，输出 IO 错误  [DF-3005]
  └── 迁移后自检失败 → 自动回滚 + 输出详细错误报告  [DF-3007]
```

### 4.2 幂等性设计

#### 4.2.1 安装幂等性

| 操作 | 重复执行行为 | 幂等保证 |
|------|-------------|:--------:|
| install.ps1 重复执行 | 检测到已安装则退出（或 -Force 覆盖） | ✅ |

#### 4.2.2 写入操作幂等性保证

| 写入操作 | 幂等策略 |
|---------|---------|
| 配置文件写入 | 先读对比，无变更则跳过 |
| 技能文件部署 | 版本号对比，相同版本跳过 |

| L2 阶段执行层 | 6 个技能 | 各阶段流程执行 | 向下依赖 L3 |
| L3 专项技能层 | 14 个技能 | 专业领域知识沉淀 | 无向下依赖 |
| 共享基础设施 | 3 类 | 配置、文档、脚本 | 被所有层依赖 |

#### 5.4.2 内部模块职责清晰

| 内部模块 | 职责 | 输入 | 输出 | 调用方 |
|---------|------|------|------|--------|
| download-devflow.ps1 | 框架包下载与校验 | 版本号、输出路径 | 下载结果对象 | install.ps1, update.ps1 |
| validate-install.ps1 | 安装有效性验证 | 项目路径、期望版本 | 验证结果对象 | install.ps1, update.ps1 |
| devflow-project-config | 配置读写封装 | 配置操作指令 | 配置数据 | 所有 L1/L2 技能 |

## 6. 兼容性设计

### 6.1 PowerShell 版本兼容

#### 6.1.1 版本支持矩阵

| PowerShell 版本 | Windows | macOS | Linux | 支持状态 |
|:--------------:|:-------:|:-----:|:-----:|:--------:|
| 5.1 (Windows PowerShell) | ✅ | ❌ | ❌ | 主力支持 |
| 7.0+ (PowerShell Core) | ✅ | ✅ | ✅ | 兼容支持 |

#### 6.1.2 兼容性设计

| 兼容项 | 设计策略 | 说明 |
|--------|---------|------|
| 最低版本要求 | PowerShell 5.1 | install.ps1 启动时检测 |
| 跨版本语法 | 使用 PowerShell 5.1 兼容语法 | 避免使用 7.x 特有语法 |
| 模块兼容性 | 使用兼容模块 | 避免使用 7.x 特有模块 |
| 编码处理 | 统一 UTF-8 BOM 处理 | 解决 5.1 与 7.x 编码差异 |

**版本检测逻辑**：

```text
脚本启动
  ↓
检测 $PSVersionTable.PSVersion
  ├── Major -ge 5 → 继续执行
  └── Major -lt 5 → 输出错误 DF-1001，终止执行
```

### 6.2 跨版本兼容

#### 6.2.1 版本升级路径

```text
v2.8.5  →  v2.9.0  →  v2.9.1
   │           │           │
   └─ 逐步迁移 ┘           │
               └─ 直接迁移 ──┘
```

| 源版本 | 目标版本 | 迁移复杂度 | 迁移时间预估 |
|:------:|:--------:|:--------:|:----------:|
| v2.8.5 | v2.9.0 | 中 | ~10s |
| v2.9.0 | v2.9.1 | 高（配置重构） | ~15s |
| v2.8.5 | v2.9.1 | 高（两步合并） | ~20s |

#### 6.2.2 自动迁移检测

| 检测项 | 检测方法 | 触发动作 |
|--------|---------|---------|
| 配置文件版本 | 读取 schemaVersion 字段 | 版本不匹配时触发迁移 |
| 旧配置文件存在 | 检查 .devflow/config.json 等 | 存在旧文件且无新文件时触发迁移 |
| 技能版本 | 对比 devflow-config.json 技能版本 | 版本不一致时更新技能 |

### 6.3 路径兼容

#### 6.3.1 旧路径自动检测

devflow-init 技能在项目初始化时自动检测旧路径并执行迁移：

| 旧路径 | 检测方式 | 迁移动作 |
|--------|---------|---------|
| `.devflow/config.json` | Test-Path | 重命名 + 字段重组 → project-config.json |
| `version.json`（根） | Test-Path | 合并 → devflow-config.json |
| `.devflow/version.json` | Test-Path | 合并 → devflow-config.json |
| `devflow-manifest.json` | Test-Path | 合并 → devflow-config.json |
| `setup.ps1` | Test-Path | 归档到 backup/legacy-scripts/ |
| `sync-skills.ps1` | Test-Path | 归档到 backup/legacy-scripts/ |

#### 6.3.2 前向兼容读取

在共存周期内（v2.9.1 - v2.10.0），技能文件支持新旧路径双读取：

```text
读取配置
  ↓
尝试读取新路径（devflow-config.json / project-config.json）
  ├── 成功 → 使用新配置
  └── 失败 → 尝试读取旧路径
            ├── 成功 → 触发自动迁移
            └── 失败 → 全新初始化
```
