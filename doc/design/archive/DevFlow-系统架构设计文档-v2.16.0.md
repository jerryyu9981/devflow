### 3.2 技术选型与 ADR

#### ADR-001: 网络层监控实现载体——规范内嵌模板 vs 独立脚本库

| 维度 | 内容 |
|:-----|:------|
| **决策标题** | E2E 网络层事件订阅能力以什么形式固化进规范 |
| **上下文** | RT-216-004 需要为测试工程师提供网络层监控能力。OpenLLM 已验证脚本（manual_scan_all_pages.py）是项目级实现 |
| **备选方案 A** | 规范内嵌代码模板：将 attach_network_listeners + assert_network_clean 完整代码写入 testing-stage-execution/SKILL.md 的 E2E 章节，使用者复制到自己的测试工程。优点：技能自包含，加载即可用；缺点：SKILL.md 行数增长 |
| **备选方案 B** | 独立脚本库：在 devflow-plugin 下维护通用巡检脚本库，SKILL.md 仅引用路径。优点：SKILL.md 精简；缺点：多一层间接引用，AI 执行时不会自动加载，且跨项目适配成本高 |
| **决策** | **方案 A：规范内嵌代码模板** |
| **理由** | 与 v2.15.0 ADR-001（T1-T4 内联增强）决策一致，遵循 DevFlow"技能自包含"原则。AI 代理执行 E2E 时以 SKILL.md 为唯一上下文，内嵌模板确保能力可用。OpenLLM 已验证脚本作为模板的参考实现来源 |
| **已知后果** | SKILL.md 增长 ~40 行；模板为 Playwright 实现，其他框架需等价映射（NFR-216-005）|

#### ADR-002: 环境/代码判定——响应体关键词判定 vs 状态码白名单

| 维度 | 内容 |
|:-----|:------|
| **决策标题** | H 类环境提示与 B 类代码缺陷的判定依据 |
| **上下文** | RT-216-002 需要区分 503"无法连接Ollama服务"（环境遗留）与竞态 500（代码缺陷）|
| **备选方案 A** | 响应体关键词判定：HTTP≥500 时读取响应体，含服务未就绪/依赖提示关键词（"无法连接"/"not available"/"connection refused"等）→ H 类；否则 B 类。优点：精准，可解释；缺点：依赖响应体质量，空响应体需 fallback |
| **备选方案 B** | 状态码白名单：将特定状态码（如 503）整体归为环境类。优点：简单；缺点：503 也可能是真实代码缺陷（如网关超时），误判风险高 |
| **决策** | **方案 A：响应体关键词判定（+直连复现 fallback）** |
| **理由** | BUG-291-012（竞态 500）与 503 环境提示的区别在响应体而非状态码。关键词判定 + 空响应体时直连复现（curl 确认归属）的 fallback 链条，兼顾精准与兜底 |
| **已知后果** | 需在规范中定义关键词清单样例与 fallback 规则；响应体读取失败时容错采集空摘要 |

#### ADR-003: 多轮巡检策略——自动触发 vs 人工判断

| 维度 | 内容 |
|:-----|:------|
| **决策标题** | 偶发缺陷多轮巡检的触发方式 |
| **上下文** | RT-216-005 需要提升偶发/竞态缺陷捕获概率，但多轮巡检增加 Step 4 耗时 |
| **备选方案 A** | 自动触发：首轮 0 代码类缺陷 + 存在 500 类风险页面时自动执行 ≥3 轮。优点：无需人工判断，确定性高；缺点：可能过度巡检低风险项目 |
| **备选方案 B** | 人工判断：测试工程师根据经验决定是否多轮。优点：灵活；缺点：依赖人，可能漏检（正是 BUG-291-012 教训）|
| **决策** | **方案 A：自动触发（带范围限定）** |
| **理由** | BUG-291-012 的教训是"靠运气命中"，必须机制化。自动触发条件限定"首轮 0 缺陷 + 有风险页"，且多轮巡检限定风险页子集（NFR-216-004 控制耗时）|
| **已知后果** | 低风险项目可能触发不必要的多轮；通过风险页判定规则（含模型/数据异步加载页）缓解 |

## 4. DT-216-001 详细设计：T3a 巡检信号表升级（6→8 类）

### 4.1 文件变更目标

`testing-stage-execution/SKILL.md` → `#### T3a 巡检信号和问题分类` → `6 类巡检信号采集表`

### 4.2 信号表设计

| 信号类型 | Playwright API | 采集方式 | 对应问题 |
|:---------|:---------------|:---------|:---------|
| HTTP 4xx | `page.on('response')` | 拦截响应，检查 `400 ≤ status < 500` | 接口契约不一致（A 类）|
| HTTP ≥ 500 | `page.on('response')` | 拦截响应，检查 `status ≥ 500`，**采集响应体摘要（前 200 字符）**| 后端运行时错误（B 类）/ 环境类提示（H 类）|
| 网络请求失败 | `page.on('requestfailed')` | 捕获失败请求 + 失败原因（`request.failure()`）| 网络断点/代理错误/跨域 |
| console.error | `page.on('console')` | 过滤 `msg.type() === 'error'`，记录 message 文本 | 前端逻辑错误（D 类）/ 弃用警告（I 类）|
| pageerror | `page.on('pageerror')` | 直接捕获未处理异常 | 前端运行时异常（C 类）|
| 接口 200 但渲染空 | `page.evaluate()` + DOM 检查 | 主内容区域 `children.length === 0` | 字段映射/渲染问题（E 类）|
| 静默失败（行为信号）| `btn.click()` + 网络计数器 + DOM 检查 | 关键按钮点击后无新请求且无 UI 响应 | 空实现（F 类）|
| 表单提交响应 | `submit_btn.click()` + 错误消息检测 | 提交后 4xx/5xx 被前端吞掉 | 表单错误被吞（G 类）|

### 4.3 关键增强点

- 原"HTTP ≥ 400"拆分为"HTTP 4xx"与"HTTP ≥ 500"两行（4xx=契约问题 A 类，5xx=运行时错误 B 类/H 类）
- 5xx 行新增"响应体摘要采集（前 200 字符）"字段说明
- 新增 requestfailed 信号行
- 巡检脚本要求逐页访问前后记录错误数，将错误精确定位到来源页面

## 5. DT-216-002 详细设计：问题分类扩展（7→9 类）+ 判定优先级

### 5.1 文件变更目标

`testing-stage-execution/SKILL.md` → `7 类标准问题分类表` → 扩展为 9 类

### 5.2 新增分类设计

| 类别 | 模式名称 | 典型信号 | 判定方法 | 处置路径 |
|:----:|:---------|:---------|:---------|:---------|
| **H 类** | 环境类提示（服务未就绪/依赖缺失）| HTTP 503/504 + 响应体 `{"detail":"无法连接..."}` 类服务提示 | 响应体明确指向外部服务/依赖未启动 | 登记环境遗留清单，不进缺陷闭环；环境恢复后复测 |
| **I 类** | 第三方弃用警告 | console.error 含 "deprecated"/"deprecation" | message 匹配弃用关键词 | 仅记录，不登记缺陷 |

### 5.3 判定优先级流程设计

```
HTTP ≥ 500 → 读取响应体摘要
  ├─ 响应体含服务未就绪/依赖提示（如 503 + "无法连接Xxx服务"）→ H 类（环境遗留）
  ├─ 响应体含异常堆栈/业务错误 → B 类（代码缺陷，登记）
  └─ 响应体为空/通用错误 → 直连复现后归 B 类
console.error → 检查 message
  ├─ 含 deprecated/deprecation → I 类（仅记录）
  └─ 否则 → D 类（代码缺陷）
```

## 7. DT-216-004 详细设计：E2E 网络层事件订阅标准动作

### 7.1 文件变更目标

`testing-stage-execution/SKILL.md` → E2E 测试章节（4.5 四轨贯通）→ 新增"网络层事件订阅标准动作"

### 7.2 代码模板设计（规范内嵌）

```python
# 标准动作：E2E 用例强制订阅网络层事件
network_errors = {"http5xx": [], "request_failed": [], "console_errors": []}

def attach_network_listeners(page):
    def on_response(resp):
        if resp.status >= 500:
            body = ""
            try:
                body = resp.text()[:200]  # 响应体摘要
            except Exception:
                pass
            network_errors["http5xx"].append(
                {"url": resp.url, "status": resp.status, "body": body}
            )
    def on_request_failed(req):
        network_errors["request_failed"].append(
            {"url": req.url, "reason": req.failure}
        )
    def on_console(msg):
        if msg.type == "error":
            network_errors["console_errors"].append(msg.text)
    page.on("response", on_response)
    page.on("requestfailed", on_request_failed)
    page.on("console", on_console)

def assert_network_clean():
    code_5xx = [e for e in network_errors["http5xx"]
                if not is_env_hint(e["body"])]          # 排除 H 类环境提示
    code_console = [m for m in network_errors["console_errors"]
                    if "deprecated" not in m.lower()]    # 排除 I 类弃用警告
    assert not code_5xx, f"代码类 HTTP≥500: {code_5xx}"
    assert not network_errors["request_failed"], \
        f"网络请求失败: {network_errors['request_failed']}"
    assert not code_console, f"代码类 console error: {code_console}"
```

### 7.3 规范要求

- T3b 深度用例与 4.5 E2E 用例**必须**调用 `attach_network_listeners` + 用例末尾 `assert_network_clean`
- `is_env_hint(body)` 为环境提示关键词判定辅助函数（关键词清单样例：无法连接/not available/connection refused/service unavailable）
- 模板标注"Playwright 为标准实现，其他框架按等价事件映射"（NFR-216-005）

## 8. DT-216-005 详细设计：偶发缺陷多轮巡检策略

### 8.2 设计内容

|:---|:---------|
| 触发条件 | 首轮巡检 0 个代码类缺陷，但存在 500 类风险页面（含模型/数据异步加载页）时 |
| 执行轮次 | 至少 3 轮快速巡检（全页面 × 网络层监控）|

| 依据 | BUG-291-012 经验：单轮未命中属概率事件，3 轮×9 页可稳定复现 |

| T3a 巡检 | 代码类 HTTP≥500 = 0、requestfailed = 0、代码类 console error = 0；H 类环境提示允许遗留但必须登记环境遗留清单 |

| 偶发缺陷 | 多轮巡检任一轮出现代码类 500 → 门禁不通过，回退 Step 3 |

## 12. DT-216-009 详细设计：审计执行确定性加固

### 12.1 文件变更目标

| 文件 | 变更类型 | 行数 |
|:-----|:---------|:----:|
| `audit-agent/SKILL.md` | 检查点复查规则增强 | ~20 行 |
| 全流程审计报告模板 | 新增逐条执行记录章节 | ~10 行 |

### 12.2 audit-agent 检查点复查增强设计

- 能力 3 检查点复查抽样表的"验证命令"列作为**审计执行唯一依据**
- 审计时逐条复制验证命令到终端执行 → 记录实际输出 → 对比声称结果
- 验证命令执行失败时记录实际错误输出，标记检查点未通过
- 前置要求：各阶段检查点的"验证命令"列可直接复制粘贴运行（无占位符、无歧义）

### 12.3 全流程审计报告模板增强

新增章节 `## 各阶段检查点逐条执行记录`：分阶段列出 验证命令 | 声称结果 | 实际输出 | 一致性，确保审计结论基于真实执行结果。
