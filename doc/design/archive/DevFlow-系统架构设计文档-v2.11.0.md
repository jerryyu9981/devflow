## 3. 上下游关系

| 方向 | 系统/模块 | 交互方式 |
|:-----|:----------|:---------|
| **输入** | Git 仓库 | `git log` 命令 |
| **输入** | 文件系统（doc/ 目录） | LS / Glob / Read / Grep |
| **输入** | 技术债务总表（技术债务总表.md） | Read 命令读取 |
| **输出** | 审计报告（doc/audit/comprehensive/） | Write 命令写入 |
| **输出** | Console 摘要 | 标准输出 |

## 4. 部署形态

| 维度 | 内容 |
|:-----|:------|
| **类型** | TRAE Skill（SKILL.md） |
| **依赖** | TRAE 平台提供的 Read / Write / LS / Glob / Grep / RunCommand 工具 |
| **安装** | 随 devflow-plugin install.ps1 / setup.ps1 自动部署 |

## 5. 安全设计

| 安全关切 | 设计 |
|:---------|:------|
| **读取范围** | 仅读取 DevFlow 项目目录下的文件 |
| **写入范围** | 仅写入 `doc/audit/comprehensive/` 下的审计报告 |
| **密钥泄露** | 不涉及密钥、密码、令牌 |
| **命令注入** | `git log` 版本号参数只接受字母数字点号格式 |

## 6. 非功能设计说明

### 6.1 性能

| 指标 | 目标 |
|:-----|:-----|
| 审计执行时间（≤ 10 commit） | ≤ 5 分钟 |
| 审计执行时间（> 10 commit） | ≤ 10 分钟 |
| 单次命令执行超时 | 30 秒 |

### 6.2 可观测性

| 维度 | 实现 |
|:-----|:------|
| **日志** | 执行过程中以结构化文本输出进度日志 |
| **结果** | 每个 Phase 完成后输出中间结果摘要 |
| **报告** | 完整的审计报告写入标准路径 |

### 6.3 可靠性与兼容性

| 维度 | 设计 |
|:-----|:------|
| **幂等性** | 同一版本多次执行结果一致 |
| **后向兼容** | 新增 skill 文件不影响现有 6 阶段流程 |
| **失败降级** | 任意 Phase 失败不影响其他 Phase 执行 |
