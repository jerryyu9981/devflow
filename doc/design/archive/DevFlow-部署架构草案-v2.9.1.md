## 1. 部署概述

### 1.1 DevFlow 部署模式

DevFlow 采用**本地文件部署**模式，而非传统的服务端部署。框架本身不依赖任何服务器进程，所有能力均通过技能文件、脚本和配置文件在本地项目中生效。

| 维度 | 说明 |
|------|------|
| **部署形态** | 本地文件系统部署（非服务端） |
| **运行载体** | TRAE IDE / VS Code 技能系统 + PowerShell 脚本 |
| **部署单元** | 技能文件 + 脚本 + 配置 + 文档模板 |
| **部署位置** | 项目根目录下的 `.devflow/` 目录 + 根目录配置文件 |
| **资源占用** | 磁盘空间 ~20-50MB，无常驻进程 |
| **网络依赖** | 首次安装/更新需联网，日常使用完全离线 |

### 1.2 部署形态构成

DevFlow 部署后由以下四类文件组成：

```text
├───────────────┬───────────────┬───────────────┬───────────────┤
│   技能文件     │   脚本文件     │   配置文件     │   文档模板     │
│  (Skills)     │  (Scripts)    │  (Configs)    │  (Templates)  │
├───────────────┼───────────────┼───────────────┼───────────────┤

│ L2 阶段执行技能│ update.ps1    │  config.json  │ 设计文档模板   │
```

### 1.3 v2.9.1 部署变更要点

v2.9.1 是 DevFlow 框架的**架构精简 + 流程质量增强**版本，部署层面涉及以下核心变更：

| 变更类别 | 变更内容 | v2.9.0 → v2.9.1 | 影响范围 |
|:--------:|---------|:----------------:|---------|
| **配置架构重构** | JSON 配置文件精简合并 | 6个文件 → 3个核心文件 | 所有技能的配置读写逻辑 |
| **脚本架构重构** | 安装脚本精简 | 5个脚本 → 2个入口 + 2个内部模块 | install/update 流程 |
| **流程质量增强** | 全阶段产出真实性验证门禁 | 新增 6 阶段验证点 + 全阶段盘点 | 各阶段执行技能 + 审计 |

**变更总览**：

```text
v2.9.0 部署结构                  v2.9.1 部署结构
───────────────                  ───────────────
配置文件（6个）      →         配置文件（3个）
  version.json                   devflow-config.json（根目录，框架级）
  .devflow/config.json           project-config.json（.devflow/，项目级）
  .devflow/state.json            state.json（.devflow/，状态管理）
  .devflow/version.json
  devflow-manifest.json
  plugin-config/version.json

安装脚本（5个）      →         安装脚本（2入口+2模块）
  install.ps1                    install.ps1（入口，合并setup）
  setup.ps1                      update.ps1（入口，合并sync-skills）
  update.ps1                     ├── .devflow/scripts/download-devflow.ps1
  sync-skills.ps1                └── .devflow/scripts/validate-install.ps1
  download-devflow.ps1
  validate-install.ps1

质量门禁（无）        →         质量门禁（全阶段）
                                 Step 0~5 产出真实性验证
                                 Step 5 全阶段产出盘点
```

## 3. 环境要求

### 3.1 操作系统

| 操作系统 | 最低版本 | 推荐版本 | 说明 |
|:--------:|:--------:|:--------:|------|
| **Windows** | Windows 10 1903 | Windows 11 | 主要支持平台，全功能可用 |
| macOS | macOS 11 (Big Sur) | macOS 14+ | 兼容支持，需 PowerShell Core |
| Linux | Ubuntu 20.04 | Ubuntu 22.04+ | 兼容支持，需 PowerShell Core |

> **说明**：DevFlow 官方主要支持 Windows 平台，macOS/Linux 为兼容支持。本文档部署流程以 Windows 为主。

### 3.2 PowerShell

| 组件 | 最低版本 | 推荐版本 | 说明 |
|------|:--------:|:--------:|------|
| **Windows PowerShell** | 5.1 | 5.1 | Windows 内置，install/update 脚本主运行环境 |
| PowerShell Core | 7.0 | 7.4+ | 跨平台可选，功能一致 |

**验证命令**：

```powershell
# 检查 PowerShell 版本
$PSVersionTable.PSVersion

# 检查执行策略（需允许本地脚本运行）
Get-ExecutionPolicy -List
```

**执行策略要求**：至少允许 `RemoteSigned` 或更宽松策略。

```powershell
# 设置执行策略（如需）
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### 3.3 IDE 环境

| IDE | 最低版本 | 说明 |
|-----|:--------:|------|
| **TRAE** | 3.0.0 | 首选 IDE，技能系统原生支持，完整 DevFlow 体验 |
| VS Code | 1.80+ | 兼容 IDE，需安装相关插件，技能体验可能受限 |

**IDE 插件依赖**：

| 插件 | 用途 | 必需性 |
|------|------|:------:|
| DevFlow Plugin | 技能加载、状态管理、UI 集成 | 必需 |
| Git 插件 | 版本控制、备份、发布 | 必需 |
| PowerShell 插件 | 脚本执行与调试 | 推荐 |

### 3.4 其他依赖

| 组件 | 最低版本 | 用途 | 必需性 |
|------|:--------:|------|:------:|
| **Git** | 2.30+ | 版本控制、备份、发布同步 | 必需 |
| 网络连接 | - | 首次安装、版本更新时下载框架包 | 安装/更新时必需 |

### 3.5 网络要求

| 场景 | 网络要求 | 说明 |

## 4. 部署方式

### 4.1 全新安装（install.ps1）

**适用场景**：项目中从未安装过 DevFlow，首次部署。

**执行方式**：

```powershell
# 方式一：在项目根目录直接执行
.\install.ps1

# 方式二：指定项目路径
.\install.ps1 -ProjectPath "D:\my-project"

# 方式三：指定版本
.\install.ps1 -Version "2.9.1"

# 方式四：强制覆盖已有安装
.\install.ps1 -Force
```

**安装内容**：

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | 环境检测 | PowerShell/Git/IDE/磁盘空间 |
| 2 | 下载框架包 | 从官方源下载指定版本 |
| 3 | 部署技能文件 | 解压到 `.devflow/skills/` |
| 4 | 部署脚本 | 复制入口脚本和内部脚本 |
| 5 | 创建配置文件 | 生成 `devflow-config.json` + `project-config.json` 模板 + `state.json` |
| 6 | 部署模板 | 复制文档模板到 `.devflow/templates/` |
| 7 | IDE 集成 | 同步配置到 IDE 全局目录，注册技能 |
| 8 | 安装验证 | 调用 `validate-install.ps1` 验证完整性 |

### 4.2 增量更新（update.ps1）

**适用场景**：已有 DevFlow 安装，升级到新版本。

**执行方式**：

```powershell
# 方式一：更新到最新版本
.\update.ps1

# 方式二：指定目标版本
.\update.ps1 -TargetVersion "2.9.1"

# 方式三：预览更新内容（不实际执行）
.\update.ps1 -DryRun

# 方式四：跳过备份（不推荐）
.\update.ps1 -SkipBackup
```

**更新内容**：

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | 状态检测 | 读取当前版本，检查工作区状态 |
| 2 | 版本对比 | 计算新旧版本差异（技能/脚本/配置变更） |
| 3 | 备份保护 | 备份当前 `.devflow/` 目录 |
| 4 | 下载新版本 | 获取目标版本框架包 |
| 5 | 技能同步 | 新增/修改/删除技能文件 |
| 6 | 脚本更新 | 更新入口脚本和内部脚本 |
| 7 | 配置迁移 | 按需执行配置迁移（如 v2.9.0 → v2.9.1） |
| 8 | IDE 同步 | 更新 IDE 全局配置副本 |
| 9 | 更新验证 | 验证版本一致性和文件完整性 |

### 4.3 旧版本升级（自动迁移）

**适用场景**：从 v2.9.0 或更早版本升级到 v2.9.1，涉及配置架构重构。

**迁移触发**：`update.ps1` 执行到"配置迁移"步骤时自动检测并触发；或 `devflow-init` 技能首次运行时检测。

**迁移内容**：

| 迁移项 | 源文件 | 目标文件 | 迁移方式 |
|--------|--------|----------|:--------:|
| 框架版本号 | `version.json` / `.devflow/version.json` / `devflow-manifest.json` | `devflow-config.json` | 合并，取最高版本 |
| 项目元数据 | `.devflow/config.json` | `project-config.json` | 字段映射 |
| 远程仓库配置 | `.devflow/config.json.remote` | `project-config.json.remote` | 直接迁移 |
| 命名规范 | `.devflow/config.json.naming` | `project-config.json.naming` | 直接迁移 |
| 工作流配置 | `.devflow/config.json.workflow` | `project-config.json.workflow` | 直接迁移 |
| 环境配置 | `.devflow/config.json.environments` | `project-config.json.environments` | 直接迁移 |
| 运行时状态 | `.devflow/state.json` | `.devflow/state.json` | 保留，字段兼容 |

**迁移保障**：
- 迁移前自动备份所有旧配置到 `.devflow/backup/before-v291-migration/`
- 迁移过程原子化：失败自动回滚
- 迁移后完整验证：Schema 校验 + 字段完整性检查
- 旧文件归档保留：至少一个版本周期（v2.9.1 ~ v2.10.0）

### 5.1 全新安装流程

```text

    │

              ▼

└─────────────┬─────────────┘
              │ 下载完成
              ▼
```

## 6. 配置管理

### 6.1 框架配置：devflow-config.json

**文件位置**：`{project_root}/devflow-config.json`

**职责定位**：框架级只读配置，DevFlow 版本和技能清单的唯一真相源。

**核心字段**：

| 字段 | 类型 | 说明 | 更新方式 |
|------|:----:|------|---------|
| `schemaVersion` | string | 配置文件 Schema 版本 | 框架更新时 |
| `devflowVersion` | string | DevFlow 框架语义化版本号 | 框架更新时 |
| `metadata` | object | 框架元数据（名称、描述、发布日期、仓库等） | 框架更新时 |
| `skills.L1` | array | L1 编排层技能清单（id、name、version） | 框架更新时 |
| `skills.L2` | array | L2 阶段执行层技能清单 | 框架更新时 |
| `skills.L3` | array | L3 专项技能层清单 | 框架更新时 |
| `framework` | object | 框架运行要求（最低IDE版本、支持平台等） | 框架更新时 |

**访问规则**：
- 所有技能和脚本**只读**此文件
- 仅 `install.ps1` 和 `update.ps1` 可写入
- IDE 全局目录维护只读副本，用于无项目上下文场景

### 6.2 项目配置：project-config.json

**文件位置**：`{project_root}/.devflow/project-config.json`

**职责定位**：项目级可写配置，每个项目独立维护，替代原 `.devflow/config.json`。

**核心字段**：

| 字段 | 类型 | 说明 | 更新方式 |
|------|:----:|------|---------|
| `schemaVersion` | string | 配置 Schema 版本 | 迁移/升级时 |
| `project` | object | 项目元数据（名称、代号、版本、负责人、创建日期） | init / 手动修改 |
| `remote` | object | 远程仓库配置（origin、默认分支、提供商） | init / 手动修改 |
| `naming` | object | 命名规范（文档格式、分支名、提交信息等） | 手动修改 |
| `workflow` | object | 工作流配置（起始步骤、自动推进、质量门禁阈值等） | 手动修改 |
| `environments` | object | 环境配置（dev/test/staging/prod） | 手动修改 |

**访问规则**：
- `devflow-init` 和 `devflow-project-config` 技能可读写
- 其他技能只读
- 用户可手动编辑，但需符合 JSON Schema

### 6.3 状态管理：state.json

**文件位置**：`{project_root}/.devflow/state.json`

**职责定位**：运行时状态管理，记录项目当前阶段、已完成阶段、审计结果、版本检测记录等。

**核心字段**：

| 字段 | 类型 | 说明 | 更新时机 |
|------|:----:|------|---------|
| `project` | string | 项目名称 | 初始化时 |
| `devflowVersion` | string | 当前使用的 DevFlow 版本 | 版本更新后 |
| `currentPhase` | string | 当前所处阶段 | 阶段流转时 |
| `completedPhases` | array | 已完成阶段列表 | 阶段完成时 |
| `versionCheck` | object | 版本检测记录 | 每次版本检查时 |
| `currentDocuments` | object | 各阶段产出文档索引 | 阶段完成时 |
| `auditResults` | object | 各阶段审计结果 | 审计完成时 |
| `migrationLog` | array | 迁移历史记录 | 每次迁移后 |

**访问规则**：
- `devflow-phase-manager` 技能主要维护
- 各阶段执行技能可追加状态信息
- 审计技能写入审计结果

### 6.4 配置变更管理

**配置变更类型**：

| 变更类型 | 触发方式 | 影响范围 | 回滚方式 |
|---------|---------|---------|---------|
| **框架版本升级** | `update.ps1` | devflow-config.json + 技能文件 | 回滚到上一版本 |
| **配置 Schema 升级** | 自动迁移 | project-config.json 结构 | 迁移备份回滚 |
| **项目配置修改** | 手动 / 技能修改 | project-config.json 字段 | Git 版本回退 |
| **状态流转** | 阶段推进 | state.json 字段 | 阶段回退（需技能支持） |

**变更原则**：
1. **单一真相源**：每类配置只有一个真相源，禁止多源并存
2. **向后兼容**：新版本配置必须能读取旧版本状态（至少兼容一个版本）
3. **原子写入**：所有配置变更采用"临时文件写入 + 校验 + 原子替换"模式
4. **变更留痕**：重要配置变更记录到 state.json 的日志中
5. **可回滚**：任何配置变更都必须有对应的回滚路径

**Source of Truth 映射**：

```text
                    ┌──────────────────────┐
                    │   devflow-config.json│
                    │   (框架级配置)        │
                    │   项目根目录          │
                    └──────────┬───────────┘
                               │ 唯一真相源
             ┌─────────────────┼─────────────────┐
             ▼                 ▼                 ▼
    IDE 全局副本         state.json      各技能文件引用
    (只读缓存)         (状态管理)        (只读引用)


                    ┌──────────────────────┐
                    │   project-config.json│
                    │   (项目级配置)        │
                    │   .devflow/ 目录      │
                    └──────────┬───────────┘
                               │ 唯一真相源
             ┌─────────────────┼─────────────────┐
             ▼                 ▼                 ▼
       文档生成器         命名检查工具       备份/发布脚本
       (只读引用)         (只读引用)        (只读引用)
```

## 7. 版本发布

### 7.1 发布物清单

DevFlow 每个版本的发布物包含以下内容：

| 类别 | 文件/目录 | 说明 |
|------|----------|------|

**发布包格式**：
- 格式：ZIP 压缩包
- 命名：`devflow-v{version}.zip`
- 大小：约 10-20MB
- 校验：附 SHA256 校验文件

### 7.2 版本号规则

DevFlow 采用**语义化版本号**（Semantic Versioning）：

```text
v{MAJOR}.{MINOR}.{PATCH}
  │       │       │
  │       │       └── 补丁版本：bug 修复、小调整，不影响功能
  │       └────────── 次版本：新增功能，向后兼容
  └────────────────── 主版本：不兼容的架构性变更
```

**示例**：

| 版本号 | 说明 |
|--------|------|
| v2.9.0 | 次版本更新，新增功能，向后兼容 |
| v2.9.1 | 补丁版本，架构精简 + 质量增强，配置架构有变更（通过迁移兼容） |
| v2.10.0 | 次版本更新，新增功能 |
| v3.0.0 | 主版本更新，不兼容的架构重构 |

**v2.9.1 版本说明**：
- 虽然涉及配置架构重构，但通过自动迁移机制保证向后兼容
- 旧版本项目可通过 `update.ps1` 平滑升级
- 因此版本号递增为补丁级（2.9.0 → 2.9.1），而非次版本级

### 7.4 回滚策略

**回滚层级**：

| 层级 | 回滚方式 | 适用场景 | 操作难度 |
|:----:|---------|---------|:--------:|
| L1 配置回滚 | 恢复备份的配置文件 | 配置变更导致问题 | 低 |
| L2 技能回滚 | 恢复备份的技能文件 | 技能逻辑错误 | 低 |
| L3 版本回滚 | `update.ps1 -TargetVersion` | 整体版本问题 | 中 |
| L4 完整回滚 | 从 Git tag 恢复 | 严重问题，需要完全回退 | 中 |

**回滚触发条件**：
- 安装/更新过程中验证失败 → 自动回滚
- 升级后关键流程无法执行 → 手动回滚
- 数据丢失或损坏风险 → 紧急回滚
- 发现严重安全漏洞 → 紧急回滚

**回滚验证**：
- 回滚后必须运行 `validate-install.ps1` 确认完整性
- 回滚后验证核心流程至少能正常启动
- 记录回滚原因和结果，供后续分析

## 8. 运维监控

### 8.1 版本检测

**检测机制**：

| 检测方式 | 触发时机 | 检测内容 |
|---------|---------|---------|
| **启动检测** | devflow-init 每次执行时 | 检查当前版本与最新版本差异 |
| **定期检测** | 可配置（默认每周一次） | state.json 中记录上次检测时间 |
| **手动检测** | 用户执行 update.ps1 -DryRun | 详细版本差异对比 |

**检测结果处理**：

| 结果 | 动作 |
|------|------|
| 当前为最新版本 | 无操作，静默继续 |
| 有新版本可用 | 输出提示，建议更新 |
| 当前版本超前（异常） | 输出警告 |
| 检测失败（网络问题） | 静默跳过，不影响正常使用 |

**版本检测记录**存储在 `state.json.versionCheck` 中：

```json
{
  "versionCheck": {
    "lastCheck": "2026-07-22",
    "installedDevflowVersion": "2.9.1",
    "latestVersion": "2.9.1",
    "result": "consistent",
    "action": "no_action"
  }
}
```

### 8.2 配置校验

**校验时机**：

| 时机 | 校验内容 | 校验方式 |
|------|---------|---------|
| 安装完成 | 所有配置文件格式与完整性 | validate-install.ps1 |
| 更新完成 | 所有配置文件格式与完整性 | validate-install.ps1 |
| 迁移完成 | 新配置 Schema 有效性 + 字段完整性 | 迁移内置校验 |

| 手动触发 | 全量配置校验 | validate-install.ps1 |

**校验项**：

| 校验项 | 校验内容 | 失败处理 |
|--------|---------|---------|

### 8.4 问题排查

**常见问题排查指南**：

| 问题现象 | 可能原因 | 排查步骤 | 解决方案 |
|---------|---------|---------|---------|
| 安装脚本无法执行 | PowerShell 执行策略限制 | `Get-ExecutionPolicy` | 设置 RemoteSigned |
| 下载框架包失败 | 网络连接问题 | 检查网络、代理设置 | 手动下载后离线安装 |
| 安装后技能不显示 | IDE 未正确注册 | 检查 IDE 全局配置目录 | 重启 IDE / 手动注册 |
| 配置迁移失败 | 旧配置文件损坏 | 查看迁移日志 | 手动修复后重试 / 回滚 |
| 版本检测失败 | 网络问题 / 源地址不可达 | 测试网络连通性 | 跳过检测 / 配置镜像源 |
| 验证不通过 | 文件缺失 / 损坏 | 查看验证报告详情 | 重新安装 / 从备份恢复 |
| 状态文件损坏 | 异常退出 / 磁盘错误 | 检查 state.json 格式 | 从备份恢复 / 重新初始化 |

**日志与诊断信息位置**：

| 日志类型 | 位置 | 用途 |
|---------|------|------|
| 安装日志 | 控制台输出 + 临时日志文件 | 安装过程排查 |
| 更新日志 | 控制台输出 + 临时日志文件 | 更新过程排查 |
| 迁移日志 | `state.json.migrationLog` | 迁移历史与结果 |
| 验证报告 | 控制台输出（validate-install.ps1） | 安装完整性排查 |
| 备份目录 | `.devflow/backup/` | 回滚与恢复 |

## 9. 部署风险与缓解

### 9.1 安装失败风险

| 风险项 | 风险等级 | 触发场景 | 影响 | 缓解措施 |
|--------|:--------:|---------|------|---------|
| **PowerShell 版本过低** | 低 | Windows 7 或未更新的 Win10 | 脚本无法执行 | 安装前检测，提示用户升级 PowerShell |
| **执行策略限制** | 中 | 企业环境严格策略 | 脚本无法运行 | 检测并提示修改执行策略，提供命令 |
| **磁盘空间不足** | 低 | 磁盘剩余空间 < 50MB | 安装中断 | 安装前检测，提示释放空间 |
| **网络下载失败** | 中 | 网络不稳定 / 防火墙限制 | 下载中断，安装失败 | 支持断点续传 / 手动下载离线安装 |
| **文件写入权限不足** | 中 | 系统目录 / 只读目录 | 部署文件失败 | 安装前检测目录权限，提示选择合适目录 |
| **杀毒软件拦截** | 低 | 脚本执行被误报 | 安装被阻断 | 提示用户添加信任 / 手动操作 |

### 9.2 迁移失败风险

| 风险项 | 风险等级 | 触发场景 | 影响 | 缓解措施 |
|--------|:--------:|---------|------|---------|
| **旧配置文件损坏** | 中 | 手动编辑错误 / 异常中断 | 迁移解析失败 | 迁移前备份，失败自动回滚，支持手动修复 |
| **字段冲突无法自动解决** | 低 | 多个旧文件同字段值不一致 | 迁移结果不确定 | 按优先级规则处理，输出警告，关键冲突要求确认 |
| **迁移过程中断** | 中 | 断电 / 进程被杀 | 配置处于中间状态 | 原子写入 + 备份恢复，启动时检测中间状态并自动回滚 |
| **Schema 不兼容** | 低 | 跨大版本直接升级 | 迁移规则不适用 | 检测版本跨度，建议逐步升级 |
| **迁移后验证失败** | 中 | 迁移逻辑 bug / 边界情况 | 新配置无效 | 验证失败自动回滚，保留失败现场供分析 |

### 9.3 权限不足风险

| 风险项 | 风险等级 | 触发场景 | 影响 | 缓解措施 |
|--------|:--------:|---------|------|---------|
| **目录写入权限** | 中 | 项目在 Program Files 等系统目录 | 文件无法写入 | 安装前检测，建议用户目录下项目 |
| **Git 操作权限** | 低 | 未配置 Git 用户信息 | 备份/发布失败 | init 阶段检测并引导配置 |
| **IDE 全局目录权限** | 低 | 多用户环境权限隔离 | IDE 集成失败 | 降级处理，仅项目级生效，输出警告 |
| **注册表访问** | 低 | 脚本需要读取系统信息 | 信息获取不全 | 降级使用默认值，不影响核心功能 |

### 9.4 网络异常风险

| 风险项 | 风险等级 | 触发场景 | 影响 | 缓解措施 |
|--------|:--------:|---------|------|---------|
| **首次安装无网络** | 中 | 离线环境 | 无法下载框架包 | 支持离线安装包（预先下载的 ZIP） |
| **更新时网络中断** | 中 | 下载过程中网络断开 | 更新中断 | 断点续传 / 失败后回滚到原版本 |
| **版本检测失败** | 低 | 网络不可用 | 无法获知新版本 | 静默跳过，不影响正常使用 |
| **远程仓库不可达** | 低 | Git 服务器宕机 | 备份/发布失败 | 本地备份不受影响，远程操作降级 |
| **防火墙/代理拦截** | 中 | 企业网络环境 | 下载失败 | 支持代理配置 / 提供镜像源配置 |
