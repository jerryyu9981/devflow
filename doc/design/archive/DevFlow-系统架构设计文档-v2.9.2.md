## 1. 概述

### 1.1 架构定位

DevFlow 是一个**基于技能的开发流程框架**，不是传统软件应用。其"系统"由以下组件构成：

| 组件 | 说明 | 技术形态 |
|------|------|---------|
| 技能文件（Skills） | L1/L2/L3 分层技能定义 | Markdown (.md) + 内联指令 |
| 文档模板（Templates） | 标准化的文档产出模板 | Markdown (.md) |
| 状态管理（State） | 项目当前阶段、版本、审计记录 | JSON (.devflow/state.json) |
| 配置管理（Config） | 项目级配置：远程仓库、命名等 | JSON |
| 全局台账（Ledger） | 技术债务总表、候选需求池 | Markdown (.md) |
| 版本清单 | 版本号、元数据 | JSON (version.json) |
| 安装脚本 | 框架部署与更新 | PowerShell (.ps1) / Shell (.sh) |

### 1.2 v2.9.2 架构变更范围

## 2. 配置架构现状

### 2.1 配置文件体系

v2.9.1 配置架构精简后，DevFlow 的配置文件体系为：

```text
框架级权威配置
  devflow-config.json ── 版本号、技能列表、仓库地址（单一事实源）
       │
       ├── 项目级状态
       │     .devflow/state.json ── 当前阶段、版本号、审计记录
       │
       ├── 项目级配置
       │     .devflow/config.json ── projectVersion、远程仓库、备份配置
       │
       └── 项目根元数据
             项目根 version.json ── 版本号、repository、homepage
```

### 2.2 配置漂移问题

devflow-init v2.9.1 检测到的配置不一致问题：

| 配置文件 | 当前版本 | 预期版本 | 差异 |
|---------|:--------:|:--------:|:----:|
| devflow-config.json | v2.9.1 | v2.9.2 | 权威源，需更新为新版本号 |
| 项目根 version.json | v2.8.5 | v2.9.2 | 落后 1 个次版本 + 1 个修订版 |
| .devflow/config.json projectVersion | 2.9.0 | 2.9.2 | 落后 2 个修订版 |

## 3. 设计概要

### 3.1 配置文件版本号统一（V292-001, V292-002）

| 设计项 | 内容 |
|:-------|:------|
| **设计目标** | 消除 devflow-init 检测到的版本不一致告警 |
| **设计方法** | 以 devflow-config.json 为权威版本源，将项目根 version.json 和 .devflow/config.json 的版本号字段统一更新为 2.9.2 |
| **操作步骤** | 1) 读取 devflow-config.json 获取权威版本号 → 2) 更新项目根 version.json version 字段为 2.9.2 → 3) 补全 repository 和 homepage 字段 → 4) 更新 .devflow/config.json projectVersion 为 2.9.2 |
| **幂等性** | 操作幂等，重复执行不产生副作用 |
| **验证方法** | 3 个配置文件的版本号字段手动核对一致 |

### 3.2 已弃用配置文件清理（V292-003）

| 设计项 | 内容 |
|:-------|:------|
| **设计目标** | 清理 v2.9.1 架构精简后遗留的弃用文件，避免用户混淆 |
| **涉及文件** | devflow-plugin/version.json（v2.8.5）、devflow-plugin/devflow-manifest.json（v2.8.3） |
| **备份策略** | 复制至 .devflow/backup/ 后删除原文件 |
| **备份命名规则** | 保留原文件名，不添加时间戳前缀（便于按版本还原） |
| **安全约束** | 备份失败或文件不存在时跳过删除，记录错误但不阻塞 |
| **验证方法** | 1) LS 确认备份文件存在 2) Glob 确认原文件不存在 |

### 3.3 风险归集门禁前置准备（V292-004）

| 设计项 | 内容 |
|:-------|:------|
| **设计目标** | 为 TD-026 完整偿还做准备，在问题跟踪记录模板中增加"风险归集检查"必填章节 |
| **影响文件** | operations-stage-execution/SKILL.md（问题跟踪记录模板部分） |
| **新增章节内容** | 包含：本阶段 P1+ 风险是否已归集到技术债务总表、未归集风险 ID 及原因、归集日期 |
| **章节位置** | 在问题跟踪记录模板的"问题汇总"章节之后 |
| **验证方法** | Grep 确认章节关键字存在 |
