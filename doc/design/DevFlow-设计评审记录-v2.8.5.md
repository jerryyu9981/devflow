### 3.6 release.ps1 脚本架构设计（R-06）

```
脚本：devflow-plugin/release.ps1

设计结构：
  1. 参数解析：-Version <string>（必需）
  2. 版本号格式校验：v{major}.{minor}.{patch}
  3. version.json 一致性校验
  4. Git Tag 创建：git tag v{版本号}
  5. Push to origin：git push origin v{版本号}
  6. Push to backup：git push backup v{版本号}
  7. 发布后验证：确认所有远程 Tag 存在
  8. 日志输出：每步输出 [级别] [时间戳] 消息
  9. 错误处理：任一失败则中止，输出错误信息

  返回值：
    - 0: 成功
    - 非 0: 失败（具体错误码对应失败步骤）
```

### 3.7 devflow-init 交互流程设计（R-03）

```
现有流程：
  → 自动检测 .devflow/config.json
  → 存在则跳过
  → 不存在则创建默认配置

修改后流程：
  → 自动检测 .devflow/config.json
  → 存在且包含 remote 地址 → 跳过（向后兼容）
  → 存在但不含 remote 地址 → 交互输入
  → 不存在 → 交互输入

交互设计：
  → 提示："请输入远程仓库地址（留空则跳过）："
  → 输入后显示："远程仓库地址为：{url}，确认？(Y/N)"
  → Y → 写入 .devflow/config.json
  → N → 重新输入
  → 留空 → 跳过（记录说明）
```

## 技能间委托关系一致性审查

审查规则：
1. A 技能委托/引用 B 技能 → 检查 B 技能中是否存在对应的规范或步骤
2. A 技能的执行流程是否正确引用了 B 技能的规范（路径/名称一致）
3. A 技能中是否有内联的、与 B 技能规范不一致的模板或步骤

审查记录示例：
| 审查项 | 委托技能 | 被委托技能 | 一致性 | 发现 |
|--------|---------|-----------|:------:|------|
| 1 | coding-stage-execution (3.x) | code-logic-review | ✅ | 正确引用 |
| 2 | design-stage-execution (2.6a) | security-design-review | ⚠️ | 路径引用为旧版 |
