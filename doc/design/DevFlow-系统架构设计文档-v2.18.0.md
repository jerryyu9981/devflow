### DT-218-002 pre-push hook 递归修复

**修改点 1**：`push-with-backup.ps1` L68/L93

```powershell
# 修改前
$mirrorOutput = & git push --mirror backup 2>&1
$ghOutput = & git push --mirror github 2>&1
# 修改后（--no-verify 防止递归触发 pre-push hook）
$mirrorOutput = & git push --no-verify --mirror backup 2>&1
$ghOutput = & git push --no-verify --mirror github 2>&1
```

**修改点 2**：`.devflow/hooks/post-push`（安装至 .git/hooks/pre-push）——后台 mirror 调用改为显式调用 push-with-backup.ps1（避免 push 命令内嵌触发递归）。

**修改点 3**：新增远程 tag 一致性检查——备份流程完成后比较 origin/backup/github 三远程 `refs/tags/v{版本号}` 解引用是否一致，不一致输出 WARN 日志。

**设计约束**：保留自动备份功能（Phase 2/3 mirror）；不改变 hook 安装机制；验证命令 `git push --no-verify` 仍可用。

## 5. 技术选型与 ADR

### ADR-218-001：T3a 巡检用例模板的承载位置

| 项 | 内容 |
|:---|:-----|
| **决策标题** | T3a 巡检 E2E 用例模板承载位置 |
| **上下文** | v2.17.0 预研确认 Playwright E2E 用例标准化可行；需确定模板写入哪个技能文档 |
| **备选方案** | A1：写入 testing-stage-execution（E2E 章节内）——与 attach_network_listeners 标准动作同章节，上下文完整（**选定**）；A2：独立 skill 文件——过度拆分，模板与既有规范脱节 |
| **决策与理由** | 选 A1：用例模板依赖 v2.16.0 L4 断言标准动作，同章节可确保实现一致性；增量 ~60 行可接受 |
| **已知后果与风险** | 章节长度增长；通过"标题层级 + 引用"缓解 |

### ADR-218-002：hook 递归修复方案

| 项 | 内容 |
|:---|:-----|
| **决策标题** | pre-push hook 后台 mirror 递归修复方案 |
| **上下文** | push-with-backup.ps1 的 mirror 命令未加 --no-verify，后台任务 push 时再次触发 pre-push hook 形成递归/挂起 |
| **备选方案** | A1：mirror 命令加 --no-verify + 显式脚本调用（**选定**）；A2：移除 hook 自动备份改为纯手动——丢失自动备份能力 |
| **决策与理由** | 选 A1：最小侵入修复，保留自动备份功能，阻断递归链 |
| **已知后果与风险** | 需人工验证备份仍可用（AC-218-005）；tag 一致性检查提供额外保障 |

### ADR-218-003：用户文档版本刷新方式

| 项 | 内容 |
|:---|:-----|
| **决策标题** | 用户指南/手册版本号刷新方式 |
| **上下文** | v2.17.0 发布时未刷新对外文档版本号（F-217-502 遗留）|
| **备选方案** | A1：版本号替换 + Git 历史内容核对（**选定**）；A2：全量重写——过度，无对外功能变更 |
| **决策与理由** | 选 A1：最小变更满足交付物门禁；内容以 v2.17.0 为准无实质变化 |
| **已知后果与风险** | 内容滞后风险由"每次发布同步刷新"规则规避 |
