## 1. 版本目标

| 目标 | 说明 | 成功指标 |
|:----|:-----|:---------|
| 🔗 **原型设计 IN/OUT 衔接规范建立** | 当前规范假设原型在 Step 2 内部设计，未定义外部工具（Figma 等）或独立设计活动的原型如何进入规范流程。建立 3 种场景导入协议（Figma/独立设计/已有原型）+ 下游移交增强（原型文件清单+DT-ID 映射+交互状态清单+E2E 断言基线） | design-stage-execution 含"外部原型导入协议"章节（3 种场景）；coding-stage-execution 含 Figma 链接类原型编码对照方式；testing-stage-execution E2E 用例引用原型状态作为断言基线 |
| 🔧 **SPEC-291 遗留闭合** | OpenLLM v2.9.1 测试巡检规范缺陷（SPEC-291-001~003）的 3 项未闭合遗留：T3a [按需] 标记与强制矛盾、网络层巡检自动化演进、测试计划模板未同步 | testing-stage-execution T3a 全栈项目标记为强制（纯后端不适用）；T3a 巡检脚本模板标准化为 Playwright E2E 用例；project-document-templates 含网络层巡检测试计划/用例/报告模板 |
| 📐 **规范内部矛盾修正** | design-stage-execution L140 将 prototype/index.html 标记为"强制"但 L146 同一文件列入"按需"，形成直接矛盾；testing-stage-execution T3a 标记 [按需] 但通过标准/L4 断言暗示强制 | prototype/index.html 全栈项目强制、纯后端不适用，无矛盾；T3a 标记与通过标准一致 |
| 📋 **文档模板补齐** | project-document-templates 完全无原型相关模板，UI 设计文档"原型设计说明"子章节未定义最小内容结构 | project-document-templates 含"原型设计说明"章节模板（来源说明+页面 RT-ID 映射+交互状态清单+文件路径/链接+覆盖率引用） |

### 版本定位

- **类型**：次版本（规范结构性增强升次版本）
- **主题**：规范衔接完善（SPEC-291 遗留闭合 + 原型设计衔接规范建立）
- **前置版本**：v2.16.0（已发布）
- **后续版本**：v3.0.0（全自动循环架构，需预研完成）

## 6. 发布策略草案

- **类型**：次版本
- **影响范围**：design-stage-execution（主改）+ coding-stage-execution（增强）+ testing-stage-execution（修正）+ project-document-templates（模板补齐）
- **总工作量**：~75 行变更 + ~8 处标记修正 + ~4 处模板新增/更新 + V216-004 预研
- **发布窗口**：2026-08
- **回滚策略**：Git revert 到 v2.16.0 tag；技能文档回退到 v2.16.0 版本
- **兼容策略**：原型衔接协议为增量新增，不破坏现有设计流程；T3a 标记修正为前瞻性要求，不追溯已发布版本
- **灰度策略**：DevFlow 为规范框架，无灰度需求；发布后全量推送 IDE 技能
