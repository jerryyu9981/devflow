## 1. 版本目标和成功指标

### 1.1 版本定位

v2.4.1 是 DevFlow 的 **Hotfix 修复版本**，聚焦 v2.4.0 遗留的 P0/P1/P2 问题修复，同时增强编码质量和测试质量管控能力。本版本不涉及新功能开发、架构变更或新技能引入。

### 1.2 成功指标（可量化）

| 指标类别 | 指标名称 | 当前值 | 目标值 | 度量方式 |
|---|---|---|---|---|
| **缺陷修复** | BUG-001 修复率 | 0%（未修复） | 100% | validate-install.ps1 在 PowerShell 5 下运行通过 |
| **缺陷修复** | P0 需求遗留数 | 2 项 | 0 项 | Backlog 验收确认 |
| **质量管控** | 验证证据覆盖率 | 低（非强制） | 100% | coding-stage-execution 强制规则 #6 执行检查 |
| **代码审查** | 偏执级检查项覆盖率 | 0 项 | 3 项新增 | code-logic-review 检查项清单验证 |
| **测试合规** | TDD 证据链检查 | 无 | 自动检查 | testing-stage-execution TDD 合规检查输出 |
| **格式标准化** | 旧技能文件格式达标率 | 部分（22 个旧技能） | 100% | check-skill-format.ps1 自动检查通过 |

## 5. Phase 计划

### 5.1 Phase 总览

```
Phase 1: P0 修复 ──→ Phase 2: P1 增强 ──→ Phase 3: P2 标准化
  (0.5 天)             (0.5 天)             (1 天)
  |                    |                    |
  BUG修复             审查增强             格式标准化
  证据强制化          TDD合规             工具增强
```

| Phase | 名称 | 周期 | 需求数 | 工时估算 | 关键里程碑 |
|---|---|---|---|---|---|
| **Phase 1** | P0 修复 | 0.5 天 | 2 项 | 0.5 天 | BUG-001 修复验证通过 + 验证证据强制化生效 |
| **Phase 2** | P1 增强 | 0.5 天 | 2 项 | 0.5 天 | 偏执级审查 3 项检查项新增 + TDD 合规检查集成 |
| **Phase 3** | P2 标准化 | 1 天 | 2 项 | 1 天 | 22 个旧技能格式标准化 + 自动填充能力增强 |

### 5.2 依赖关系

```
VR-2.4.1-001 (BUG-001 修复)          -- 独立修复，无前置依赖
VR-2.4.1-002 (验证证据强制化)        -- 独立增强，无前置依赖
VR-2.4.1-003 (偏执级代码审查)        -- 依赖 VR-002 完成（需与强制规则协同）
VR-2.4.1-004 (TDD 证据链)           -- 独立增强，无前置依赖
VR-2.4.1-005 (旧技能格式标准化)      -- 依赖 VR-006（需增强的工具辅助）
VR-2.4.1-006 (check-skill-format 增强) -- 独立工具增强
```

## 6. 风险评估

### 6.1 风险清单

| 风险 ID | 风险描述 | 概率 | 影响 | 应对措施 |
|---|---|---|---|---|
| R-001 | **回归风险**：BUG-001 修复可能引入新的兼容性问题 | 中 | 高 | 修复后在 PowerShell 5 和 PowerShell 7 双版本验证 |
| R-002 | **格式标准化影响范围**：22 个旧技能文件批量修改可能引入内容错误 | 中 | 中 | 使用 check-skill-format.ps1 增强版逐文件检查，修改后回归验证 |
| R-003 | **验证证据强制化可能阻塞正常开发流程** | 低 | 中 | 增加白名单机制，对特定场景允许豁免 |

### 6.2 裁剪策略

如果版本进度落后，按以下顺序裁剪：

1. **第一轮裁剪**：VR-2.4.1-006（P2，check-skill-format 增强，可手动完成标准化）
2. **第二轮裁剪**：VR-2.4.1-005（P2，格式标准化可推迟到 v2.4.2）

> 注：P0 需求（VR-001, VR-002）不可裁剪，P1 需求（VR-003, VR-004）强烈建议保留。

### 7.1 发布方式

| 项目 | 说明 |
|---|---|
| **发布类型** | Hotfix 直接发布，无 Alpha/Beta/RC 预发布阶段 |
| **Git Tag** | `v2.4.1` 推送到远程仓库 |
