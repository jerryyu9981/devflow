## 1. Phase 总览

v2.4.1 作为 Hotfix 修复版本，拆分为 3 个 Phase，按优先级和依赖关系排序：

```
Phase 1: P0 修复 ──→ Phase 2: P1 增强 ──→ Phase 3: P2 标准化
  (0.5 天)             (0.5 天)             (1 天)
  |                    |                    |
  BUG修复             审查增强             格式标准化
  证据强制化          TDD合规             工具增强
```

| Phase | 名称 | 周期 | 需求数 | 工时估算 | 关键里程碑 |
|---|---|---|---|---|---|
| **Phase 1** | P0 修复 | 0.5 天 | 2 项 | 0.5 天 | BUG-001 修复验证通过 + 验证证据强制化生效 |
| **Phase 2** | P1 增强 | 0.5 天 | 2 项 | 0.5 天 | 偏执级审查检查项新增 + TDD 合规检查集成 |
| **Phase 3** | P2 标准化 | 1 天 | 2 项 | 1 天 | 22 个旧技能格式标准化 + 自动填充能力增强 |

**总周期**：2 天（含 0.5 天缓冲）
**缓冲策略**：Phase 3 末尾预留 0.5 天用于回归测试和最终验证

## 5. 关键依赖关系

```
Phase 1（并行执行，无互相依赖）:
  VR-2.4.1-001 (BUG-001 修复)          -- 独立
  VR-2.4.1-002 (验证证据强制化)        -- 独立

Phase 2（并行执行，无互相依赖）:
  VR-2.4.1-003 (偏执级代码审查)        -- 建议在 VR-002 完成后执行（与强制规则协同）
  VR-2.4.1-004 (TDD 证据链)           -- 独立

Phase 3（串行执行）:
  VR-2.4.1-006 (check-skill-format 增强) -- 优先执行
    └──→ VR-2.4.1-005 (旧技能格式标准化) -- 依赖增强后的工具

跨 Phase 依赖:
  Phase 1 完成 ──→ Phase 2 开始（P0 修复优先于 P1 增强）
  Phase 2 完成 ──→ Phase 3 开始（增强能力优先于标准化执行）
```
