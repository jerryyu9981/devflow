## 1. 背景与问题

### 1.1 版本动机

v2.8.4 解决了 Step 3 "假完成"问题，但 v2.8.4 全流程闭环审计中识别出两个体系性缺口：

**缺口一：各阶段发现的风险无法自动流入全局债务总表（TD-016）**

当前各阶段（Step 0~5）都会发现风险和问题，但缺少统一的归集规范。风险只停留在阶段文档中，跨版本无法跟踪。v2.8.4 的 3 条遗留风险（RISK-01~03）仍然只存在于测试报告和 DevLogReport 中，未自动归集到债务总表。

**缺口二：用户无法感知版本变化（TD-017）**

DevFlow 只有内部工程文档（需求/设计/开发/测试/审计），缺少面向用户的 Release Note 和汇总的 Changelog。用户升级时不知道每个版本升级了什么、为什么重要、怎么升级。

### 1.2 历史遗留未处理项

除上述两个体系性缺口外，v2.8.5 还承载了 v2.8.4 之前的 6 项历史债务：

| 来源 | 债务 | 问题 |
|------|------|------|
| 远程仓库配置缺口分析（v2.8.3） | TD-012 + TD-018 | devflow-init 跳过远程仓库交互输入（TD-012）；跨技能一致性审计机制缺失（TD-018） |
| 备份疏漏分析（v2.7.4-2.7.5） | TD-019~022 | 缺少发布检查清单、发布脚本、CI/CD 门禁、季度版本审计 |

## 2. 全局目标定位

v2.8.5 的主题定义为 **"流程体系完善版"**，聚焦于补全 DevFlow 流程体系中的结构性缺口，不引入新功能，只做流程闭环。

### 2.1 版本目标

| 编号 | 目标 | 成功指标 | 可衡量依据 |
|:----:|------|---------|-----------|
| G-01 | 建立债务生命周期管理规范，风险归集流入 + 跨版本接续流出双向闭环 | v2.8.5 启动时自动触发债务审查 + 各阶段审计时风险归集率达到 100% | Step 0 执行记录 + 审计报告中检查风险归集 |
| G-02 | 建立 Release Note + Changelog 发布机制，用户可感知版本变化 | v2.8.5 发布时同时输出 Release Note + Changelog | Step 5 交付物检查 |
| G-03 | 修复 devflow-init 远程仓库配置缺口 | devflow-init 执行时必须交互输入远程仓库地址 | devflow-init 执行录屏/trace |
| G-04 | 建立发布检查清单和自动化脚本 | Step 5 按 checklist 执行，release.ps1 可执行 | 发布检查记录 + release.ps1 文件存在性 |
| G-05 | 建立跨技能一致性审计机制 | code-logic-review 中增加技能间一致性审查维度 | 审查记录证据 |
| G-06 | 建立跨版本债务接续机制 | 新版本 Step 0 自动审查全局债务总表并执行老化升级 | version-planning 中 0.0a 章节证明 |

### 2.2 版本主题

> **v2.8.5：流程体系完善版 — 债务生命周期 + 发布机制 + 配置缺口**
