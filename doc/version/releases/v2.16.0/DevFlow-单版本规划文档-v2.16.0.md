## 1. 版本目标

| 目标 | 说明 | 成功指标 |
|:----|:-----|:---------|
| 🛡️ **测试巡检网络层监控规范增强** | 基于 OpenLLM v2.9.1 使用反馈（BUG-291-012 竞态 500 漏检至人工测试，登记规范缺陷 SPEC-291-001~003），将 T3a 巡检与 E2E 的网络层健康监控固化为 Step 4 标准动作，使偶发性/时序性缺陷在测试阶段即可被捕获 | testing-stage-execution 包含 8 项网络层监控改进（信号表 8 类/问题分类 9 类/L3 断言强制/E2E 订阅标准动作/多轮策略/根因定位第 7 种/输出物标准/门禁明确化）；T3b/E2E 模板强制调用 assert_network_clean |
| 🔍 **审计执行确定性加固** | 将 v2.13.0 复盘候选 V213-001 纳入，确保 audit-agent 能力 3 检查点复查抽样表的"验证命令"列作为审计执行唯一依据，解决 Stage 3 检查点执行遗漏根因 | audit-agent 检查点复查逐条执行验证命令并记录实际输出；全流程审计报告包含"各阶段检查点逐条执行记录"章节 |

### 版本定位

- **类型**：次版本（新增功能升次版本）
- **主题**：测试巡检网络层监控增强 + 审计执行确定性加固
- **前置版本**：v2.15.0（已发布）
- **后续版本**：v3.0.0（全自动循环架构，需预研完成）

## 4. 版本风险清单

| 风险 | 级别 | 说明 | 缓解措施 |
|:-----|:----:|:------|:---------|
| 网络层断言误报环境问题为代码缺陷 | 🟡 P1 | L3 断言强制后，环境类提示（如 Ollama 未启动 503）可能被误判为缺陷 | H 类判定优先级流程必须前置：先读响应体摘要，含服务未就绪提示 → H 类环境遗留，不进断言失败集合 |
| 多轮巡检增加测试耗时 | 🟢 P2 | ≥3 轮全页面巡检可能延长 Step 4 执行时间 | 多轮策略限定"首轮 0 缺陷但有风险页"场景；每轮仅巡检风险页子集而非全量 |
| E2E 监听器代码模板跨框架适配 | 🟢 P2 | 模板基于 Playwright，其他 E2E 框架（Cypress 等）需适配 | 规范标注"Playwright 为标准实现，其他框架按等价事件映射" |
| 审计执行确定性加固影响既有审计流程 | 🟢 P2 | 逐条执行验证命令可能增加审计耗时 | 沿用 v2.14.0 已验证的检查点命令可执行化基础，增量增强 |

## 6. 发布策略草案

- **类型**：次版本
- **影响范围**：testing-stage-execution（主改）+ audit-agent（次改）+ Stage4 产出物清单（核对）
- **总工作量**：~178 行变更（25+20+15+40+15+8+15+10+30）
- **发布窗口**：2026-08
- **回滚策略**：Git revert 到 v2.15.0 tag；技能文档回退到 v2.15.0 版本
- **兼容策略**：网络层监控为增量增强，不破坏现有测试流程；L3 断言为新增强制项，仅影响新增测试
- **灰度策略**：DevFlow 为规范框架，无灰度需求；发布后全量推送 IDE 技能
