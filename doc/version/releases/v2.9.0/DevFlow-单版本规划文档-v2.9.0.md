## 1. 背景与问题

| 问题 | 说明 |
|:----|:------|
| 债务累积 | 技术债务总表仍有 7 项待偿还（TD-006~TD-013），其中 4 项 P1 已跨 3 个版本未处理 |
| 还债无保障 | 各版本还债容量无约束，全靠 PM 自觉分配，导致债务持续累积 |
| 债务易遗忘 | 跨版本债务流转机制不完整，0.0a 审查已有基础框架但流转规则需完善 |
| 测试质量 | 缺少覆盖率门禁和 E2E 集成验证，边界条件和跨模块协同问题难发现 |
| 来源模糊 | Step 0 需求收集缺少规范化来源检查清单，可能遗漏重要需求 |
| 元数据缺失 | version.json 仓库地址字段长期为空，全自动循环推迟至 v3.0 |

## 2. 版本目标

| 目标 | 成功指标 |
|:----|:---------|
| 🏛️ 建立还债配额制度 | 每个版本 15~20% 工作量用于还债，Step 0 门禁强制执行 |
| 🔄 完善跨版本债务流转 | 继承/升级/转移规则完整，0.0a 审查约束闭环 |
| 🛡️ 设置覆盖率底线 | 核心模块行覆盖率 ≥80%，不达标阻塞 Step 4 |
| 🔗 强制 E2E 验证 | 跨多模块变更必须有至少一条 E2E 用例 |
| 📋 规范需求来源 | Step 0 需求收集增加来源检查清单，覆盖 6 种渠道 |
| 🧹 修补元数据 | version.json 补全 repository/homepage 字段 |

## 6. 版本发布策略草案

| 策略维度 | 说明 |
|:---------|:------|
| 发布类型 | 功能增强（次版本 v2.8.x→v2.9.x）|
| 预计发布时间 | 2026-08 月底 |
| 发布窗口 | 工作日（周一~周五）09:00~17:00（北京时间） |
| 发布前冻结 | 发布前 24 小时冻结代码合入，仅缺陷修复 |
| 灰度策略 | 无灰度，直接全量发布（DevFlow 为规范框架，非在线服务） |
| Tag 命名 | `v2.9.0`，与 `version.json` 版本号一致 |
| 双仓库推送 | 发布时同时推送到 origin + backup |
| 后验检查 | Tag 存在性 + Tag 推送 + 版本号一致性 + 备份同步 |
| 回滚预案 | `git revert` 产生新 commit，不删除历史 |
