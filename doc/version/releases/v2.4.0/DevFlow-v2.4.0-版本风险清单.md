## 1. 风险总览

| 风险等级 | 数量 | 说明 |
|---|---|---|
| **高** | 3 项 | 可能导致版本延期或功能裁剪 |
| **中** | 5 项 | 可能影响部分需求的质量或进度 |
| **低** | 4 项 | 影响较小，已有明确应对措施 |
| **合计** | **12 项** | — |

### 风险等级定义

| 等级 | 定义 | 处理要求 |
|---|---|---|
| **高** | 发生概率 > 50% 或影响严重（版本延期 > 2 周） | 必须有主动缓解措施，每周跟踪 |
| **中** | 发生概率 20~50% 或影响中等（版本延期 1~2 周） | 需要应对预案，双周跟踪 |
| **低** | 发生概率 < 20% 或影响较小 | 记录监控，月度跟踪 |

## 2. 高风险

### RISK-001: 版本范围过大导致延期

| 字段 | 内容 |
|---|---|
| **风险 ID** | RISK-001 |
| **风险名称** | 版本范围过大导致延期 |
| **风险等级** | 高 |
| **风险类别** | 进度风险 |
| **概率** | 60% |
| **影响** | 版本延期 2~4 周，影响季度发布节奏 |
| **描述** | v2.4.0 包含 15 项需求（4 P0 + 10 P1 + 1 P2），预估 50 人天工作量。在单人开发模式下，10 周周期紧凑，Phase 间无并行空间，任何 Phase 延期都会直接压缩后续 Phase。 |
| **触发条件** | Phase 1 或 Phase 2 延期超过 3 天 |
| **影响范围** | 全版本 |
| **缓解措施** | 1. 严格执行优先级，P2 优先裁剪<br>2. 每个 Phase 内置 1~2 天缓冲<br>3. 识别可并行的工作项（如 VR-003 文档编写可与 Phase 3 并行）<br>4. 准备明确的裁剪方案（参见单版本规划文档 5.2） |
| **应急预案** | 1. 第一轮裁剪：VR-017（Codex CLI）<br>2. 第二轮裁剪：VR-009（容器化）推迟到 v2.4.1<br>3. 第三轮裁剪：VR-007 只完成安全编码规范部分<br>4. 如仍不够，发布日期推迟到 10 月中旬 |
| **负责人** | jerry.yu |
| **跟踪频率** | 每周 |

| **应急预案** | 1. 格式类问题通过脚本批量修复<br>2. 内容重复/矛盾问题标记但不立即修复，记录到 v2.4.1 待办<br>3. 使用 Phase 2 缓冲时间补充修复 |

| **风险类别** | 进度风险 |

| **描述** | 制定统一的 SKILL.md 编写规范需要平衡格式严格性和灵活性，可能需要多次迭代。如果现有技能的格式差异过大，规范制定可能需要更多时间权衡。 |
| **触发条件** | VR-012 超过 4 天未完成草案 |

| **应急预案** | 发布"核心规范 + 扩展建议"两级规范，核心规范保证质量，扩展建议逐步完善 |

### RISK-005: 安装向导跨平台实现复杂度

| 字段 | 内容 |
|---|---|
| **风险 ID** | RISK-005 |
| **风险名称** | 安装向导跨平台实现复杂度 |
| **风险等级** | 中 |
| **风险类别** | 技术风险 |
| **概率** | 40% |
| **影响** | VR-001 开发周期可能超出 5 人天预估 |
| **描述** | 交互式安装向导需要支持 Windows (PowerShell)、macOS (zsh)、Linux (bash) 三个平台的 CLI 交互，包括环境检测、进度显示、错误处理等。不同平台的终端兼容性可能带来额外工作量。 |
| **触发条件** | 单个平台的安装向导开发超过 2 天 |
| **影响范围** | Phase 2 |
| **缓解措施** | 1. VR-018 先统一安装脚本，降低安装向导的跨平台复杂度<br>2. 优先完成一个平台（Windows），再扩展到其他平台<br>3. 使用跨平台 CLI 框架（如 Node.js 的 inquirer/prompts） |
| **应急预案** | Windows/macOS 优先，Linux 使用简化版（非交互式 + 配置文件方式） |
| **负责人** | 开发负责人 |
| **跟踪频率** | 双周 |
