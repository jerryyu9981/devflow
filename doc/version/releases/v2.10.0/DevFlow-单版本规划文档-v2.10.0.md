## 1. 版本目标

### 1.1 业务目标

通过大规模还债和质量保障能力完善，将 DevFlow 的技术债务从当前的 6 笔待/偿还中状态大幅压降，同时建立季度审计、性能基线、文件结构一致性保障等长期质量机制，为 v3.0 全自动循环架构奠定基础设施。

### 1.2 用户目标

- 审计师能通过季度审计机制系统化地跟踪债务治理效果
- 开发者无需担心"设计写了改名但编码没做"的断裂问题
- 运维人员能通过统一注册的技能引用来确保技能文件完整性
- 用户不再遇到模板缺失导致的文档产出不完整

### 1.3 技术目标

- 6 笔技术债务（TD-010/011/024/025/026/027）全部偿还或完整落地
- 新增 3 项能力：季度审计机制、性能基线、文件结构一致性保障
- 恢复 V291-002 安装脚本精简（从 v2.9.1 推迟）
- 还债占比 ≥ 15%（预期 86%，远超阈值）

### 1.4 成功指标

| 指标 | 目标值 | 度量方式 |
|:-----|:------:|:---------|
| 待偿还债务数 | 6 → 0 | 债务总表统计 |
| 模板文件数 | 9 → 24 | 目录统计 |
| 技能引用注册率 | 138 → 全部注册 | 扫描统计 |
| 文件结构一致性门禁覆盖率 | 0/3 → 3/3 技能 | 技能文档验证 |
| 还债占比 | ≥ 15% | 债务总表 |

## 3. 优先级排序

| 优先级 | 数量 | BL-ID |
|:------:|:----:|:------|
| 🔴 P0 | 0 | — |
| 🟡 P1 | 3 | BL-2100-003（文件结构一致性）、BL-2100-006（风险归集门禁）、BL-2100-007（脚本精简） |
| 🟢 P2 | 4 | BL-2100-001（季度审计）、BL-2100-002（性能基线）、BL-2100-004（模板补全）、BL-2100-005（引用注册） |

**排序依据**：
1. P1 项（文件结构一致性、风险归集门禁）为流程堵漏，防止再出现 v2.9.1 式设计-执行断裂
2. V291-002（脚本精简）虽非债务，但从 v2.9.1 已推迟两个版本，应在本版本解决
3. P2 项均为积累多年的历史债务，计划在本版本一次性大规模偿还
