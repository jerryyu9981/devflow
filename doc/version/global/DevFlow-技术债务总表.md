## 说明

本表为 DevFlow 项目全局技术债务台账，汇总所有已识别的技术债务，跨版本跟踪债务状态变化。每个版本的债务新增、偿还、升级、挂起均需更新本表。

### 15 字段标准格式

| 序号 | 字段名 | 说明 | 必填 |
|:----:|--------|------|:----:|
| 1 | 债务 ID | 全局唯一标识，格式 TD-XXX | ✅ |
| 2 | 类型 | 架构/流程/质量/测试/文档/安全/性能 | ✅ |
| 3 | 严重级 | P0/P1/P2/P3 | ✅ |
| 4 | 标题 | 一句话概括债务 | ✅ |
| 5 | 发现版本 | 首次发现该债务的版本 | ✅ |
| 6 | 状态 | 待偿还/偿还中/已偿还/挂起中 | ✅ |
| 7 | 计划偿还版本 | 计划在哪版本偿还 | ✅ |
| 8 | 实际偿还版本 | 实际在哪版本偿还 | ⬜ |
| 9 | 负责人 | 债务责任人 | ✅ |
| 10 | 关联需求 | 关联的需求 ID | ⬜ |
| 11 | 关联 BL-ID | 关联的 Backlog ID | ⬜ |
| 12 | 发现日期 | 首次发现日期（YYYY-MM-DD） | ✅ |
| 13 | 最后更新日期 | 最近一次状态变更日期 | ✅ |

| 15 | 备注 | 其他补充信息 | ⬜ |

### 债务严重级定义

| 级别 | 定义 | 处置规则 |
|:----:|------|---------|
| 🔴 P0 | 阻塞性债务 | 必须在当前版本偿还，否则阻塞发布 |
| 🟡 P1 | 高优先级债务 | 应在 1~2 个版本内偿还 |
| 🟢 P2 | 中优先级债务 | 应在 3~4 个版本内偿还 |
| 🔵 P3 | 低优先级债务 | 可挂起，有空闲资源时偿还 |

### 债务类型定义

| 类型 | 说明 |
|------|------|
| 架构债务 | 架构设计缺陷、分层混乱、依赖不合理 |
| 流程债务 | 流程规范缺失、执行不到位、门禁失效 |
| 质量债务 | 代码质量差、复杂度高、重复代码多 |
| 测试债务 | 测试覆盖不足、缺少自动化测试 |
| 文档债务 | 文档缺失、过时、不规范 |
| 安全债务 | 安全漏洞、缺少安全设计 |
| 性能债务 | 性能瓶颈、资源浪费 |

### 债务状态流转

```
新增 → 待偿还 → 偿还中 → 已偿还
         ↓
       挂起中 → 重新激活 → 待偿还
         ↓
       升级（P3→P2→P1→P0）
```

**老化升级规则**：
- P3 债务挂起超过 2 个版本 → 自动升级为 P2
- P2 债务挂起超过 2 个版本 → 自动升级为 P1
- P1 债务挂起超过 2 个版本 → 升级为 P0，阻塞 Step 3
