# DevFlow 季度债务审计流程

> **文档类型**: 审计流程规范
> **版本**: v1.0
> **日期**: 2026-07-24
> **维护者**: DevFlow 维护团队

---

## 1. 说明

本流程定义 DevFlow 项目的季度技术债务审计机制。每季度末执行一次，由 PM-DevFlow-Dev 触发。

## 2. 审计步骤

```text
步骤 1: 启动审计
  ↓
步骤 2: 遍历债务总表
  ↓
步骤 3: 老化升级判定
  ↓
步骤 4: 制定还债计划
  ↓
步骤 5: 审计报告归档
  ↓
步骤 6: 更新总表状态
```

### 步骤 1：启动审计

| 项目 | 内容 |
|:-----|:------|
| **触发** | 每季度末（3/6/9/12月最后一周） |
| **输入** | `doc/version/global/{项目名}-技术债务总表.md` |
| **负责人** | PM-DevFlow-Dev |

### 步骤 2：遍历债务总表

- 筛选状态为"待偿还"和"挂起中"的条目
- 审查每笔债务的详细描述、发现版本、最后更新日期
- 检查是否有已到期或即将到期的债务

### 步骤 3：老化升级判定

| 规则 | 操作 |
|:-----|:------|
| P3 挂起 > 2 版本 | 升级至 P2 |
| P2 挂起 > 2 版本 | 升级至 P1 |
| P1 挂起 > 2 版本 | 升级至 P0 |
| 连续挂起版本数 +1 | 记录到"备注"字段 |

### 步骤 4：制定还债计划

- 根据债务级别（P0 > P1 > P2）确定优先偿还顺序
- 结合下一个版本的容量，分配还债配额（>= 15%）
- 标记纳入下个版本的债务，记录目标版本

### 步骤 5：审计报告归档

- 使用审计模板生成报告
- 审计报告存放于 `doc/audit/assessment/`
- 命名格式：`{项目名}-季度债务审计报告-Q{季度}-{年份}.md`

### 步骤 6：更新总表状态

- 将老化升级结果更新到技术债务总表
- 更新各条目的"最后更新日期"
- 在总表的"版本债务变化追踪"区域新增季度审计追踪章节

## 3. 审计模板

审计报告包含以下章节：

| 章节 | 内容 |
|:-----|:------|
| 审计基本信息 | 日期、项目、审计范围、审计负责人 |
| 债务总览 | 总债务数、P0/P1/P2 分布、新增/偿还/挂起统计 |
| 老化升级记录 | 升级的债务 ID、原级别、新级别、原因 |
| 还债建议 | 下版本优先偿还项、建议还债配额 |
| 审计结论 | 通过/有条件通过/不通过 |
