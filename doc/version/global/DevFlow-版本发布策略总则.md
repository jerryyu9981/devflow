# DevFlow 版本发布策略总则

> **文档类型**: 版本发布策略总则
> **文档状态**: Draft
> **版本**: v1.0
> **日期**: 2026-07-20
> **维护者**: DevFlow 维护团队
> **说明**: 本文件为全部版本共享文档，统一定义发布节奏、灰度策略、版本类型、回滚原则和兼容策略。

---

## 1. 发布节奏

| 节奏 | 说明 |
|:----|:------|
| 常规发布 | 每月一个版本，月初规划→月中开发→月末发布 |
| Hotfix 发布 | P0/P1 缺陷按需发布，不等待版本周期 |
| 发布窗口 | 工作日 09:00~17:00（北京时间），避免周末/节假日发布 |
| 发布冻结 | 版本发布前 24 小时冻结代码合入，仅允许缺陷修复 |

## 2. 版本类型

| 类型 | 示例 | 说明 |
|:----|:----:|:------|
| 重大版本 | v3.0.0 | 架构重构、破坏性变更、全自动循环 |
| 功能增强 | v2.9.0 | 新功能、流程变更、门禁新增 |
| Patch | v2.8.4 | 缺陷修复、微小增强、技术债务偿还 |
| Hotfix | v2.8.5-hotfix.1 | 紧急缺陷修复，不改变常规版本号序列 |

## 3. Tag 规范

| 规则 | 说明 |
|:----|:------|
| 格式 | `v{主}.{次}.{修订}`，前导 v 小写 |
| 示例 | `v2.8.5`, `v2.9.0` |
| 强制 | 每个发布版本必须有且仅有一个 Tag |
| 一致性 | Tag 必须与 `version.json` 版本号一致 |
| 签名 | 推荐 GPG 签名 Tag（`git tag -s`）|

## 4. 回滚原则

| 级别 | 策略 |
|:----|:------|
| 代码回滚 | `git revert <commit>` 产生新 commit，不删除历史 |
| Tag 回滚 | 仅删除未推送的 Tag；已推送的使用 `git push --force` 需双人确认 |
| 配置回滚 | 回退 `.devflow/state.json` 到发布的 commit 版本 |
| 文档回滚 | 文档作为代码一部分，随代码回滚 |
| 回滚后处理 | 创建 Hotfix 版本修复问题后重新发布 |

## 5. 发布后验证

| 检查项 | 说明 |
|:------|:------|
| Tag 存在性 | `git tag -l v{version}` 确认存在 |
| Tag 推送 | 确认 origin + backup 均有该 Tag |
| 版本号一致性 | `version.json` 版本号与 Tag 一致 |
| 备份同步 | 双仓库 commit 一致 |

## 6. 兼容策略

| 层面 | 策略 |
|:----|:------|
| 技能文件 | 同一主版本内删除功能需在版本规划中说明，否则向后兼容 |
| state.json | 新增字段为 optional，不破坏旧版本解析 |
| 文档模板 | 维持现有结构，如需修改在版本规划中说明并更新示例 |
| 配置字段 | 不删除已有字段，新增字段需有默认值 |
