# DevFlow v2.8.4 发布说明

> **版本**: v2.8.4
> **发布日期**: 2026-07-20
> **类型**: 质量保障基础版（Patch）
> **上一版本**: v2.8.3

---

## 一句话介绍

v2.8.4 解决了 **Step 3 "假完成"** 问题——文档写得漂亮但代码跑不起来。通过三道质量门禁（债务增长率 + 实际运行验证 + 可维护性否决）+ 全局技术债务总表，让"完成"真正等于"可运行、可维护、可追溯"。

---

## 为什么升级

### 解决的核心痛点

| 痛点 | 升级前 | 升级后 |
|------|--------|--------|
| "假完成" | 自测写了但没实际跑，文档好看代码挂 | 必须过 L1构建+L2启动+L3冒烟 三层验证 |
| 债务越积越多 | 每个版本加 TODO，不知道欠了多少债 | 债务增长率红线：超阈值直接阻塞 |
| 可维护性放水 | 审查 11 个维度，可维护性排最后 | 升到第 6 位，高复杂度 >5 个直接否决 |
| 证据造假 | LLM 可以编造测试结果 | Step 4 入场抽查 1~2 个 P0 用例，复现失败回退 |
| 债务散落在各处 | 每个版本各记各的，跨版本找不到 | 全局统一债务总表，15 字段标准格式 |

## 升级了什么

### 7 项核心能力

#### 1. 🔴 技术债务增长率门禁（P0）
- 三项指标：新增 TODO 数（≤5）+ 高复杂度函数增量（≤3）+ 重复率增量（≤2%）
- P0 超阈值（三项全超或任意一项超 2 倍）→ 阻塞 Step 3，必须还债或申请豁免
- 适用范围：后端 / 前端 / 全栈项目

#### 2. 🔴 实际运行验证三层模型（P0）
- **L1 构建验证**：构建/编译零错误
- **L2 启动验证**：健康检查通过 / 退出码 0
- **L3 冒烟测试**：3~5 个核心用例全部通过
- 5 类产出物适配：后端 / 前端 / 脚本工具 / 数据库 / 文档型项目
- 必须提供实际输出片段作为证据，不得以"应该能跑"替代

#### 3. 🔴 全局技术债务总表（P0）
- 15 字段标准格式：ID / 类型 / 严重级 / 发现版本 / 状态 / 计划偿还版本 / 负责人 / 详细描述 等
- 状态流转：待偿还 → 偿还中 → 已偿还 / 挂起中 → 重新激活
- 老化升级规则：P1 挂起超 2 个版本 → 升级 P0，阻塞 Step 3
- 版本变化追踪：每个版本的新增 / 偿还 / 升级 / 挂起一目了然

#### 4. 🟡 证据真实性强化（P1）
- 实际输出片段要求：每条测试证据必须包含实际输出
- 交叉验证：静态质量 ↔ 实际运行 ↔ 自测结果三方互证
- **Step 4 自测证据抽查**：入场时随机抽 1~2 个 P0 用例独立复核，造假直接回退 Step 3

#### 5. 🟡 可维护性权重升级（P1）
- 审查维度从第 11 位提升到第 6 位
- 2 项否决条件：
  - 高复杂度函数 > 5 个 → 不通过
  - 重复率 > 10% → 不通过
- 必须关联证据（复杂度报告 / 重复率报告）

#### 6. 🟡 DevLogReport 债务章节（P1）
- 新增"技术债务"专项章节，固定 4 个小节：
  - 新增债务 / 偿还债务 / 债务增长率 / 债务总览
- 每个版本的债务变化一目了然

#### 7. 🟡 债务总表引用（P1）
- version-planning 阶段必须引用全局债务总表路径
- 必须检查还债容量（建议 15~20%）
- 债务评估必须有输入来源说明

## 怎么升级

### 已有项目升级到 v2.8.4

```bash
# 1. 拉取最新版本
git pull origin master
git checkout v2.8.4

# 2. 检查全局债务总表位置
# doc/version/global/DevFlow-技术债务总表.md

# 3. 在下一个版本迭代中启用新门禁
# - Step 3 自动启用债务增长率检查和实际运行验证
# - Step 4 自动启用自测证据抽查
```

### 新使用的项目

直接从 v2.8.4 开始，所有质量门禁默认生效。

## 注意事项

### 阈值是经验值
债务增长率的三个阈值（≤5 / ≤3 / ≤2%）基于经验设定，v2.9.0 会根据 v2.8.4 的实际数据校准。如果你的项目阈值不合适，可以在项目级 config.json 中覆盖。

### 冒烟测试适配
冒烟测试提供了 5 类标准适配（后端/前端/脚本/数据库/文档），特殊项目类型可以自行扩展。

### 章节编号变化
coding-stage-execution.md 中新增了 3.5 实际运行验证章节，后续章节编号顺延。如果你的项目引用了旧章节编号，需要同步更新。
