## 1. 回滚触发条件

### 1.1 自动触发条件

| 触发条件 | 阈值 | 级别 | 动作 |
|:---------|:----:|:----:|:-----|
| 安装后验证失败 | validate-install full 模式 Fail | P0 | 紧急回滚 |
| 核心功能不可用 | 3 个以上 P0 用例失败 | P0 | 紧急回滚 |
| 配置加载异常 | 新配置无法读取且旧配置 fallback 失败 | P1 | 按预案回滚 |

### 1.2 手动触发条件

- 发现 P0 级安全漏洞
- 数据损坏或配置丢失
- 严重兼容性问题影响大面积用户
- 合规性问题

## 2. 回滚策略

### 2.1 部署策略对应的回滚路径

DevFlow 插件采用 Git Tag 版本管理，回滚路径为 **直接回退** 模式：

| 回滚类型 | 方式 | 命令 | 预计耗时 |
|:---------|:-----|:-----|:--------:|
| 代码回滚 | Git Tag 切换 | `git checkout v2.8.5` | < 1 分钟 |
| 配置回滚 | 恢复旧配置 | 使用 version.json + .devflow/config.json | < 5 分钟 |
| 完整回滚 | 重新安装旧版本 | download-devflow.ps1 -Version v2.8.5 | < 5 分钟 |

### 2.2 审批流程

| 环境 | 审批要求 |
|:-----|:---------|
| Dev | 开发人员自决 |
| Test | 测试负责人审批 |
| Pro | 发布负责人 + PM 双签 |
| 紧急回滚（P0） | 可先执行后补审批，2 小时内补材料，24 小时内 RCA |

## 3. 回滚步骤

### 3.1 标准回滚流程

```text
1. 确认故障级别 → 2. 执行审批 → 3. 备份当前状态 → 4. 执行回滚
→ 5. 回滚后验证 → 6. 记录问题 → 7. 启动根因分析
```

### 3.2 详细步骤

| 步骤 | 操作 | 命令/说明 | 验证标准 |
|:----:|:-----|:----------|:---------|
| 1 | 确认故障级别 | 评估影响范围和用户数 | 明确 P0/P1/P2 |
| 2 | 启动审批流程 | 按审批矩阵执行 | 获得审批确认 |
| 3 | 备份当前状态 | 备份配置文件和状态 | 备份文件存在 |
| 4 | 执行版本回退 | `git checkout v2.8.5` 或重新安装 | 版本号正确 |
| 5 | 配置回滚 | 确认旧配置文件可用 | version.json 可读取 |
| 6 | 回滚验证 | validate-install.ps1 -Mode full | 0 Fail |
| 7 | 通知用户 | 发布回滚通知 | 通知已发出 |
| 8 | 根因分析 | 24 小时内输出 RCA | RCA 文档完成 |
