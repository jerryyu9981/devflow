# DevFlow Release Note v2.9.0

> **版本**: v2.9.0
> **发布日期**: 2026-07-21
> **版本主题**: 还债治理 + 流程规范化

---

## 一句话介绍

v2.9.0 建立了完整的还债配额机制和跨版本债务老化流转规则，规范了 Step 0 需求来源采集流程，并在测试阶段新增了覆盖率门禁和 E2E 集成验证标准，让债务治理和测试质量有据可依。

## 为什么升级

- **还债有配额** — 每版本至少 15~20% 工作量用于偿还技术债务，低于 15% 须 PM 批准，连续 2 版低于 15% 触发专项评审
- **债务跨版本不丢失** — 挂起债务记录"连续挂起版本数"，P3>2→P2, P2>2→P1, P1>2→P0 老化升级，确保债务不会无限期挂起
- **需求来源规范化** — Step 0 收集需求时必须逐一检查 6 个标准通道（历史技术债/用户反馈/业务输入/线上问题/竞品变化/上版本遗留），避免遗漏
- **测试质量有门禁** — 新代码行覆盖率 ≥80%，低于 80% 阻塞测试阶段；E2E 验证流程标准化，通过率须 ≥95%
- **version.json 字段补全** — devflow-init 初始化时自动从 config.json 读取仓库地址补全 repository/homepage 字段

## 怎么升级

```bash
# 1. 更新到最新版本
git pull origin main

# 2. 确认版本号
cat .devflow/config.json  # projectVersion 应显示 2.9.0

# 3. 查看完整变更
git log v2.8.5..v2.9.0 --oneline
```

## 注意事项

- `.devflow/config.json` 的 `projectVersion` 字段已从 2.8.3 更新至 2.9.0
- `version.json` 的 `devflowVersion` 保持 2.8.5 不变（DevFlow 框架版本）
- 新增的还债配额门禁从 v2.10.0 版本开始首次生效
- 覆盖率门禁和 E2E 验证流程从 Step 4 自动触发，不影响已有流程
- 本版本无破坏性变更，向后兼容
