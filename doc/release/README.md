## v2.8.5 债务生命周期 + 发布自动化版

> 发布日期：2026-07-20 | 类型：功能增强 | [详细 Release Note](releases/DevFlow-Release-Note-v2.8.5.md)

### 一句话介绍
建立完整的债务生命周期闭环（发现→记录→审查→老化→偿还），标准化 Release Note + Changelog 发布文档体系，实现自动化发布脚本，确保跨版本风险和债务不遗忘、可接续。

### 核心升级

| 能力 | 优先级 | 说明 |
|------|:------:|------|
| 风险归集门禁 | 🔴 P0 | 4 个 L2 阶段技能嵌入标准化风险归集门禁，P1+ 风险自动流入债务总表 |
| 跨版本债务审查 | 🔴 P0 | Step 0 新增 0.0a 债务审查子步骤，含老化升级规则和 Backlog 预填 |
| 债务生命周期闭环 | 🔴 P0 | 流入（风险归集）+ 流出（版本启动审查→老化→偿还）双向机制 |
| Release Note 标准化 | 🟡 P1 | 8 章节模板 + Step 5 发布交付物门禁强制执行 |
| release.ps1 脚本 | 🟡 P1 | 5 步自动化：版本校验→version.json→Tag→push origin→push backup→后验 |
| Release Checklist | 🟡 P1 | 13 项检查清单（发布前 4 + 发布时 3 + 发布后 6）|
| 远程仓库交互输入 | 🟡 P1 | devflow-init 增加交互式配置（提示→输入→确认→写入）|
| 技能间委托一致性审查 | 🟡 P1 | code-logic-review 新增第 13 个审查维度 |

### 关键数据
- **8 项需求**（R-01~R-08）
- **22 项功能要项**
- **21 个测试用例** / 100% 通过率
- 零 P0/P1 缺陷
- **9 个 TD-ID** 全部实现

### 升级影响
- **新增门禁**：4 个 L2 阶段增加风险归集门禁 + Step 0 增加 0.0a 债务审查
- **新增技能维度**：code-logic-review 增加"技能间委托关系一致性审查"
- **新增文档**：Release Note + Changelog 汇总页更新
- **新增脚本**：release.ps1（devflow-plugin/）
- **流程变更**：devflow-init 初始化时增加远程仓库交互输入

### 向后兼容性
✅ 完全向后兼容。风险归集门禁仅在新阶段执行时触发；devflow-init 交互输入在已有配置时自动跳过。

## v2.8.4 质量保障基础版

> 发布日期：2026-07-20 | 类型：Patch | [详细 Release Note](releases/DevFlow-Release-Note-v2.8.4.md)

### 一句话介绍
解决 Step 3 "假完成"问题——文档写得漂亮但代码跑不起来。三道质量门禁 + 全局技术债务总表，让"完成"真正等于"可运行、可维护、可追溯"。

### 核心升级

| 能力 | 优先级 | 说明 |
|------|:------:|------|
| 技术债务增长率门禁 | 🔴 P0 | 新增 TODO / 高复杂度 / 重复率三项增量阈值，超阈值阻塞 Step 3 |
| 实际运行验证三层模型 | 🔴 P0 | L1构建 + L2启动 + L3冒烟，5 类产出物适配，必须有实际输出片段 |
| 全局技术债务总表 | 🔴 P0 | 15 字段标准格式 + 老化升级规则 + 跨版本变化追踪 |
| 证据真实性强化 | 🟡 P1 | 输出片段要求 + 交叉验证 + Step 4 自测抽查机制 |
| 可维护性权重升级 | 🟡 P1 | 从第 11 位升到第 6 位 + 2 项否决条件 |
| DevLogReport 债务章节 | 🟡 P1 | 新增技术债务专项章节，4 个固定小节 |
| 债务总表引用 | 🟡 P1 | version-planning 必须引用全局债务总表 + 还债容量检查 |

### 关键数据
- **7 项需求** / **31 个 FR** / **21 个测试用例**
- 测试通过率：**100%**
- 零 P0/P1 缺陷
- 技术债务净减：**5 条**

### 升级影响
- **新增门禁**：Step 3 增加 3.5 实际运行验证，Step 4 增加 4.0b 自测抽查
- **章节顺延**：coding-stage-execution.md 章节编号顺延，外部引用需更新
- **新增文档**：全局技术债务总表（doc/version/global/）

### 向后兼容性
✅ 完全向后兼容。新增的门禁是"做加法"，原有流程全部保留，只是在关键节点增加了验证步骤。
