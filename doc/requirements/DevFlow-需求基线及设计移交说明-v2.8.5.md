进入 Step 2 后，任何需求变更必须：

4. 通知下游同步

### 2.3 重点关注项

| 关注项 | 说明 |
|--------|------|
| R-01 P0 优先级 | 债务生命周期是核心，设计阶段需优先确保双向闭环的完整性 |
| Phase 1 优先 | 3 个 Phase 中 Phase 1 必须先完成，因为 Phase 3 依赖 Phase 1 的 Release Note 模板 |
| 向后兼容 | 所有技能文件修改必须向后兼容，不破坏现有流程 |
| 多技能一致性 | R-01 需要修改 4 个 L2 技能文件，需统一设计模板确保一致性 |

### 2.4 设计阶段建议

| 建议 | 原因 |
|------|------|
| 先设计债务生命周期规范模板 | 4 个 L2 技能文件的风险归集步骤应使用统一的设计模板 |
| version-planning 的 0.0a 节点独立设计 | 这是全新的流程节点，需要完整的流程设计和门禁定义 |
| release.ps1 按 Phase 3 设计 | 不需要在 Phase 2 之前提前设计，但架构上应考虑与 Release Checklist 的配合 |
