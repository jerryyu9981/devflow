## 3. 用户角色画像

### 角色1：多项目管理者

| 维度 | 描述 |
|---|---|
| **背景** | 同时管理多个项目的开发者 |
| **痛点** | 每个项目配置DevFlow时需要手动编辑config.json |
| **期望** | 通过devflow-init交互式配置快速完成项目设置 |
| **关联需求** | FR-001（devflow-init远程仓库交互式配置） |
| **典型场景** | 新建项目后运行devflow-init，通过交互式问答自动配置远程仓库地址（origin和backup），无需手动编辑config.json |

### 角色2：性能工程师

| 维度 | 描述 |
|---|---|
| **背景** | 负责项目性能优化的开发者 |
| **痛点** | 缺乏系统化的性能工程指导 |
| **期望** | 获得从性能需求定义到优化验证的完整流程指导 |
| **关联需求** | FR-003（性能工程全流程技能） |
| **典型场景** | 在项目中遇到性能问题时，调用DevFlow性能工程L3技能，获取系统化的性能分析、优化和验证指导 |

### 角色3：数据库开发者

| 维度 | 描述 |
|---|---|
| **背景** | 负责数据库Schema变更的开发者 |
| **痛点** | 迁移脚本编写不规范，回滚策略缺失 |
| **期望** | 获得数据库迁移的规范和最佳实践 |
| **关联需求** | FR-004（数据库迁移管理技能） |
| **典型场景** | 在进行数据库Schema变更时，调用DevFlow数据库迁移管理L3技能，获取迁移脚本编写规范、回滚策略和跨数据库支持指导 |

### 角色4：CLI用户

| 维度 | 描述 |
|---|---|
| **背景** | 使用命令行工具的极客开发者 |
| **痛点** | DevFlow在非IDE环境（如Codex CLI）兼容性不足 |
| **期望** | 在命令行环境也能流畅使用DevFlow |
| **关联需求** | FR-005（Codex CLI深度适配） |
| **典型场景** | 在终端中使用Codex CLI进行开发时，DevFlow技能能正常加载和执行，核心流程无兼容性问题 |

### 角色5：技能市场用户

| 维度 | 描述 |
|---|---|
| **背景** | 通过TRAE技能市场发现和安装DevFlow的用户 |
| **痛点** | 需要手动下载和配置，安装体验差 |
| **期望** | 一键安装，自动更新 |
| **关联需求** | FR-002（技能市场集成） |
| **典型场景** | 在TRAE技能市场搜索DevFlow，一键完成安装和配置，无需手动下载文件和编辑配置 |
