### 2.1 总体目标

DevFlow v2.4.1 是 v2.4.0 的首个修复与增强版本，聚焦于两大核心目标：**修复 v2.4.0 遗留问题** 和 **增强编码/测试质量管控**。本版本不涉及新功能开发或架构变更，核心价值在于提升 DevFlow 开发工具链的可靠性、可追溯性和规范性。

### 3.2 VR-2.4.1-001: validate-install.ps1 PS5.1 兼容性修复

#### 3.2.1 需求概述

| 字段 | 内容 |
|---|---|
| **需求 ID** | VR-2.4.1-001 |
| **需求类型** | BUG 修复 |
| **优先级** | P0 |
| **来源** | v2.4.0 测试报告 -- PS5.1 环境兼容性问题 |
| **影响范围** | `scripts/validate-install.ps1` |

#### 3.2.2 问题描述

`validate-install.ps1` 第 133 行使用了 `Test-Path ... -and Test-Path ...` 的复合表达式语法。该语法在 PowerShell 7.x 中可正常执行，但在 PowerShell 5.1 中因 `-and` 运算符优先级和 `Test-Path` 返回值的类型处理差异导致执行失败，报错信息为参数绑定异常或布尔表达式解析错误。

#### 3.2.3 修复方案

将第 133 行的复合 `Test-Path` 表达式拆分为独立的 `Test-Path` 调用，使用变量中转结果，确保 PS5.1 和 PS7.x 均可正确执行。

**修改前（问题代码）**：
```powershell
$valid = Test-Path "C:\path\A" -and Test-Path "C:\path\B"
```

**修改后（兼容方案）**：
```powershell
$pathAExists = Test-Path "C:\path\A"
$pathBExists = Test-Path "C:\path\B"
$valid = $pathAExists -and $pathBExists
```

#### 3.2.4 详细要求

| 序号 | 要求项 | 要求描述 |
|---|---|---|
| 1 | 语法修复 | 将第 133 行的复合 `Test-Path ... -and ...` 表达式拆分为独立的 `Test-Path` 调用 |
| 2 | PS5.1 验证 | 修复后的脚本在 Windows PowerShell 5.1 环境下必须可正常执行，无报错 |
| 3 | PS7.x 兼容 | 修复后的脚本在 PowerShell 7.x 环境下行为必须与修复前完全一致，无功能回归 |
| 4 | 全文件扫描 | 扫描 validate-install.ps1 全文件，排查是否存在其他类似的 PS5.1 不兼容语法 |
| 5 | 回归验证 | 修复后在 PS5.1 和 PS7.x 两个环境下均需运行 validate-install.ps1 全量验证通过 |

### 3.3 VR-2.4.1-002: coding-stage-execution 验证证据强制化

#### 3.3.1 需求概述

| 字段 | 内容 |
|---|---|
| **需求 ID** | VR-2.4.1-002 |
| **需求类型** | 流程增强 |
| **优先级** | P1 |
| **来源** | 内部改进提案 -- AI Agent 编码后声明完成但无验证证据 |
| **影响范围** | `skills/coding-stage-execution/SKILL.md` |

#### 3.3.2 问题描述

当前 coding-stage-execution 技能的强制规则 #6 虽然要求 AI Agent 在每项编码任务完成后进行验证，但未明确要求必须附带实际的运行命令和输出截图作为验证证据。在实际执行中，AI Agent 通常仅以文字声明"任务已完成"或"测试已通过"，缺乏可追溯的验证证据，导致编码质量无法被有效审计。

#### 3.3.3 详细要求

| 序号 | 要求项 | 要求描述 |
|---|---|---|
| 1 | 规则 #6 增强 | 在 coding-stage-execution 的强制规则 #6 中，增加"必须附带实际运行命令和输出截图"的强制性要求 |
| 2 | 证据格式定义 | 明确验证证据的标准格式：包含完整运行命令、命令输出内容（文本或截图）、执行时间戳 |
| 3 | 阻断机制 | 当验证证据缺失时，后续流程（开发审计）应阻断并要求补充证据 |
| 4 | 示例更新 | 在 coding-stage-execution 技能文件中提供至少 2 个合规的验证证据示例和 1 个不合格示例 |
| 5 | DevLogReport 更新 | DevLogReport 模板中增加"验证证据"字段，要求每项编码任务的 DevLog 必须包含证据链接或引用 |

### 3.4 VR-2.4.1-003: code-logic-review 偏执级检查新增

#### 3.4.1 需求概述

| 字段 | 内容 |
|---|---|
| **需求 ID** | VR-2.4.1-003 |
| **需求类型** | 功能增强 |
| **优先级** | P1 |
| **来源** | 三方对比分析报告 -- 同类产品在代码审查深度上的差距 |
| **影响范围** | `skills/code-logic-review/SKILL.md` |

#### 3.4.2 问题描述

当前 code-logic-review 技能覆盖常规代码逻辑审查（需求对齐、数据流、边界条件等），但未覆盖以下偏执级（paranoid-level）检查项：N+1 查询检测、竞态条件检测、信任边界违规检测。这些检查项在同类竞品的审查能力中已具备，DevFlow 需要补齐差距。

#### 3.4.3 详细要求

| 序号 | 要求项 | 要求描述 |
|---|---|---|
| 1 | N+1 查询检测 | 新增 N+1 查询检测检查项，要求审查器识别循环内部的数据库/网络/API 调用模式，并提供批量查询优化建议 |
| 2 | 竞态条件检测 | 新增竞态条件检测检查项，要求审查器识别共享状态读写、并发访问无保护、TOCTOU（Time-of-check to time-of-use）等竞态模式，并提供加锁/原子操作建议 |
| 3 | 信任边界违规检测 | 新增信任边界违规检测检查项，要求审查器识别未经验证的用户输入直接用于敏感操作（SQL 拼接、命令注入、路径遍历等）的模式，并提供输入清洗/参数化建议 |
| 4 | 检查触发条件 | 3 项偏执级检查仅在涉及相应技术栈时触发（如 N+1 查询仅在涉及数据库操作时触发），避免对不相关的代码产生噪音 |
| 5 | 输出格式 | 3 项偏执级检查的输出格式与现有检查项一致，包含：检查项名称、严重级别（P0/P1/P2）、问题描述、修复建议、参考规范 |

### 3.5 VR-2.4.1-004: testing-stage-execution TDD 证据链检查

#### 3.5.1 需求概述

| 字段 | 内容 |
|---|---|
| **需求 ID** | VR-2.4.1-004 |
| **需求类型** | 功能增强 |
| **优先级** | P1 |
| **来源** | 内部改进提案 -- 测试阶段无法追溯 TDD 合规性 |
| **影响范围** | `skills/testing-stage-execution/SKILL.md` |

#### 3.5.2 问题描述

当前 testing-stage-execution 技能未包含 TDD（Test-Driven Development）证据链检查项。在编码阶段（Step 3），AI Agent 理应遵循 TDD 流程（先编写测试代码，再编写生产代码），但当前无法在测试阶段回溯验证每个 feat/fix 提交是否包含先于生产代码的测试文件。

#### 3.5.3 详细要求

| 序号 | 要求项 | 要求描述 |
|---|---|---|
| 1 | TDD 证据链检查项 | 在 testing-stage-execution 技能中新增 TDD 证据链检查项，验证每个 feat/fix 提交的 Git 提交历史中是否包含先于生产代码的测试文件 |
| 2 | 检查维度 | 检查维度包括：测试文件提交时间是否早于生产代码提交时间；测试文件是否覆盖对应功能的核心逻辑；测试文件是否可独立运行 |
| 3 | 合规判定标准 | 定义 TDD 合规判定标准：合规 -- 测试文件先于生产代码提交；部分合规 -- 测试文件与生产代码同一提交但在同一文件中先定义测试；不合规 -- 无测试文件或测试晚于生产代码 |
| 4 | 报告输出 | TDD 证据链检查结果纳入测试阶段报告，包含：每个 feat/fix 提交的 TDD 合规状态、合规率统计、不合规项清单 |
| 5 | 阈值要求 | TDD 合规率阈值设定为 >= 90%（允许 10% 的非合规宽限，用于紧急修复场景） |

### 3.6 VR-2.4.1-005: 22 个旧版技能文件格式标准化

| 字段 | 内容 |

### 3.7 VR-2.4.1-006: check-skill-format.ps1 自动填充能力增强

#### 3.7.1 需求概述

| 字段 | 内容 |
|---|---|
| **需求 ID** | VR-2.4.1-006 |
| **需求类型** | 脚本增强 |
| **优先级** | P2 |
| **来源** | VR-2.4.1-005 的依赖需求 -- 需要自动化工具支撑批量标准化 |
| **影响范围** | `scripts/check-skill-format.ps1` |

#### 3.7.2 问题描述

当前 check-skill-format.ps1 仅具备格式检查（检测问题）能力，不具备自动修复能力。VR-2.4.1-005 需要对 22 个旧版技能文件进行批量标准化，手动修复效率低下且容易遗漏。需要在检查脚本中增加自动填充缺失标准章节的能力。

#### 3.7.3 详细要求

| 序号 | 要求项 | 要求描述 |
|---|---|---|
| 1 | 自动填充功能 | check-skill-format.ps1 增加 `--fix` 参数，启用自动修复模式 |
| 2 | 填充范围 | 自动填充覆盖 skill-md-writing-standards 规范定义的全部标准章节模板（缺失章节自动插入，内容使用规范定义的占位符模板） |
| 3 | 幂等性 | 多次执行自动填充不会产生重复章节或内容冲突 |
| 4 | 差异预览 | `--fix` 模式执行前输出修改预览（将要新增/修改的章节列表），用户确认后再执行 |
| 5 | 验证闭环 | 自动填充完成后自动重新运行格式检查，验证填充结果是否合规 |
| 6 | PS5.1 兼容 | 自动填充功能需确保在 PS5.1 和 PS7.x 下均可正常运行 |
