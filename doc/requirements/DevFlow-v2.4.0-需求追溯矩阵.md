## 1. 追溯矩阵概述

### 1.1 文档目的

本文档是 DevFlow v2.4.0 版本的需求追溯矩阵，建立从版本目标到业务流程的完整追溯链，确保每个需求都可追踪其来源（版本成功指标）和去向（用户故事、用户场景、业务流程），实现需求的全生命周期可追溯性。

### 1.2 追溯链结构

DevFlow 需求追溯链采用多层级追溯模型，从战略目标逐步分解到可验证的业务流程：

```
版本成功指标(GOAL) -> Backlog项(BL) -> 需求(RT) -> 验收标准(AC) -> 用户故事(US) -> 用户场景(USC) -> 业务流程(BP)
```

| 追溯层级 | ID 前缀 | 命名规则 | 说明 |
|---|---|---|---|
| 版本成功指标 | GOAL-{维度}{编号} | 如 GOAL-A1, GOAL-B2 | 对应版本成功指标说明文档中的 15 项指标 |
| Backlog 项 | BL-{NNN} | 三位数字，按 Backlog 序号 | 对应本版本 Backlog 中的条目序号 |
| 需求追溯项 | RT-{NNN} | 三位数字，按需求编号 | 核心追溯节点，关联 VR-ID |
| 验收标准 | AC-{RT编号}-{序号} | 如 AC-001-1, AC-001-2 | 从开发需求文档的验收标准章节提取 |
| 用户故事 | US-{NNN} | 三位数字，按需求对应编号 | 对应用户需求说明书中的用户故事 |
| 用户场景 | USC-{NNN} | 三位数字，按场景编号 | 对应用户需求说明书中的用户场景 |
| 业务流程 | BP-{NNN} | 三位数字，按流程编号 | 对应用户需求说明书中的业务流程 |

### 1.3 强制追溯规则

| 规则编号 | 规则名称 | 规则描述 |
|---|---|---|
| TR-001 | P0/P1 全追溯 | 所有 P0 和 P1 需求必须 100% 建立完整追溯链（从版本目标到业务流程） |
| TR-002 | 来源可溯 | 每个需求必须关联至少一个版本成功指标，说明该需求对版本目标的贡献 |
| TR-003 | 验收可验 | 每个需求必须至少有 1 条可验证的验收标准 |
| TR-004 | 故事映射 | 每个需求必须对应至少 1 个用户故事 |
| TR-005 | 场景覆盖 | P0 需求必须对应至少 1 个用户场景 |

### 7.1 后续阶段追溯扩展

### 7.2 追溯矩阵使用场景

| 使用场景 | 使用方式 | 使用者 |
|---|---|---|
| **需求评审** | 检查每项需求的追溯链完整性，确保无"孤儿需求" | 质量负责人 |

| **变更影响分析** | 当需求变更时，通过追溯链快速识别受影响的设计项、代码模块和测试用例 | 开发负责人 |
| **发布验收** | 通过追溯链验证每项需求的验收标准是否全部通过 | 项目负责人 |
| **审计输入** | 作为 Step 1 评估报告的需求完整性审计输入 | 质量负责人 |
