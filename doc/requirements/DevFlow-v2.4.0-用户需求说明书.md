## 2. 业务目标

### 2.1 总体目标

DevFlow v2.4.0 从用户视角聚焦四大核心痛点的系统性解决：**上手体验改善、工程能力缺口补全、内容质量统一、跨平台兼容**。版本目标是让 DevFlow 从"可用"走向"好用"，让用户在 10 分钟内完成从安装到首次项目开发，让技能内容质量达到 100% 审查通过，让 DevFlow 在主流 AI 编程工具中均能稳定运行。

### 2.2 分维度业务目标

#### 2.2.1 上手体验维度

| 目标项 | 当前状态 | v2.4.0 目标 | 衡量方式 |
|---|---|---|---|
| 新用户安装成功率 | ~60%（估算） | >= 90% | 安装验证测试通过率（VR-005） |
| 安装到首次运行时间 | > 30 分钟（估算） | < 10 分钟 | 手动计时测试（安装 + 初始化 + 首次版本规划） |
| 新用户自助完成率 | ~40%（估算） | >= 80% | 仅提供快速入门指南，5 名新用户中 >= 4 名在 30 分钟内完成全流程 |
| 安装过程错误率 | 未度量 | < 5% | 非用户操作错误导致的安装失败率 |

**用户价值描述**：安装不再是新用户使用 DevFlow 的第一道门槛。交互式安装向导（VR-001）自动检测环境、引导配置、一键安装全部技能和模板；增强的项目初始化向导（VR-002）通过交互式问答自动推断项目阶段并生成配置文件；快速入门指南（VR-003）提供 5 分钟内可完成的上手教程；安装验证测试（VR-005）确保安装完整性，让用户安心开始使用。

#### 2.2.2 工程能力维度

| 目标项 | 当前状态 | v2.4.0 目标 | 衡量方式 |
|---|---|---|---|
| 技能总数 | 22 个（3 L1 + 6 L2 + 10 L3 + 3 Orchestrator） | >= 25 个 | `skills/` 目录下 SKILL.md 文件统计 |
| 模板总数 | 19 个 | >= 25 个 | `templates/` 目录下模板文件统计 |
| 容灾备份覆盖评级 | ★☆☆☆☆ | >= ★★★☆☆ | 工程能力矩阵评估 |
| 工程领域覆盖数 | 17 个 | >= 19 个 | 工程能力矩阵评估 |

**用户价值描述**：开发者在项目开发过程中遇到容灾备份、安全开发、容器化部署等场景时，DevFlow 能提供完整的规范指导和操作模板。容灾备份技能增强（VR-006）从最低评级提升到中等水平，安全开发全流程技能（VR-007）覆盖安全设计、安全编码、安全测试链路，容器化部署技能（VR-009）提供 Docker/K8s 部署规范。

#### 2.2.3 内容质量维度

| 目标项 | 当前状态 | v2.4.0 目标 | 衡量方式 |
|---|---|---|---|
| 技能质量审查通过率 | 未审查 | 100% | VR-011 质量审查报告 |
| 格式一致性 | 低（5 种以上不同格式） | 100% | VR-012 格式检查脚本 |
| 内容重复/矛盾数量 | 未知 | 0 | VR-011 质量审查 + VR-013 交叉引用检查 |
| 交叉引用正确率 | 未知 | 100% | VR-013 交叉引用检查脚本 |

**用户价值描述**：AI 助手在调用 DevFlow 技能时不再因格式不一致、内容重复或引用断裂而产生困惑。技能文件质量审查（VR-011）对全部 22 个技能进行系统性质量评估并修复问题；SKILL.md 编写规范和模板（VR-012）提供四套层级标准模板，确保后续新增技能格式统一；交叉引用完整性检查（VR-013）和 L2 速查表补全（VR-014）确保技能间的调用链路清晰可靠。

#### 2.2.4 跨平台兼容维度

| 目标项 | 当前状态 | v2.4.0 目标 | 衡量方式 |
|---|---|---|---|
| Claude Code 兼容性 | ★★★☆☆ | ★★★★☆ | 核心流程 >= 90% 无阻塞通过 |
| Cursor 兼容性 | ★★☆☆☆ | ★★★★☆ | 核心流程 >= 90% 无阻塞通过 |
| Codex CLI 兼容性 | ★☆☆☆☆ | ★★★☆☆ | 基础流程 >= 70% 无阻塞通过 |
| Windows/macOS/Linux 统一支持 | ★★★☆☆ | ★★★★★ | 三平台安装+运行全流程测试通过 |

**用户价值描述**：无论开发者使用 TRAE IDE、Claude Code 还是 Cursor 作为 AI 编程助手，DevFlow 都能稳定运行。跨平台兼容验证（VR-015/VR-016/VR-017）确保在三大 AI 编程工具中的核心流程可用，跨平台安装脚本统一（VR-018）消除 Windows/macOS/Linux 三平台的安装体验差异。

### 4.2 USC-001: 新用户首次安装 DevFlow

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-001 |
| **场景名称** | 新用户首次安装 DevFlow |
| **用户角色** | 主要用户（开发者 / 开发团队负责人） |
| **关联需求** | VR-001（交互式安装向导）、VR-018（跨平台安装脚本统一） |
| **前置条件** | 用户已安装 AI 编程助手（TRAE IDE / Claude Code / Cursor 之一）；用户有网络连接；用户对 DevFlow 有基本了解（通过 README 或推荐） |

**场景描述（步骤流程）**：

1. 用户在 AI 编程助手中执行 DevFlow 安装命令
2. 交互式安装向导启动，自动检测当前运行环境（操作系统类型、Shell 环境、AI 编程助手类型）
3. 安装向导显示检测结果，告知用户当前环境是否满足安装条件
4. 用户确认安装配置（安装目录、技能集选择等）
5. 安装向导自动下载并安装选定的技能文件和模板文件
6. 安装向导自动执行安装验证测试（VR-005），检查技能文件完整性和模板齐全性
7. 安装向导输出安装结果报告，包含：安装状态、已安装技能列表、验证结果、后续操作指引

**预期结果**：
- 整个安装过程在 5 分钟内完成
- 安装验证测试 100% 通过
- 用户无需手动判断环境依赖
- 安装完成后可直接使用 DevFlow

**异常场景**：

| 异常编号 | 异常描述 | 系统行为 |
|---|---|---|
| E-001-01 | 网络连接失败，无法下载技能文件 | 安装向导提示网络错误，建议检查网络连接后重试，支持断点续传 |
| E-001-02 | 安装目录权限不足 | 安装向导提示权限不足，给出修复建议（使用 sudo / 修改目录权限） |
| E-001-03 | 检测到已有 DevFlow 版本 | 安装向导提示用户选择：覆盖安装 / 升级安装 / 取消，默认选择升级安装 |
| E-001-04 | 操作系统不支持 | 安装向导显示不支持的平台信息，提供已支持平台列表 |
| E-001-05 | 安装验证失败（技能文件不完整） | 安装向导显示具体缺失文件列表，自动尝试重新下载缺失部分 |

### 4.3 USC-002: 新项目初始化并启动版本规划

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-002 |
| **场景名称** | 新项目初始化并启动版本规划 |
| **用户角色** | 主要用户（开发者 / 开发团队负责人） |
| **关联需求** | VR-002（项目初始化向导增强） |
| **前置条件** | DevFlow 已安装且验证通过；用户已打开一个项目目录（新建或已有项目） |

**场景描述（步骤流程）**：

1. 用户在 AI 编程助手中调用 DevFlow 初始化功能
2. 增强版初始化向导启动，自动检测当前项目状态（是否已有 `.devflow/` 目录、是否有 `package.json` / `pom.xml` 等项目元文件）
3. 初始化向导通过交互式问答收集项目信息：项目名称、项目类型、技术栈、团队规模、开发模式
4. 初始化向导自动推断项目当前所处的开发阶段（新项目 -> 版本规划阶段，已有项目 -> 检测到当前阶段）
5. 初始化向导自动生成 `.devflow/config.json` 配置文件，包含项目信息和阶段状态
6. 初始化向导自动创建 `.devflow/state.json` 状态文件
7. 初始化向导输出初始化结果，包含：配置文件路径、当前阶段、下一步操作建议（如"开始版本规划"）

**预期结果**：
- 整个初始化过程在 3 分钟内完成
- 自动推断的项目阶段与实际情况一致
- 生成的配置文件语法正确、内容合理
- 用户无需手动填写大量配置字段

**异常场景**：

| 异常编号 | 异常描述 | 系统行为 |
|---|---|---|
| E-002-01 | 项目目录已有 `.devflow/` 配置 | 初始化向导提示已有配置，询问用户：重置配置 / 保留并升级 / 取消 |
| E-002-02 | 无法自动推断项目类型 | 初始化向导提供项目类型列表供用户手动选择 |
| E-002-03 | 无法自动推断开发阶段 | 初始化向导默认从"版本规划"阶段开始，提示用户可在后续调整 |
| E-002-04 | 配置文件写入失败（目录只读） | 初始化向导提示错误，建议检查目录权限或更换安装目录 |

### 4.4 USC-003: 开发者按规范编写技能文件

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-003 |
| **场景名称** | 开发者按规范编写技能文件 |
| **用户角色** | 主要用户（开发者 / 技能开发者） |
| **关联需求** | VR-012（SKILL.md 编写规范和模板） |
| **前置条件** | VR-012 已交付 4 套标准模板（L1/L2/L3/Orchestrator）；开发者需要新增或修改一个技能文件 |

**场景描述（步骤流程）**：

1. 开发者确定需要编写的技能类型和层级（L1/L2/L3/Orchestrator）
2. 开发者获取对应层级的标准模板文件
3. 开发者按模板结构填写技能内容（元数据、适用条件、技能描述、输入输出、关联技能等）
4. 开发者使用格式检查脚本验证技能文件是否符合 VR-012 规范
5. 格式检查脚本输出检查结果，标注不符合规范的条目及修改建议
6. 开发者根据检查结果修改技能文件，直至全部检查项通过

**预期结果**：
- 新增技能文件 100% 符合 SKILL.md 编写规范
- 格式检查脚本在 10 秒内完成检查并输出结果
- 开发者无需反复查阅规范文档即可正确编写技能文件
- 同一层级的技能文件格式完全一致

**异常场景**：

| 异常编号 | 异常描述 | 系统行为 |
|---|---|---|
| E-003-01 | 技能层级不确定 | 规范文档提供层级选择指引，根据技能性质（编排/执行/参考）推荐合适层级 |
| E-003-02 | 模板中某些字段不适用当前技能 | 规范说明可选字段和必填字段的区别，不适用字段标注为 N/A 并说明原因 |
| E-003-03 | 格式检查脚本报错但不明确 | 检查脚本输出详细错误说明和修改示例，提供规范文档对应章节的链接 |

### 4.5 USC-004: 质量审查发现技能问题

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-004 |
| **场景名称** | 质量审查发现技能问题 |
| **用户角色** | 主要用户（质量负责人 / 开发者） |
| **关联需求** | VR-011（技能文件质量审查和统一）、VR-013（技能间交叉引用完整性检查） |

**场景描述（步骤流程）**：

### 6.2 BPF-001: 安装与初始化流程

#### 6.2.1 流程目标

确保新用户在任何支持平台上都能顺利安装 DevFlow 并完成项目初始化，实现"安装到首次运行 < 10 分钟"的目标。

#### 6.2.2 流程步骤

| S6 | 运行验证 | 安装验证脚本 | 自动验证已安装的技能文件完整性（文件存在、格式正确）和模板齐全性 | 已安装文件 | 验证报告 |
| S7 | 验证结果判断 | 安装向导 | 根据验证报告判断安装是否成功 | 验证报告 | 安装成功/失败 |

| S3 | 兼容问题收集 | 兼容性负责人 | 收集测试过程中发现的兼容性问题，记录问题现象、重现步骤、平台信息 | 测试执行结果 | 兼容性问题清单 |
| S4 | 问题分级 | 兼容性负责人 | 按严重程度对兼容性问题进行分级：P0（阻塞功能）/ P1（功能降级）/ P2（体验问题） | 兼容性问题清单 | 分级后的问题清单 |
| S5 | 兼容问题修复 | 开发者 | 按分级优先级修复兼容性问题：P0 立即修复 / P1 记录并修复 / P2 记录待修或接受限制 | 分级后的问题清单 | 修复后的 DevFlow |
| S6 | 回归验证 | 兼容性负责人 | 在各平台上重新执行核心流程测试，验证修复是否有效且未引入新问题 | 修复后的 DevFlow | 回归测试结果 |
| S7 | 兼容性评分 | 兼容性负责人 | 根据回归测试结果计算各平台的兼容性评分（五星制），输出兼容性评估报告 | 回归测试结果 | 兼容性评估报告 |

#### 6.4.3 异常分支流程

| 分支编号 | 触发条件 | 分支流程 | 恢复路径 |
|---|---|---|---|
| B-003-01 | S1 平台环境准备失败（如 Codex CLI 尚无稳定版本） | 记录环境准备失败原因 -> 评估是否为平台本身限制 -> 如是，标注为已知限制 | 降低该平台的评分目标（如 VR-017 从 ★★★★☆ 降为 ★★★☆☆） |

## 7. 业务规则

### 7.1 安装向导交互规则

| 规则编号 | 规则名称 | 规则描述 |
|---|---|---|
| BR-001 | 环境检测优先规则 | 安装向导必须在用户配置前先完成环境检测，确保后续配置引导基于准确的环境信息 |
| BR-002 | 默认值推荐规则 | 所有交互式配置项必须提供合理的默认值，用户可直接回车使用默认配置，实现"零配置安装" |
| BR-003 | 步骤可回退规则 | 用户在安装过程中的任何步骤都可以返回上一步重新配置，但已完成的下载步骤不重复执行 |
| BR-004 | 错误不中断规则 | 非关键错误（如非致命的格式检查警告）不应中断安装流程，应在安装完成后统一报告 |
| BR-005 | 幂等安装规则 | 重复执行安装命令不会导致重复安装或文件覆盖混乱，已安装的文件仅当版本更新时才覆盖 |
| BR-006 | 进度可见规则 | 安装过程中必须提供实时进度反馈（已下载文件数 / 总文件数、当前步骤名称），避免长时间无响应 |

### 7.2 质量审查通过/不通过判定规则

| 规则编号 | 规则名称 | 规则描述 |
|---|---|---|
| BR-007 | 审查通过标准 | 技能文件质量审查通过的必要条件：① 格式 100% 符合 VR-012 编写规范；② 内容无 P0/P1 级别重复或矛盾；③ 必填字段全部填写且准确 |
| BR-007-01 | 审查不通过标准 | 出现以下任一情况即判定审查不通过：① 存在 P0 级别内容重复或矛盾；② 必填字段缺失或内容错误；③ 格式严重不符合规范（>3 个规范项不合规） |
| BR-008 | 问题分级规则 | P0 = 阻塞 AI 助手正常调用技能的问题（如引用断裂、必填字段缺失）；P1 = 影响技能输出质量但不阻塞调用的问题（如描述含糊、示例过时）；P2 = 优化建议（如措辞优化、格式微调） |
| BR-009 | 回归审查规则 | 修复后的技能文件必须重新通过完整的质量审查流程（而非仅验证修复点），确保修复未引入新问题 |
| BR-010 | 交叉引用正确性规则 | 技能 A 引用技能 B 时，技能 B 必须存在且层级关系正确（如 L2 引用 L3 是合法的，L3 引用 L2 是不合法的） |

|---|---|---|

#### 兼容性评分详细标准

| 评分 | 无阻塞通过率 | 描述 |
|---|---|---|
| ★★★★★ | 100% | 全部测试用例无阻塞通过，与 TRAE IDE 体验完全一致 |
| ★★★★☆ | >= 90% | 核心流程无阻塞通过，少数边缘场景有轻微差异但不影响使用 |
| ★★★☆☆ | >= 70% | 核心流程大部分可用，部分功能有降级或限制 |
| ★★☆☆☆ | >= 50% | 基础功能可用，核心流程有明显阻塞点 |
| ★☆☆☆☆ | < 50% | 基础功能不稳定，不建议在该平台使用 |

#### 评分规则补充说明

| 规则编号 | 规则名称 | 规则描述 |
|---|---|---|
| BR-012 | 核心流程定义 | Claude Code/Cursor 兼容性验证的核心流程：安装 -> 初始化 -> 版本规划 -> 需求分析 -> 设计；Codex CLI 兼容性验证的核心流程：安装 -> 技能加载 -> 技能调用 |
| BR-013 | 无阻塞判定 | "无阻塞通过"指测试用例执行过程中未出现因 DevFlow 技能问题导致的功能不可用或严重错误输出。平台自身的问题（如 Claude Code 响应超时）不计入 DevFlow 兼容性问题 |
| BR-014 | 评分计算方式 | 无阻塞通过率 = 该平台无阻塞通过的测试用例数 / 该平台总测试用例数 x 100%，结果四舍五入到整数 |
| BR-015 | 评分降级规则 | 如某平台存在已知的、平台自身限制导致的兼容性问题（且 DevFlow 无法通过适配解决），可在评分报告中标注"因平台限制降级"，但降级后的评分仍需达到对应需求的最低目标 |
