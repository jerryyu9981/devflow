## 1. 项目概述

### 1.1 项目定位

v2.8.1 为脚本交互增强与技术债务修复版本，在 v2.8.0 基础上进一步完善 DevFlow 三阶段安装流程（Download → Setup → Init）的交互体验，同时修复 update.ps1 中遗留的 SKILL.md 硬编码问题。

### 1.2 核心目标

1. **download-devflow.ps1 版本比较与交互确认**：Clone/Update 前展示远程版本与本地版本，仅在有更新时执行下载；展示源/目的地址供用户确认
2. **setup.ps1 增加交互确认**：复制前展示版本号、文件数、目标路径，用户确认后才执行
3. **修复 update.ps1 SKILL.md 硬编码**：对非 .md 文件保留原文件名（参照 V260-037 方案）
4. **devflow-init 版本更新时同步文件**：检测到 `installed_newer` 时，将 TRAE 系统目录的 DevFlow 文件同步到项目 `.devflow/`

### 1.3 需求优先级

| 优先级 | 定义 | 本版本数量 |
|:------:|------|:---------:|
| 🔴 P0 | 必须完成，blocking | 3 项 |
| 🟡 P1 | 应该完成，高优先级 | 1 项 |

## 2. 核心功能需求

### 2.1 V260-044：download-devflow.ps1 增加版本比较与交互确认

**用户故事**：作为 DevFlow 用户，我希望在执行 Clone 或 Update 前能确认源/目的地址，并且仅当远程仓库有新版本时才执行下载，避免不必要的网络操作。

**验收标准**：

| 编号 | 验收项 | 验证方法 |
|:----:|--------|---------|
| AC-01 | 展示远程版本和本地版本，仅远程版本更新时才执行 clone/pull | 手动测试 |
| AC-02 | 展示源地址（从 version.json.repository 读取）和目的地址（默认当前目录），等待用户确认 | 手动测试 |

**功能点**：

| 功能 | 描述 |
|------|------|
| 源地址确认 | 从 `version.json.repository` 读取仓库地址并展示，用户可修改或确认 |
| 目的地址确认 | 默认当前目录，用户可修改后确认 |
| 远程版本获取 | 通过 `git ls-remote --tags` 获取远程仓库最新 tag 的版本号 |
| 本地版本读取 | 从本地 `version.json.devflowVersion` 读取当前版本 |
| 语义化版本比较 | major.minor.patch 逐段比较数字 |
| 更新判断 | 远程版本 > 本地版本 → 执行 clone/pull；否则提示"已是最新版本"并跳过 |

### 2.2 V260-045：setup.ps1 增加交互确认步骤

**用户故事**：作为首次安装用户，我希望 setup.ps1 在执行文件复制前能展示即将安装的版本信息和文件数量，让我确认后再写入 TRAE 系统目录，避免误操作。

**验收标准**：

| 编号 | 验收项 | 验证方法 |
|:----:|--------|---------|
| AC-03 | 执行前展示版本号和文件数，等待用户输入 y/Y 确认后才执行复制 | 手动测试 |
| AC-06 | 展示安装后的目标路径（`~/.trae-cn/skills/`） | 手动测试 |

**功能点**：

| 功能 | 描述 |
|------|------|
| 版本号展示 | 读取并展示本地副本 `version.json.devflowVersion` |
| 文件计数 | 统计即将复制的技能文件数量并展示 |
| 目标路径展示 | 展示安装后的 TRAE 系统目录目标路径 |
| 交互确认 | 通过 `Read-Host` 等待用户输入 y/Y，确认后才执行复制 |
| 取消处理 | 用户输入非 y/Y 时，优雅退出并提示未安装 |

### 2.3 V260-038：修复 update.ps1 复制逻辑中 SKILL.md 硬编码

**用户故事**：作为使用 update.ps1 直接更新 DevFlow 的用户，我希望非 .md 配置文件（如 `version.json`、`sync-skills.ps1`、`download-devflow.ps1`）在更新后保留原文件名，而不是被错误命名为 `SKILL.md`。

**验收标准**：

| 编号 | 验收项 | 验证方法 |
|:----:|--------|---------|
| AC-04 | 非 .md 文件保留原文件名；.md 文件仍命名为 SKILL.md | 文件存在性检查 |

**功能点**：

| 功能 | 描述 |
|------|------|
| 扩展名判断 | 复制前判断源文件扩展名：.md → `SKILL.md`，非 .md → 保留原文件名 |
| 影响范围 | 直接影响用户直接运行 `update.ps1` 的场景；推荐更新路径 `update-devflow.bat`（调用 `sync-skills.ps1`）不受影响 |
| 兼容性 | 不改变已有 .md 技能文件的更新行为 |

### 2.4 V260-046：devflow-init 版本更新时同步项目 devflow 文件

**用户故事**：作为 DevFlow 用户，当检测到 TRAE 系统目录的 DevFlow 版本比项目记录版本更新时，我希望 devflow-init 不仅更新项目中的版本号记录，还能将 TRAE 系统目录的最新 DevFlow 配置文件同步到项目目录，保持两者一致。

**验收标准**：

| 编号 | 验收项 | 验证方法 |
|:----:|--------|---------|
| AC-05 | 检测到 `installed_newer` 时，将 TRAE 系统目录的 DevFlow 相关文件同步到项目 `.devflow/` | 文件内容比对 |

**功能点**：

| 功能 | 描述 |
|------|------|
| 检测触发 | 版本差异检测结果为 `installed_newer`（TRAE 版本 > 项目版本）时触发 |
| 文件同步 | 从 `~/.trae-cn/skills/` 下的 DevFlow 相关文件复制到项目 `.devflow/` |
| 配置更新 | 同步更新 `config.json` 和 `state.json` 的模板结构 |
| 版本号写入 | 同步更新 `state.json.devflowVersion` 为 TRAE 系统目录版本 |
| 降级处理 | 目标目录或文件不存在时跳过对应项，不中断流程 |
