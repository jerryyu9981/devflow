## 2. 业务目标

### 2.1 总体目标

DevFlow v2.5.0 "生态集成版本" 是 v2.4.1 之后的全新功能版本，聚焦四大核心目标：**完成 TRAE 技能市场生态集成**、**性能工程领域覆盖提升至最高等级**、**devflow-init 交互式远程仓库配置**、**Codex CLI 跨平台兼容性**。本版本包含 5 项功能需求（VR-019/004/008/010/017），不涉及架构变更。

### 3.2 FR-001（VR-019）: devflow-init 远程仓库交互式配置

#### 3.2.1 需求概述

| 字段 | 内容 |
|---|---|
| **需求 ID** | FR-001 |
| **关联 VR** | VR-019 |
| **需求类型** | 功能增强 |
| **优先级** | P1 |
| **来源** | 内部改进提案 -- 多项目管理的远程仓库配置不便 |
| **影响范围** | `devflow-init/SKILL.md`、`.devflow/config.json` |

#### 3.2.2 需求描述

增强 devflow-init 编排器，在初始化流程中增加远程仓库配置引导步骤。当用户在新的项目中初始化 DevFlow 时，交互式地引导用户输入项目远程仓库地址（origin 和可选的 backup），并将配置正确写入 `.devflow/config.json`。

#### 3.2.3 详细要求

| 序号 | 要求项 | 要求描述 |
|---|---|---|
| FR-001-1 | origin 远程仓库地址输入 | 交互式引导用户输入 origin 远程仓库地址，支持 HTTPS 和 SSH 两种 Git URL 格式 |
| FR-001-2 | backup 远程仓库地址输入 | 交互式引导用户输入 backup 远程仓库地址（可选），用户可跳过 |
| FR-001-3 | 地址类型区分 | 交互界面明确区分"DevFlow 下载地址"（DevFlow 自身的 Git 仓库 URL）与"用户项目 Git 远程仓库地址"（用户项目的 Git 仓库 URL），避免混淆 |
| FR-001-4 | 配置写入 | 配置正确写入 `.devflow/config.json` 的 `remote.origin` 和 `remote.backup` 字段 |
| FR-001-5 | 示例说明 | 提供示例说明两种地址的区别：<br>- DevFlow 下载地址示例：`https://github.com/example/devflow.git`<br>- 项目远程仓库示例：`https://github.com/example/my-project.git` |

#### 3.2.4 错误处理

| 错误场景 | 处理方式 |
|---|---|
| 地址格式不合法 | 提示 URL 格式不正确并给出正确格式示例（HTTPS: `https://host/owner/repo.git`；SSH: `git@host:owner/repo.git`） |
| 用户跳过配置 | 允许空值，保持空字符串 `""`，后续可通过 `git remote add` 命令手动配置 |
| 用户输入 DevFlow 下载地址到项目仓库字段 | 系统提示"此处应输入项目远程仓库地址，非 DevFlow 下载地址" |
