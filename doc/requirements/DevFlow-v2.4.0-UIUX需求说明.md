## 1. 概述

### 1.1 文档目的

本文档是 DevFlow v2.4.0 版本的 **UI/UX 需求说明**，从用户界面和交互体验视角定义 CLI 交互界面、终端输出格式、HTML 文档输出的设计规范和交互原型。DevFlow 作为一套基于 CLI 交互的软件开发工程规范插件，其 UI/UX 体验主要体现在终端命令行交互和文档输出两个维度。本文档为开发团队（Step 3 编码阶段）提供明确的界面设计约束和交互行为规范，确保各交互界面风格统一、信息传达清晰、操作流程简洁。

### 1.2 范围定义

本文档覆盖 DevFlow v2.4.0 中涉及用户界面和交互体验的全部需求项：

| 需求编号 | 需求名称 | 交互类型 | 覆盖章节 |
|---|---|---|---|
| VR-001 | 交互式安装向导 | CLI 交互 | 第 3 章 |
| VR-002 | 项目初始化向导增强 | CLI 交互 | 第 4 章 |
| VR-005 | 安装验证测试 | 终端输出 | 第 5 章 |
| VR-003 | 快速入门指南 | HTML 文档 | 第 6 章 |

### 1.3 设计原则

DevFlow 的 UI/UX 设计遵循以下四项核心原则：

| 原则 | 说明 | 适用范围 |
|---|---|---|
| **CLI 优先** | 所有交互以终端命令行为主界面，不依赖 GUI 框架，保证在最小环境即可运行 | 安装向导、初始化向导、验证测试 |
| **信息清晰** | 状态信息使用颜色 + 图标 + 文字三重编码，确保关键信息一目了然 | 所有 CLI 输出、HTML 文档 |
| **操作简单** | 采用向导式交互，每步仅问一个问题，提供默认选项减少用户决策负担 | 安装向导、初始化向导 |
| **错误友好** | 错误信息包含原因描述和可操作的恢复建议，避免技术术语堆砌 | 所有错误场景 |

## 2. CLI 交互设计规范

本章定义 DevFlow 所有 CLI 交互界面的统一设计规范，适用于 VR-001、VR-002、VR-005 及后续版本的 CLI 交互场景。

### 2.1 交互风格

#### 2.1.1 ANSI 色彩使用规范

DevFlow CLI 交互使用 ANSI 转义码实现终端色彩，色彩分配遵循语义一致性原则：

| 色彩类别 | ANSI 颜色码 | 用途 | 使用场景 |
|---|---|---|---|
| **成功绿** | `\033[32m` / `Green` | 表示通过、完成、正常状态 | 环境检测通过、安装完成、验证通过 |
| **警告黄** | `\033[33m` / `Yellow` | 表示可选缺失、建议注意 | 可选依赖未安装、版本升级提示 |
| **错误红** | `\033[31m` / `Red` | 表示失败、错误、必需项缺失 | 环境不满足、安装失败、验证不通过 |
| **信息蓝** | `\033[34m` / `Blue` | 表示标题、提示、引导信息 | 步骤标题、菜单项、提示文本 |
| **进度灰** | `\033[90m` / `DarkGray` | 表示进度条背景、次要信息 | 进度条底色、分隔线、说明文字 |
| **重置** | `\033[0m` / `Reset` | 恢复默认颜色 | 每段色彩输出后必须重置 |

**使用规则**：
1. 每段带颜色的输出结束后必须调用颜色重置
2. 同一行避免使用超过 2 种颜色
3. 不使用闪烁、反色等可能干扰阅读的特殊效果

#### 2.1.2 输入方式

DevFlow CLI 支持四种标准输入交互方式：

| 输入方式 | 格式说明 | 使用场景 | 示例 |
|---|---|---|---|
| **单选菜单** | 数字编号 + 选项文本 + 默认标记 `[推荐]` | 项目类型选择、分支策略选择 | `请输入选项 [1-3]: _` |
| **多选菜单** | 数字编号 + 选项文本 + 空格分隔输入 | 模板选择、技能选择 | `请输入选项 (空格分隔): 1 3 5` |
| **文本输入** | 提示文字 + `>` 光标 + 格式说明 | 仓库名称、项目名称输入 | `> _` |
| **确认提示** | Yes/No 选项 + 默认标记 `(Y/n)` 或 `(y/N)` | 危险操作确认、覆盖确认 | `确认继续? (Y/n): _` |

#### 2.1.3 输出格式规范

| 输出元素 | 格式说明 | 使用场景 |
|---|---|---|
| **标题行** | 使用 `═══` 等粗线框包裹，居中对齐 | 步骤标题、章节标题 |
| **分隔线** | 使用 `───` 细线分隔内容区块 | 选项之间、步骤之间 |
| **表格** | 使用 `│` 竖线和 `─` 横线构成对齐表格 | 环境检测结果、安装摘要 |
| **进度条** | 使用 `[=====>   ]` 纯文字字符实现 | 文件复制、安装进度 |
| **状态图标** | 使用 Unicode 字符辅助状态识别 | `✓` 成功、`✗` 失败、`⚠` 警告、`ℹ` 信息 |

#### 2.1.4 响应时间要求

| 交互场景 | 响应时间要求 | 说明 |
|---|---|---|
| 用户输入后反馈 | < 0.5 秒 | 即时回显输入内容 |
| 菜单选项显示 | < 1 秒 | 选项渲染完成 |
| 环境检测结果 | < 2 秒 | 所有检测项完成 |
| 安装进度更新 | < 2 秒/步 | 每个安装步骤的状态刷新 |
| 错误提示显示 | < 0.5 秒 | 错误发生后立即提示 |

## 3. VR-001 安装向导原型草案

本章定义交互式安装向导每个步骤的 CLI 交互界面原型。安装向导运行于终端环境，通过 PowerShell（Windows）或 bash（macOS/Linux）脚本实现。

### 3.1 步骤总览

安装向导共 5 个步骤，按顺序执行：

| 步骤 | 名称 | 用户交互类型 | 说明 |
|---|---|---|---|
| 1 | 环境检测 | 仅输出（自动） | 自动检测运行环境并展示结果 |
| 2 | 配置引导 | 单选菜单 + 文本输入 | 引导用户选择分支策略和配置远程仓库 |
| 3 | 远程仓库配置 | 文本输入 | 可选输入 DevFlow 远程仓库地址 |
| 4 | 安装执行 | 仅输出（自动） | 展示安装进度 |
| 5 | 安装完成 | 仅输出（自动） | 展示安装结果摘要和下一步指引 |

### 3.2 步骤 1 — 环境检测

**行为描述**：安装脚本启动后自动执行环境检测，逐项检查操作系统、Git、PowerShell/bash、Node.js（可选）、网络连通性，并检测是否已安装旧版本。检测结果使用带状态图标的列表展示。

**交互原型**：

```
╔══════════════════════════════════════════════════╗
║  DevFlow Plugin Installer v2.4.0                ║
╠══════════════════════════════════════════════════╣
║  环境检测中...                                   ║
╠══════════════════════════════════════════════════╣
║  ✓ 操作系统: Windows 11 (x64)                    ║
║  ✓ Git: 2.45.0                                  ║
║  ✓ PowerShell: 5.1.19041                         ║
║  ✗ Node.js: 未安装 (可选)                         ║
║  ✓ 网络连通性: 正常                               ║
║  ℹ 已安装版本: v2.3.2 (将升级到 v2.4.0)           ║
╚══════════════════════════════════════════════════╝
```

**状态说明**：
- `✓` 绿色：检测通过
- `✗` 红色：必需项缺失（安装将中止）或可选项缺失（仅提示）
- `ℹ` 蓝色：信息性提示

**异常处理**：
- 若必需项（操作系统不兼容、Git 未安装、PowerShell/bash 版本过低）检测失败，显示错误提示并提供安装指引后退出
- 若可选项缺失，显示黄色警告但允许继续

```
╔══════════════════════════════════════════════════╗
║  环境检测失败                                     ║
╠══════════════════════════════════════════════════╣
║  ✗ Git: 未安装                                   ║
║                                                  ║
║  Git 是 DevFlow 的必需依赖。请先安装 Git 后重试。   ║
║                                                  ║
║  下载地址: https://git-scm.com/downloads          ║
╚══════════════════════════════════════════════════╝
```

### 3.3 步骤 2 — 配置引导

**行为描述**：环境检测通过后，引导用户选择分支策略。用户通过输入数字编号进行选择，提供默认推荐选项。

**交互原型 — 分支策略选择**：

```
─── 配置引导 ─────────────────────────────────────

请选择分支策略:
  [1] git-flow       (推荐，适合正式项目)
  [2] feature-branch (适合敏捷团队)
  [3] trunk-based    (适合持续部署)

请输入选项 [1-3] (默认: 1): _
```

**交互行为**：
- 用户输入 1-3 之间的数字后按回车确认
- 直接按回车使用默认选项（标注推荐的选项）
- 输入无效值时提示重新输入：

```
⚠ 无效输入，请输入 1-3 之间的数字
请输入选项 [1-3] (默认: 1): _
```

### 3.4 步骤 3 — 远程仓库配置

**行为描述**：询问用户是否需要配置 DevFlow 远程仓库地址。此项为可选项，用户可直接回车跳过。

**交互原型**：

```
─── 远程仓库配置 ─────────────────────────────────

请输入 DevFlow 远程仓库地址 (可选，直接回车跳过):
> _
提示: 格式为 https://xxx 或 http://xxx
```

**交互行为**：
- 用户输入仓库 URL 后按回车确认
- 直接按回车跳过，使用默认配置（无远程仓库）
- 输入格式不正确时提示：

```
⚠ 格式不正确，仓库地址应以 https:// 或 http:// 开头
请重新输入 (直接回车跳过):
> _
```

### 3.5 步骤 4 — 安装进度

**行为描述**：配置确认后开始执行安装。安装过程中使用纯文字进度条实时展示安装状态，每个步骤完成后更新进度。

**交互原型**：

```
─── 正在安装 DevFlow v2.4.0 ──────────────────────

  [====>                ] 25% - 复制技能文件
  [========>            ] 50% - 复制模板文件
  [============>        ] 75% - 生成配置文件
  [================>] 100% - 完成
```

**进度条规范**：
- 总宽度：20 个字符
- 已完成部分：`=` 字符
- 当前位置：`>` 字符（指向最后一个已完成位置）
- 未完成部分：空格字符
- 百分比显示在进度条前方

**安装步骤定义**：

| 进度范围 | 步骤名称 | 说明 |
|---|---|---|
| 0%-25% | 复制技能文件 | 将 skills/ 目录下所有 SKILL.md 复制到目标路径 |
| 25%-50% | 复制模板文件 | 将 templates/ 目录下所有模板文件复制到目标路径 |
| 50%-75% | 生成配置文件 | 生成 .devflow/config.json 配置文件 |
| 75%-100% | 完成 | 更新版本号、清理临时文件 |

### 3.6 步骤 5 — 安装结果

**行为描述**：安装完成后展示安装摘要，包括安装的技能数量、模板数量、配置文件路径，以及下一步操作指引。

**交互原型 — 成功**：

```
╔══════════════════════════════════════════════════╗
║  ✓ 安装完成！                                     ║
╠══════════════════════════════════════════════════╣
║  已安装 25 个技能                                 ║
║  已安装 22 个模板                                 ║
║  配置文件: .devflow/config.json                   ║
║                                                  ║
║  下一步: 在你的项目中运行 devflow-init 初始化项目    ║
╚══════════════════════════════════════════════════╝
```

**交互原型 — 部分成功（有警告）**：

```
╔══════════════════════════════════════════════════╗
║  ⚠ 安装完成（部分成功）                            ║
╠══════════════════════════════════════════════════╣
║  已安装 25 个技能                                 ║
║  已安装 22 个模板                                 ║
║  配置文件: .devflow/config.json                   ║
║                                                  ║
║  ⚠ Node.js 未安装，部分 HTML 文档生成功能不可用      ║
║                                                  ║
║  下一步: 在你的项目中运行 devflow-init 初始化项目    ║
╚══════════════════════════════════════════════════╝
```

**交互原型 — 失败**：

```
╔══════════════════════════════════════════════════╗
║  ✗ 安装失败                                       ║
╠══════════════════════════════════════════════════╣
║  错误: 写入 .devflow/config.json 失败              ║
║  原因: 目标目录权限不足                             ║
║                                                  ║
║  建议操作:                                        ║
║    1. 检查目标目录的写入权限                        ║
║    2. 以管理员身份重新运行安装脚本                    ║
║    3. 查看日志获取详细信息: install.log              ║
╚══════════════════════════════════════════════════╝
```

## 4. VR-002 初始化向导原型草案

本章定义项目初始化向导的 CLI 交互界面原型。初始化向导通过用户交互收集项目信息，自动推断当前阶段，并生成项目配置文件。

### 4.1 步骤总览

| 步骤 | 名称 | 用户交互类型 | 说明 |
|---|---|---|---|
| 1 | 项目信息输入 | 文本输入 | 输入项目名称和简要描述 |
| 2 | 项目类型选择 | 单选菜单 | 选择项目类型（Web/移动端/后端/库/其他） |
| 3 | 开发模式选择 | 单选菜单 | 选择开发模式（独立开发/团队协作） |
| 4 | 阶段推断结果 | 仅输出（自动） | 展示自动推断的项目阶段和检测结果 |
| 5 | 配置生成确认 | 确认提示 | 确认生成配置文件 |

### 4.2 步骤 1 — 项目信息输入

**交互原型**：

```
╔══════════════════════════════════════════════════╗
║  DevFlow 项目初始化向导                             ║
╠══════════════════════════════════════════════════╣
║                                                  ║
║  请输入项目名称:                                   ║
║  > MyWebApp                                      ║
║                                                  ║
║  请输入项目简要描述 (可选，直接回车跳过):             ║
║  > 一个基于 React 的前端项目                         ║
║                                                  ║
╚══════════════════════════════════════════════════╝
```

**交互行为**：
- 项目名称为必填项，输入为空时提示重新输入
- 项目描述为可选项，直接回车跳过

**空输入提示**：

```
⚠ 项目名称不能为空
请输入项目名称:
> _
```

### 4.3 步骤 2 — 项目类型选择

**交互原型**：

```
─── 项目类型 ──────────────────────────────────────

请选择项目类型:
  [1] Web 应用      (前端 / 全栈 Web 项目)
  [2] 移动端应用    (iOS / Android / 跨平台)
  [3] 后端服务      (API 服务 / 微服务)
  [4] 工具库        (SDK / 组件库 / CLI 工具)
  [5] 其他          (文档项目 / 数据脚本等)

请输入选项 [1-5]: _
```

### 4.4 步骤 3 — 开发模式选择

**交互原型**：

```
─── 开发模式 ──────────────────────────────────────

请选择开发模式:
  [1] 独立开发      (单人项目，简化流程)
  [2] 团队协作      (多人协作，完整工程规范)

请输入选项 [1-2]: _
```

### 4.5 步骤 4 — 阶段推断结果

**行为描述**：根据用户输入的项目信息和当前项目目录状态，自动推断项目当前所处的开发阶段。

**交互原型 — 推断成功**：

```
╔══════════════════════════════════════════════════╗
║  ℹ 项目阶段推断结果                                ║
╠══════════════════════════════════════════════════╣
║                                                  ║
║  ✓ 已检测到 Git 仓库                              ║
║  ✓ 已检测到 package.json                         ║
║  ✓ 已检测到 src/ 目录                             ║
║  ℹ 推断阶段: Step 2 — 设计阶段                    ║
║     依据: 已有代码结构和依赖配置，但缺少设计文档        ║
║                                                  ║
╚══════════════════════════════════════════════════╝
```

**交互原型 — 推断不确定**：

```
╔══════════════════════════════════════════════════╗
║  ℹ 项目阶段推断结果                                ║
╠══════════════════════════════════════════════════╣
║                                                  ║
║  ⚠ 未能自动推断项目阶段                              ║
║     依据: 项目目录为空，未检测到已有项目文件           ║
║                                                  ║
║  建议从以下阶段开始:                                ║
║    [1] Step 0 — 版本规划                           ║
║    [2] Step 1 — 需求分析                           ║
║    [3] Step 2 — 设计                               ║
║                                                  ║
║  请输入选项 [1-3] (默认: 1): _                     ║
║                                                  ║
╚══════════════════════════════════════════════════╝
```

### 4.6 步骤 5 — 配置生成确认

**交互原型**：

```
─── 配置摘要 ──────────────────────────────────────

  项目名称:     MyWebApp
  项目类型:     Web 应用
  开发模式:     团队协作
  分支策略:     git-flow
```

## 8. 无障碍要求

### 8.1 终端输出无障碍

终端交互的无障碍设计遵循以下规范：

| 规范项 | 要求 | 实现方式 |
|---|---|---|
| **不依赖颜色传达信息** | 状态信息不能仅通过颜色区分，必须同时使用文字或图标 | 使用 `✓`/`✗`/`⚠`/`ℹ` 图标 + 文字描述双重编码 |
| **图标替代方案** | 在不支持 Unicode 图标的终端中，使用文字替代 | `[OK]` 替代 `✓`，`[FAIL]` 替代 `✗`，`[WARN]` 替代 `⚠`，`[INFO]` 替代 `ℹ` |
| **高对比度** | 文字与背景的对比度不低于 4.5:1 | ANSI 颜色搭配默认终端背景色 |
| **屏幕阅读器兼容** | 输出文本应可被屏幕阅读器正确朗读 | 避免使用纯装饰性字符序列，状态图标后跟随文字描述 |
| **输入提示清晰** | 所有需要用户输入的位置必须有明确的提示 | 使用 `> _` 或 `请输入: _` 明确标识输入位置 |

**图标降级方案**：

当终端不支持 Unicode 图标时（如部分 Windows CMD 环境），自动降级为 ASCII 文字替代：

| Unicode 图标 | ASCII 替代 | 含义 |
|---|---|---|
| `✓` | `[OK]` | 成功/通过 |
| `✗` | `[FAIL]` | 失败/错误 |
| `⚠` | `[WARN]` | 警告/注意 |
| `ℹ` | `[INFO]` | 信息/提示 |

脚本应在启动时检测终端 Unicode 支持能力，自动选择合适的图标集。

### 8.2 HTML 文档无障碍

快速入门指南 HTML 文档遵循 **WCAG 2.1 AA** 级别无障碍要求：

| WCAG 准则 | 要求 | 实现方式 |
|---|---|---|
| **1.1.1 非文本内容** | 所有图片和图标必须有 alt 文本 | 代码块中的装饰图标添加 `aria-hidden="true"`，功能性图标添加 `aria-label` |
| **1.3.1 信息和关系** | 使用语义化 HTML 标签 | 使用 `<nav>` 导航、`<main>` 主内容、`<section>` 章节、`<h1>`-`<h4>` 层级标题 |
| **1.3.2 有意义的顺序** | DOM 顺序与视觉顺序一致 | 步骤内容按逻辑顺序排列，CSS 布局不改变阅读顺序 |
| **1.4.3 对比度** | 文字与背景对比度 >= 4.5:1 | 正文文字 `#333333` 在白色背景上对比度 12.6:1 |
| **2.1.1 键盘** | 所有交互可通过键盘完成 | FAQ 折叠支持 Enter/Space 键，步骤导航支持 Tab 键切换 |
| **2.4.1 跳过区块** | 提供跳过导航链接 | 页面顶部提供 "跳到主内容" 链接 |
| **2.4.3 焦点顺序** | 焦点顺序符合逻辑 | Tab 顺序: 导航 → 步骤标签 → 内容 → FAQ |
| **2.4.6 标题和标签** | 标题清楚描述内容 | 每个步骤使用描述性标题，FAQ 使用问题作为标题 |
| **3.1.1 页面语言** | 声明页面主要语言 | `<html lang="zh-CN">` |
| **4.1.2 名称和角色** | 自定义组件有正确的 ARIA 角色 | FAQ 折叠使用 `role="button"` + `aria-expanded` |

| **终端宽度** | CLI 交互界面以 80 字符宽度为基准设计，兼容最小 60 字符宽度的终端窗口 |
| **编码格式** | CLI 输出和 HTML 文档均使用 UTF-8 编码 |
