### 1.2 USC-001: 多项目远程仓库配置

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-001 |
| **场景名称** | 多项目远程仓库配置 |
| **用户角色** | 使用 DevFlow 管理多个项目的开发者 |
| **关联需求** | FR-001（devflow-init 远程仓库交互式配置） |
| **前置条件** | 已通过 `install.ps1` 安装 DevFlow 到项目 A，现在要在项目 B 使用 DevFlow |

#### 1.2.1 主场景

1. 用户在项目 B 目录执行 `devflow-init`
2. 初始化流程启动，DevFlow 检测当前项目状态
3. 初始化流程中展示远程仓库配置引导界面
4. 引导界面首先明确说明"DevFlow 下载地址"与"用户项目 Git 远程仓库地址"的区别，并提供示例
5. 用户输入项目 B 的 origin 远程仓库地址（如 `https://github.com/example/project-b.git`）
6. 系统校验 URL 格式，格式正确则继续
7. 用户可选输入 backup 远程仓库地址，或跳过
8. 配置自动写入 `.devflow/config.json` 的 `remote.origin` 和 `remote.backup` 字段
9. 初始化流程继续后续步骤

**预期结果**：config.json 中正确写入项目 B 的远程仓库地址，后续 DevFlow 流程可正确引用。

#### 1.2.2 异常场景

| 异常编号 | 异常描述 | 系统行为 |
|---|---|---|
| E-001-01 | 用户输入了 DevFlow 下载地址而非项目仓库地址 | 系统检测到地址与 DevFlow 自身仓库匹配，提示"此处应输入项目远程仓库地址，非 DevFlow 下载地址" |
| E-001-02 | 用户输入非法 URL 格式（如缺少协议前缀、格式不完整） | 系统提示 URL 格式不正确，并给出正确格式示例（HTTPS: `https://host/owner/repo.git`；SSH: `git@host:owner/repo.git`） |

#### 1.2.3 边界场景

| 边界编号 | 边界描述 | 系统行为 |
|---|---|---|
| B-001-01 | 用户跳过远程仓库配置（直接回车或选择跳过） | 保持空字符串 `""`，系统提示"可后续通过 `git remote add` 命令手动配置"，初始化流程继续 |
| B-001-02 | 用户只配置 origin，不配置 backup | origin 字段写入用户输入值，backup 字段保持空字符串 `""` |

### 1.4 USC-003: 性能工程全流程指导

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-003 |
| **场景名称** | 性能工程全流程指导 |
| **用户角色** | 负责性能优化的开发者 |
| **关联需求** | FR-003（性能工程全流程技能） |
| **前置条件** | 项目存在性能瓶颈，需要系统化性能工程指导 |

#### 1.4.1 主场景

1. 用户在编码阶段或测试阶段调用性能工程技能（L3 performance-engineering）
2. 技能首先提供性能需求定义模板，用户填写响应时间、吞吐量、并发数、资源约束等指标
3. 技能引导用户建立性能测试基准（基准测试 → 负载测试 → 压力测试 → 稳定性测试）
4. 基于测试结果，技能提供性能瓶颈分析框架（前端渲染/后端接口/数据库查询/缓存策略）
5. 技能提供性能优化决策树，用户按照"分析 → 定位 → 优化 → 验证"的循环进行优化
6. 技能提供容量规划指南，帮助用户进行资源评估和扩容策略制定

**预期结果**：用户获得从需求定义到容量规划的完整性能工程指导，无需外部参考资料。

#### 1.4.2 边界场景

| 边界编号 | 边界描述 | 系统行为 |
|---|---|---|
| B-003-01 | 用户仅需查看某一环节（如仅查看瓶颈分析方法） | 技能文件章节独立，用户可跳转到具体章节直接使用 |

### 1.5 USC-004: 数据库迁移规范指导

| 字段 | 内容 |
|---|---|
| **场景 ID** | USC-004 |
| **场景名称** | 数据库迁移规范指导 |
| **用户角色** | 需要执行数据库 Schema 变更的开发者 |
| **关联需求** | FR-004（数据库迁移管理技能） |
| **前置条件** | 项目有数据库变更需求（如新增表、修改字段、调整索引等） |

#### 1.5.1 主场景

1. 用户在编码阶段调用数据库迁移管理技能（L3 database-migration）
2. 技能首先提供 Schema 版本管理规范，用户按照命名约定创建新的迁移版本
3. 技能引导用户编写 up/down 迁移脚本对，确保幂等性和事务包裹
4. 技能提供回滚策略说明，用户了解自动回滚和手动回滚的适用场景
5. 技能提供多环境迁移流程指导（Dev → Test → Pro），包括数据脱敏和配置差异
6. 迁移执行后，技能提供数据一致性校验方法（校验脚本/Checksum/行数对比）

**预期结果**：用户获得从迁移脚本编写到多环境部署再到一致性校验的完整数据库迁移指导。

#### 1.5.2 边界场景

| 边界编号 | 边界描述 | 系统行为 |
|---|---|---|
| B-004-01 | 用户使用 MongoDB 而非关系型数据库 | 技能文件提供 MongoDB 特定的迁移脚本示例和注意事项 |
| B-004-02 | 迁移过程中需要数据回滚 | 技能提供回滚策略章节，用户按步骤执行回滚操作 |

### 3.2 BPF-001: 远程仓库交互式配置流程

#### 3.2.1 流程目标

在 devflow-init 初始化流程中，通过交互式引导帮助用户完成项目远程仓库地址的配置，并将配置正确写入 config.json。

#### 3.2.2 流程步骤

| 步骤编号 | 步骤名称 | 执行者 | 操作描述 | 输入 | 输出 |
|---|---|---|---|---|---|
| S1 | 初始化启动 | 开发者 | 在新项目目录执行 `devflow-init`，初始化流程启动 | 项目目录 | 初始化流程启动 |
| S2 | 地址类型说明 | AI Agent | 展示远程仓库配置引导界面，明确说明"DevFlow 下载地址"与"项目仓库地址"的区别，提供示例 | 引导界面 | 用户已理解两种地址的区别 |
| S3 | origin 地址输入 | 开发者 | 输入项目 origin 远程仓库地址（HTTPS 或 SSH 格式） | 用户输入 | origin 地址值 |
| S4 | 格式校验 | AI Agent | 校验 origin 地址是否为合法 Git URL 格式 | origin 地址值 | 校验通过/失败 |
| S5 | backup 地址输入 | 开发者 | 可选输入 backup 远程仓库地址，或直接跳过 | 用户输入 | backup 地址值（或空字符串） |
| S6 | 配置写入 | AI Agent | 将 origin 和 backup 地址写入 `.devflow/config.json` 的 `remote.origin` 和 `remote.backup` 字段 | 地址值 | config.json 更新 |
| S7 | 配置确认 | AI Agent | 展示配置结果，确认写入成功 | config.json | 配置完成提示 |

#### 3.2.3 异常分支

| 分支编号 | 触发条件 | 分支流程 | 恢复路径 |
|---|---|---|---|
| B-001-01 | S4 格式校验失败 | 提示 URL 格式不正确，给出正确格式示例 | 回到 S3 重新输入 |
| B-001-02 | 用户输入 DevFlow 下载地址到项目仓库字段 | 检测地址匹配，提示"此处应输入项目仓库地址" | 回到 S3 重新输入 |
| B-001-03 | 用户跳过所有配置 | origin 和 backup 均保持空字符串，提示后续可通过 `git remote add` 手动配置 | 继续后续初始化步骤 |

#### 3.3.2 流程步骤
