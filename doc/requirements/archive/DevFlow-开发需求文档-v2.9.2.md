## 4. 业务流程

### 4.1 配置版本号统一流程

```
开始
  → 读取 devflow-config.json 权威版本号
  → 更新项目根 version.json
  → 更新 .devflow/config.json projectVersion
  → 验证三者一致
  → 结束
```

### 4.2 弃用文件清理流程

```
开始
  → 检查 .devflow/backup/ 是否存在
    → 不存在则创建
  → 备份 version.json 和 devflow-manifest.json
  → 验证备份完整
  → 删除原文件
  → 验证 devflow-plugin/ 无弃用文件
  → 结束
```

### 4.3 风险归集模板增强流程

```
开始
  → 读取 operations-stage-execution 问题跟踪记录模板
  → 增加"风险归集检查"必填章节
  → 验证章节存在
  → 结束
```

## 5. 功能需求

### 5.1 F-01 项目根 version.json 版本号统一

| 属性 | 内容 |
|:-----|:-----|
| **需求 ID** | FR-292-001 |
| **优先级** | P0 |
| **来源** | 线上问题 (SRC-04) |
| **需求池项** | V292-001 |

**描述**：
将项目根 version.json 的 version 字段更新为 2.9.2，补全 repository 和 homepage 字段。

**输入**：
devflow-config.json (v2.9.1) 作为权威版本源

**处理**：
手动更新 version 字段为 2.9.2，填充 repository 和 homepage

**输出**：
项目根 version.json 版本号=2.9.2，repository/homepage 非空

**错误处理**：
文件不存在时创建并填充

### 5.2 F-02 .devflow/config.json projectVersion 更新

| 属性 | 内容 |
|:-----|:-----|
| **需求 ID** | FR-292-002 |
| **优先级** | P0 |
| **来源** | 线上问题 (SRC-04) |
| **需求池项** | V292-002 |

**描述**：
将 .devflow/config.json 中 projectVersion 从 2.9.0 更新为 2.9.2。

**输入**：
当前 config.json (projectVersion=2.9.0)

**处理**：
手动更新 projectVersion 字段为 2.9.2

**输出**：
config.json projectVersion=2.9.2

### 5.3 F-03 已弃用配置文件清理

| 属性 | 内容 |
|:-----|:-----|
| **需求 ID** | FR-292-003 |
| **优先级** | P1 |
| **来源** | 线上问题 (SRC-04) |
| **需求池项** | V292-003 |

**描述**：
将 devflow-plugin/version.json 和 devflow-manifest.json 备份至 .devflow/backup/ 后删除。

**输入**：
devflow-plugin/ 下两个弃用文件

**处理**：
备份 → 验证备份完整 → 删除原文件

**输出**：
devflow-plugin/ 下无 version.json 和 devflow-manifest.json

**错误处理**：
备份失败则不删除

### 5.4 F-04 风险归集门禁前置准备

| 属性 | 内容 |
|:-----|:-----|
| **需求 ID** | FR-292-004 |
| **优先级** | P2 |
| **来源** | 技术债 (SRC-06) |
| **需求池项** | V292-004 |
| **技术债务 ID** | TD-026 |

**描述**：
在 operations-stage-execution 的问题跟踪记录模板中增加"风险归集检查"必填章节。

**输入**：
当前问题跟踪记录模板（无风险归集章节）

**处理**：
在模板中增加必填章节，包含：本阶段 P1+ 风险是否已归集到技术债务总表、未归集风险 ID 及原因

**输出**：
模板包含风险归集必填章节
