## 1. 业务目标

### 1.1 版本使命

v2.8.5 定位为 **"流程体系完善版"**，使命是补全 DevFlow 流程体系中的结构性缺口，建立从"风险发现→债务记录→版本审查→债务偿还"的完整债务生命周期闭环，同时补齐发布机制、配置交互和自动化脚本三大辅助能力。

### 1.2 业务目标与成功指标

| 目标编号 | 目标 | 成功指标 | 验收方式 |
|:--------:|------|---------|---------|
| G-01 | 债务生命周期闭环 | 各阶段风险归集率 100% + 新版本自动触发债务审查 | Step 0 执行记录 + 审计报告 |
| G-02 | 用户可感知版本变化 | v2.8.5 发布时同时输出 Release Note + Changelog | Step 5 交付物检查 |
| G-03 | devflow-init 配置修复 | 执行时必须交互输入远程仓库地址 | 执行录屏/trace |
| G-04 | 发布检查清单+脚本 | Step 5 按 checklist 执行，release.ps1 可执行 | 文件存在性 + 执行测试 |
| G-05 | 跨技能一致性审计 | code-logic-review 增加技能间一致性审查维度 | 审查记录证据 |
| G-06 | 跨版本债务接续 | Step 0 自动审查全局债务总表并执行老化升级 | version-planning 中 0.0a 章节证明 |

## 2. 用户场景与用户故事

### 2.1 用户角色定义

| 角色 | 描述 | 使用场景 |
|------|------|---------|
| DevFlow 框架使用者 | 使用 DevFlow 进行项目开发的产品经理/开发者 | 日常使用 DevFlow 各阶段技能 |

| 最终用户 | 通过 Release Note 了解版本变化的用户 | 查看版本更新 |

### 2.2 用户场景

#### 场景一：债务生命周期管理（R-01）

**主场景**：
1. 开发者在 Step 3 编码阶段发现一个风险（如某技能缺少关键门禁）
2. 根据新规范，在阶段审计移交前将风险录入全局债务总表
3. 下个版本启动时，Step 0.0a 自动读取总表中待偿还条目
4. 老化升级规则自动检查：超过 2 个版本未处理的 P1 自动升级为 P0
5. 升级后的债务自动进入本版本 Backlog，分配还债计划

**异常场景**：风险未录入总表 → 阶段门禁检查不通过 → 回退补录

#### 场景二：版本发布说明（R-02）

**主场景**：
1. Step 5 完成部署后，自动生成 Release Note 描述本版本变更
2. Changelog 汇总页自动追加新版本记录
3. 用户打开 Changelog 即可查看所有版本的历史变更

#### 场景三：devflow-init 交互配置（R-03）

**主场景**：
1. 新项目首次执行 devflow-init
2. 工具交互提示"请输入远程仓库地址（留空则跳过）"
3. 用户输入后，工具校验地址格式并确认
4. 配置写入 devflow-project-config 规范文件

#### 场景四：一致性审计（R-04）

**主场景**：
1. 开发者在 code-logic-review 中触发一致性审计
2. 审计检查：A 技能委托 B 技能 → B 技能中有对应规范吗？
3. A 技能执行流程正确引用 B 技能规范了吗？
4. A 技能有没有内联与 B 技能规范不一致的模板？

#### 场景五：发布自动化（R-05 ~ R-07）

**主场景**：
1. Step 5 开始前，执行 Release Checklist 逐项检查
2. 运行 release.ps1 自动校验版本号、创建 Tag、推送双仓库
3. CI/CD 门禁自动校验 Tag 存在性、备份同步、版本号一致性

## 3. 业务流程

### 3.1 债务生命周期流程（R-01）

```text
[方向一：流入]
Step 0~5 各阶段执行
    ↓
发现 P1+ 风险/问题
    ↓
阶段审计移交前 → 检查是否已录入全局债务总表
    ↓ 已录入                   ↓ 未录入
    通过门禁                  退回补录
    ↓                         ↓
继续下一阶段                写入总表（固定15字段格式）
                              ↓
                             重新检查门禁

[方向二：流出]
新版本 Step 0 启动
    ↓
0.0a 债务审查节点（新增）
    ↓
打开全局债务总表
    ↓
列出"待偿还"状态条目
    ↓
执行老化升级检查：
  - P3 挂起 >2 版本 → P2
  - P2 挂起 >2 版本 → P1
  - P1 挂起 >2 版本 → P0（阻塞 Step 3）
    ↓
确定本版本还债计划
    ↓
写入本版本 Backlog
```

### 3.2 发布流程（R-02, R-05 ~ R-07）

```text
Step 5 开始
    ↓
执行 Release Checklist（发布前）
  - [ ] 版本号确认（version.json vs 规划文档）
  - [ ] Backlog 完成度确认
  - [ ] 测试报告确认
  - [ ] 审计报告确认
    ↓
运行 release.ps1
  - 版本号校验
  - Git Tag 创建（v{版本号}）
  - Tag 推送到 origin
  - Tag 推送到 backup
  - 版本一致性验证
    ↓
生成 Release Note
  - 一句话介绍
  - 为什么升级
  - 升级了什么
  - 怎么升级
  - 注意事项
    ↓
更新 Changelog 汇总页
    ↓
CI/CD 门禁校验（后置验证）
  - Tag 存在性
  - 远程仓库同步
  - 备份同步
  - 版本号一致性
```
