## 1. 项目概述

### 1.1 项目定位

DevFlow 是软件开发工程规范框架，通过 L1/L2/L3 三层技能体系为 AI 驱动的软件开发提供 6 阶段（Step 0~5）工程管控。本版本（v2.16.0）聚焦**测试巡检网络层监控规范增强**与**审计执行确定性加固**。

### 1.2 核心目标

| 目标 | 说明 | 成功指标 |
|:----|:-----|:---------|
| G1：网络层监控固化 | 将 T3a 巡检与 E2E 的网络层健康监控固化为 Step 4 标准动作，使偶发/时序缺陷（如 BUG-291-012 竞态 500）在测试阶段即可被捕获 | testing-stage-execution 包含 8 项改进；T3b/E2E 模板强制调用 assert_network_clean |
| G2：审计执行确定性 | 确保 audit-agent 检查点复查以"验证命令"列为唯一依据逐条执行 | audit-agent 检查点逐条执行记录；全流程审计报告含逐条执行记录章节 |

### 1.3 核心概念定义

| 术语 | 定义 |
|:-----|:-----|
| T3a 全页面巡检 | 自动导航全部路由，逐页采集网络层/渲染/行为信号，输出逐页问题表 |
| 网络层信号 | HTTP 响应状态、网络请求失败（requestfailed）、console error、pageerror 等浏览器网络层事件 |
| H 类环境提示 | 响应体明确指向外部服务/依赖未启动（如 503"无法连接Ollama服务"），非代码缺陷 |
| I 类弃用警告 | console error 含 deprecated/deprecation 关键词的第三方弃用提示，仅记录不登记 |
| L3 网络层断言 | "无代码类 HTTP≥500 + 无 requestfailed + 无代码类 console error"的强制断言 |
| assert_network_clean | E2E 用例末尾强制执行的网络层健康断言函数 |

### 2.2 用户故事

**US-216-001（测试工程师）**：作为测试工程师，我希望 T3a 巡检能自动监控 HTTP≥500、requestfailed 和 console error 并关联来源页面，以便偶发的时序性缺陷（如竞态 500）在巡检阶段就被捕获，而不是漏检到人工测试。

**US-216-002（测试工程师）**：作为测试工程师，我希望巡检能区分"环境类提示"（如 Ollama 未启动的 503）与"代码缺陷"（如竞态 500），以便环境问题登记为环境遗留、真实缺陷进入缺陷闭环，避免误报与漏报。

**US-216-003（测试工程师）**：作为测试工程师，我希望 E2E 用例能自动订阅网络层事件并在用例末尾断言网络健康，以便每个 E2E 用例都证明"请求成功"，而不只是"页面打开"。

**US-216-004（审计师）**：作为审计师，我希望审计时逐条执行检查点复查的验证命令并记录实际输出，以便审计结论基于真实执行结果而非 LLM 自觉，杜绝检查点执行遗漏。

### 2.3 功能需求详述

#### RT-216-001: T3a 巡检信号表升级（6→8 类）

| 项 | 内容 |
|:---|:-----|
| 前置条件 | testing-stage-execution 已包含 T3a 六步闭环工作流与 6 类信号表 |
| 功能描述 | 将 T3a 巡检信号采集表从 6 类升级为 8 类 |
| 处理逻辑 | ① 原"HTTP ≥ 400"拆分为"HTTP 4xx"与"HTTP ≥ 500"两行；② HTTP ≥ 500 行强制采集响应体摘要（前 200 字符）；③ 新增"网络请求失败（requestfailed）"信号行（采集失败 URL + 失败原因）；④ 每个响应事件必须关联来源页面（逐页访问前后记录错误数）|
| 输入 | 浏览器网络层事件（response/requestfailed/console/pageerror）|
| 输出 | 8 类信号采集表（含响应体摘要字段）|
| 权限 | 无特殊权限要求 |
| 错误处理 | 响应体读取失败（非 JSON/流式）时记录空摘要并继续采集 |

#### RT-216-002: 问题分类扩展（7→9 类）+ 判定优先级流程

| 项 | 内容 |
|:---|:-----|
| 前置条件 | 7 类标准问题分类表存在（A~G 类）|
| 功能描述 | 新增 H 类环境提示 / I 类弃用警告，并定义判定优先级流程 |
| 处理逻辑 | ① H 类：HTTP 503/504 + 响应体含"无法连接Xxx服务"类服务提示 → 登记环境遗留清单，不进缺陷闭环；② I 类：console error 含 deprecated/deprecation → 仅记录不登记；③ 判定优先级：HTTP≥500 → 读响应体摘要 → 含服务提示走 H 类 / 含异常堆栈走 B 类；console.error → 含弃用关键词走 I 类 / 否则走 D 类 |
| 输出 | 9 类问题分类表 + 判定优先级流程 |
| 错误处理 | 响应体为空/通用错误时，直连复现后归 B 类 |

#### RT-216-003: L3 网络层断言强制

| 项 | 内容 |
|:---|:-----|
| 前置条件 | 断言分级规范（L1/L2/L3）存在 |
| 功能描述 | L3 网络层断言成为 T3a/T3b/E2E 强制项 |
| 处理逻辑 | ① 新增 L3 层级定义（无代码类 HTTP≥500 + 无 requestfailed + 无代码类 console error）；② 禁止模式清单新增"页面可达即通过"条目（"页面可达≠请求成功≠功能正确"）|
| 输出 | 断言分级章节新增 L3 强制项 + 禁止模式清单新增条目 |

#### RT-216-004: E2E 网络层事件订阅标准动作

| 项 | 内容 |
|:---|:-----|
| 前置条件 | E2E 测试章节（4.5 四轨贯通）存在 |
| 功能描述 | attach_network_listeners + assert_network_clean 代码模板入规范 |
| 处理逻辑 | ① attach_network_listeners：订阅 response（≥500 采集响应体摘要）/requestfailed/console 事件；② assert_network_clean：过滤 H 类环境提示与 I 类弃用警告后断言网络健康；③ T3b/E2E 断言模板强制调用两个函数 |
| 输出 | 网络层事件订阅标准动作章节 + 代码模板 |
| 错误处理 | 响应体读取异常时容错（try/except 采集空摘要）|

#### RT-216-005: 偶发缺陷多轮巡检策略

| 项 | 内容 |
|:---|:-----|
| 前置条件 | T3a 六步闭环工作流存在 |
| 功能描述 | 首轮 0 缺陷但有风险页（含模型/数据异步加载页）时执行 ≥3 轮快速巡检 |
| 处理逻辑 | ① 触发条件：首轮 0 代码类缺陷 + 存在 500 类风险页面；② 每轮独立输出错误计数，跨轮对比；③ 任一轮出现代码类 500 → 立即登记缺陷 |
| 输出 | 六步工作流步骤 2 新增多轮策略 |
| 错误处理 | 多轮巡检限定风险页子集，控制耗时 |

#### RT-216-006: 根因定位手段扩展（6→7 种）

| 项 | 内容 |
|:---|:-----|
| 前置条件 | 根因定位 6 种手段表存在 |
| 功能描述 | 新增"并发/时序复现"手段 |
| 处理逻辑 | 快速连续访问/多轮重复请求触发竞态（如响应序列化与 DB session 关闭竞态），比对单次稳定与多轮偶发差异 |
| 输出 | 根因定位表新增第 7 种手段 |

#### RT-216-007: 巡检输出物标准

| 项 | 内容 |
|:---|:-----|
| 前置条件 | T3a 六步闭环工作流步骤 6（报告更新）存在 |
| 功能描述 | 逐页问题表扩展字段标准 |
| 处理逻辑 | 逐页问题表新增：HTTP 状态码分布（200/4xx/5xx 计数）、网络失败清单（URL+原因）、console error 分类（代码类 D / 弃用 I）、环境类提示清单（H 类 + 依赖说明）、关联缺陷 ID |
| 输出 | 逐页问题表模板（测试执行证据标准）|

#### RT-216-008: 门禁明确化

| 项 | 内容 |
|:---|:-----|
| 前置条件 | T3 通过标准 + 测试矩阵通过标准存在 |
| 功能描述 | 网络层门禁明确化 |
| 处理逻辑 | T3 通过标准补充：代码类 HTTP≥500=0、requestfailed=0、代码类 console error=0；H 类环境提示允许遗留但必须登记环境遗留清单 |
| 输出 | T3 通过标准 + 测试矩阵通过标准更新 |

#### RT-216-009: 审计执行确定性加固

| 项 | 内容 |
|:---|:-----|
| 前置条件 | audit-agent 能力 3 检查点复查抽样表存在 |
| 功能描述 | 检查点复查以"验证命令"列为唯一依据逐条执行 |
| 处理逻辑 | ① 确保各阶段检查点验证命令列可复制粘贴运行（无占位符/无歧义）；② 审计时逐条复制验证命令到终端执行、记录实际输出、对比声称结果；③ 全流程审计报告追加"各阶段检查点逐条执行记录"章节 |
| 输出 | audit-agent 章节更新 + 全流程审计报告模板更新 |
| 错误处理 | 验证命令执行失败时记录实际错误输出，标记检查点未通过 |
