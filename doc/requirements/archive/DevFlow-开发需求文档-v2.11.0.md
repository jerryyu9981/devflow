## 3. 用户场景

### 3.1 主场景

| 场景编号 | US-001 | 审计师发布版本前审计 |
|:---------|:-------|:---------------------|
| **用户角色** | 审计师 / PM |
| **前置条件** | Step 5 全部完成，待发布版本已打 tag |
| **触发条件** | 审计师执行 audit-agent |
| **主流程** | ① 输入目标版本号 → ② 追溯链验证：Git log 提取 ID + 交叉比对 → ③ 产出物盘点：LS 6 阶段产出物 → ④ 检查点复查：重新执行验证命令 → ⑤ 生成审计报告 |
| **后置结果** | 审计报告输出至 `doc/audit/comprehensive/` |
| **异常场景** | 追溯链 ID 不匹配 → 输出警告不阻塞；产出物缺失 → 输出缺失清单；检查点命令失败 → 输出对比差异 |
| **边界场景** | 版本号格式错误 → 提示正确格式；无产出物目录 → 空输出报告；Git log 无可提取 ID → 降级为人工补充 |

### 3.2 异常场景

| 异常 | 行为 |
|:-----|:------|
| Git 仓库无 commit（新项目） | 输出"无追溯链数据"，跳过 ID 验证 |
| 产出目录不存在 | 标记为缺失，在报告中列明 |
| 验证命令执行超时 | 超时后标记为"未验证"，给出超时详情 |

## 5. 业务流程

### 5.1 audit-agent 主流程

```text
[审计师] 执行 audit-agent {version}
    │
    ├─ Phase 1：追溯链验证
    │    ├─ git log --oneline {version} → 提取 commit footer 中的 RT-ID/TD-ID
    │    ├─ 读取各阶段追溯矩阵（doc/requirements/ / doc/design/ / doc/development/）
    │    └─ 交叉比对 → 输出一致性报告
    │
    ├─ Phase 2：产出物盘点 + 检查点复查
    │    ├─ LS/Glob 列出 Step 0~5 产出目录 → 核对产出清单
    │    ├─ 读取 Release Checklist → 逐项重新执行验证命令
    │    └─ 对比命令输出与声称结果 → 输出对比报告
    │
    └─ Phase 3：报告生成
         ├─ 汇总 Phase 1~2 发现
         ├─ 内置风险归集检查
         └─ 输出标准 Markdown 审计报告
```

### 5.2 季度审计流程

```text
[PM] 执行 audit-agent --quarterly {YYYY-Qn}
    │
    ├─ 触发债务总表更新检查
    ├─ 回顾本季度所有已发布版本的审计记录
    └─ 输出季度审计汇总报告
```

## 6. 功能需求

### 6.1 V260-002 Phase 1：追溯链独立验证（BL-211-001，🔴 P0）

| 字段 | 内容 |
|:-----|:------|
| **描述** | AI 从 Git log 提取 commit 中 RT-ID/TD-ID 引用，与各阶段追溯矩阵交叉比对 |
| **输入** | 目标版本号（如 v2.11.0） |
| **处理** | ① `git log --oneline v2.11.0` 提取 commit footer 中的 ID → ② 读取 `DevFlow-需求追溯矩阵-v{version}.md` 和 `DevFlow-TD-ID追溯矩阵-v{version}.md` → ③ 交叉比对存在性 |
| **输出** | 追溯链一致性报告（Markdown） |
| **错误处理** | Git 命令失败 → 输出错误信息；ID 格式不符 → 容错跳过并警告 |

### 6.2 V260-002 Phase 2：产出物盘点 + 检查点复查（BL-211-002，🔴 P0）

| 字段 | 内容 |
|:-----|:------|
| **描述** | AI 执行 LS 核对各阶段产出物；重新执行 Release Checklist 验证命令 |
| **输入** | 阶段列表 + Release Checklist 检查项 |
| **处理** | ① 对每个阶段，LS 列出目标目录 → ② 比对该版本应产出文档清单 → ③ 读取 Release Checklist，逐项提取验证命令 → ④ 重新执行命令 → ⑤ 对比输出与 Checklist 中的声称结果 |
| **输出** | 产出物盘点报告 + 检查点复查对比报告 |
| **错误处理** | LS 目标目录不存在 → 标记缺失；命令执行超时 → 标记为"未验证" |

### 6.3 V260-002 Phase 3：审计报告生成（BL-211-003，🔴 P0）

| 字段 | 内容 |
|:-----|:------|
| **描述** | 汇总 Phase 1~2 发现，按标准格式生成审计报告 |
| **输入** | Phase 1 报告 + Phase 2 报告 |
| **处理** | ① 合并追溯链/产出物/检查点复查 3 个章节 → ② 内置风险归集检查（TD-026）→ ③ 写入 `doc/audit/comprehensive/DevFlow-全流程闭环审计报告-v{version}.md` |
| **输出** | 标准 Markdown 审计报告 |
| **错误处理** | 文件写入失败 → 输出错误信息 |

### 6.4 TD-010 季度审计机制（BL-211-004，🟡 P1）

| 字段 | 内容 |
|:-----|:------|
| **描述** | audit-agent 内置季度审计触发能力 |
| **输入** | 季度标识（如 2026-Q3） |
| **处理** | 遍历本季度所有已发布版本 → 对每个版本执行 Phase 1~3 → 汇总输出季度审计报告 |
| **输出** | 季度审计报告 |

### 6.5 TD-026 风险归集门禁强化（BL-211-005，🟡 P1）

| 字段 | 内容 |
|:-----|:------|
| **描述** | audit-agent 审计报告自动检查 P1+ 风险归集情况 |
| **处理** | 读取技术债务总表 → 检查是否有未归集的 P1+ 风险 → 在报告中单独列出 |
| **输出** | 审计报告中的风险归集检查章节 |

## 7. 非功能需求

| 需求 | 说明 | 适用项 |
|:-----|:------|:-------|
| **兼容性** | 向后完全兼容 v2.10.2，新增 skill 文件不影响现有流程 | 全部 |
| **性能** | 审计执行时间 ≤ 5 分钟（10 个 commit 以内的版本） | Phase 1~3 |
| **可靠性** | 可重复执行，同一版本多次审计结果一致 | 全部 |
| **可观测性** | audit-agent 执行过程中输出日志（进度 + 每步结果） | 全部 |

## 8. 数据需求

| 实体 | 字段 | 来源 | 说明 |
|:-----|:-----|:-----|:------|
| 版本号 | version string | 用户输入 / 季度参数 | 格式 v{major}.{minor}.{patch} |
| Git commit 记录 | hash, message, footer | `git log` 命令输出 | 提取 RT-ID/TD-ID |
| 追溯矩阵文件 | Markdown 表格 | `doc/requirements/` 等 | 读取 RT-ID 行 |
| 产出物清单 | 文件路径列表 | LS/Glob 输出 | 核对存在性 |
| Release Checklist | 验证命令集 | 全流程闭环审计报告 | 重新执行 |

## 9. 权限与安全需求

| 需求 | 说明 |
|:-----|:------|
| **只读操作** | audit-agent 仅执行只读操作（git log / LS / Read / Grep），不修改任何文件 |
| **审计结果写入** | 仅写入 `doc/audit/comprehensive/` 报告文件 |
