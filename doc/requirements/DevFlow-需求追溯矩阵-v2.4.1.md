## 1. 追溯矩阵概述

### 1.1 文档目的

本文档是 DevFlow v2.4.1 版本的需求追溯矩阵，建立从版本目标到业务流程的完整追溯链，确保每个需求都可追踪其来源（版本目标）和去向（用户故事、用户场景、业务流程），实现需求的全生命周期可追溯性。

### 1.2 追溯链结构

DevFlow v2.4.1 需求追溯链采用多层级追溯模型，与 v2.4.0 保持一致的追溯结构：

```
版本目标(GOAL) -> Backlog项(BL) -> 需求(RT) -> 验收标准(AC) -> 用户故事(US) -> 用户场景(USC) -> 业务流程(BP)
```

| 追溯层级 | ID 前缀 | 命名规则 | 说明 |
|---|---|---|---|
| 版本目标 | GOAL-{类别}{编号} | 如 GOAL-A1, GOAL-B1 | v2.4.1 版本的 4 个维度目标 |
| Backlog 项 | BL-2.4.1-{NNN} | 按本版本 Backlog 序号 | 对应本版本 Backlog 中的条目 |
| 需求追溯项 | RT-2.4.1-{NNN} | 按需求编号 | 核心追溯节点，关联 VR-ID |
| 验收标准 | AC-2.4.1-{RT编号}-{序号} | 如 AC-2.4.1-001-1 | 从开发需求文档的验收标准章节提取 |
| 用户故事 | US-2.4.1-{NNN} | 按需求对应编号 | 对应用户需求说明书中的用户故事 |
| 用户场景 | USC-2.4.1-{NNN} | 按场景编号 | 对应用户需求说明书中的用户场景 |
| 业务流程 | BP-2.4.1-{NNN} | 按流程编号 | 对应用户需求说明书中的业务流程 |

### 1.3 强制追溯规则

| 规则编号 | 规则名称 | 规则描述 |
|---|---|---|
| TR-001 | P0/P1 全追溯 | 所有 P0 和 P1 需求必须 100% 建立完整追溯链（从版本目标到业务流程） |
| TR-002 | 来源可溯 | 每个需求必须关联至少一个版本目标，说明该需求对版本目标的贡献 |
| TR-003 | 验收可验 | 每个需求必须至少有 1 条可验证的验收标准 |
| TR-004 | 故事映射 | 每个需求必须对应至少 1 个用户故事 |
| TR-005 | 场景覆盖 | P0 需求必须对应至少 1 个用户场景 |
