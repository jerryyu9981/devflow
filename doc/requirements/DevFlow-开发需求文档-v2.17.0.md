## 6. 业务流程与业务规则

### 流程 P1：原型设计 IN 衔接（外部工具场景）

```
外部原型(Figma) → Step 2 导入 → 产出 Figma设计交付说明(链接+组件引用规则)
    → 生成 prototype/index.html → 建立 RT-ID↔原型页面映射表 → prototype-coverage 检查
```

### 流程 P2：原型设计 IN 衔接（独立设计场景）

```
独立原型(Step 1 前完成) → Step 1 作为需求输入(UIUX需求说明引用原型)
    → Step 2 正式收编(验证覆盖全部需求、补充遗漏页面) → 同 P1 后续流程
```

### 流程 P3：原型设计 IN 衔接（已有原型接入场景）

```
已有原型(无追溯) → Step 2 逆向补建追溯(原型页面→RT-ID 映射)
    → prototype-coverage 识别覆盖缺口 → 缺口页面补充设计
```

### 流程 P4：原型设计 OUT 衔接

```
Step 2→3 移交：原型文件清单 + DT-ID 映射 + 交互状态清单(空态/错误态/加载态/成功态)
Step 3 编码：对照原型实现，prototype-coverage ≥ 95%
Step 4 测试：E2E 用例引用原型状态作为断言基线
```

### 业务规则

| 规则 ID | 规则内容 | 关联需求 |
|:-------:|:---------|:--------:|
| BR-217-001 | 全栈项目 prototype/index.html 为强制产出，纯后端项目不适用 | RT-217-003 |
| BR-217-002 | 全栈项目 T3a 全页面巡检为强制项，纯后端项目以服务间集成巡检替代 | RT-217-002 |
| BR-217-003 | 原型 IN 衔接必须建立 RT-ID↔原型页面映射，无映射不得进入下游 | RT-217-001 |
| BR-217-004 | 原型 OUT 移交必须包含原型文件清单+DT-ID 映射+交互状态清单 | RT-217-001 |
