## 2. 备份类型定义

### 2.1 类型概述

| 备份类型 | 定义 | 优势 | 劣势 | 适用场景 |
|---------|------|------|------|---------|
| 全量备份 | 备份所有选定数据的完整副本 | 恢复简单直接，只需一份备份 | 耗时长、存储空间大 | 周末/低峰期定期执行，新系统初始化 |
| 增量备份 | 仅备份自上次备份以来发生变化的数据 | 备份速度快、占用空间小 | 恢复复杂，需依次应用增量链 | 日常高频备份，数据变更频繁的系统 |
| 差异备份 | 备份自上次全量备份以来发生变化的数据 | 恢复比增量简单（只需全量+最近差异），速度适中 | 存储空间比增量大 | 需要快速恢复且变更适中的系统 |

### 2.2 类型选择决策

```
数据变更频率高 + 存储成本敏感 → 增量备份
数据变更频率低 + 恢复速度优先 → 差异备份
恢复简单性优先 + 存储充足   → 全量备份
生产环境推荐组合             → 全量（周）+ 增量（日）
```

### 2.3 项目备份类型分配

| 数据类型 | 备份类型 | 备份工具 | 执行方式 | 说明 |
|---------|---------|---------|---------|------|
| 源代码 | Git 仓库（增量） | `git push --mirror` | 自动（post-push hook） | 见 code-version-backup-management |
| 数据库 | 全量 + 增量 | `{数据库原生工具}` | 定时任务 | {具体工具名，如 mysqldump/pg_dump} |
| 配置文件 | 全量 | `git archive` / 脚本 | 每次变更时 | 配置变更即触发 |
| 用户上传文件 | 增量 | `rsync` / `{云存储API}` | 每日 | 对象存储或 NAS |
| 日志数据 | 增量 | ELK 快照 / 文件同步 | 每日 | 保留策略见日志规范 |

## 3. 备份频率策略矩阵

### 3.1 频率矩阵

根据数据类型、重要性和变更频率，制定备份频率策略。

| 数据类型 | 数据重要性 | 变更频率 | 全量频率 | 增量频率 | 备份窗口 |
|---------|:---------:|:-------:|:-------:|:-------:|---------|
| 关系数据库 | P0 关键 | 高 | 每周 {日} | 每日 | 02:00-04:00 |
| NoSQL 数据库 | P0 关键 | 高 | 每周 {日} | 每日 | 02:00-06:00 |
| 消息队列数据 | P1 重要 | 极高 | 每周 {日} | 每小时 | 全天 |
| 缓存数据 | P2 一般 | 极高 | 不全量 | 不备份（可重建） | - |
| 用户文件 | P1 重要 | 中 | 每月 | 每日 | 03:00-05:00 |
| 配置文件 | P0 关键 | 低 | 每次变更时 | - | 变更后10分钟内 |
| 源代码 | P0 关键 | 高 | Git 原生管理 | 实时推送 | - |
| 系统日志 | P2 一般 | 极高 | 每月归档 | 每日 | 04:00-05:00 |

### 3.2 备份时间窗口规则

1. **避开业务高峰**：所有备份操作应在业务低峰期执行（{具体时段}）
2. **避免并发**：不同数据类型的备份任务应错开执行，避免资源争抢
3. **超时处理**：备份任务超过预计时间 150% 时自动告警
4. **窗口冲突**：当备份窗口与系统维护窗口冲突时，备份优先

## 4. 备份保留策略

### 4.1 保留周期

| 备份类型 | 保留周期 | 清理规则 | 归档规则 | 说明 |
|---------|---------|---------|---------|------|
| 每日增量 | 7 天 | 超过 7 天自动删除 | 不归档 | 满足一周内的快速恢复需求 |
| 每周全量 | 4 周 | 超过 4 周的增量链删除 | - | 覆盖一个月的恢复需求 |
| 每月全量 | 12 个月 | 超过 12 个月自动清理 | 超过 12 个月的转入冷存储 | 满足年度审计和合规需求 |
| 每年全量 | 7 年 | 超过 7 年的需合规审批后删除 | 转入合规归档存储 | 满足法律法规和行业合规要求 |
| 版本发布归档 | 永久 | 不删除 | 永久归档 | 每个发布版本的源码快照 |

### 4.2 清理规则

| 规则编号 | 规则名称 | 执行条件 | 执行动作 | 执行频率 |
|---------|---------|---------|---------|---------|
| CLR-001 | 增量过期清理 | 增量备份超过保留周期 | 删除过期增量备份文件 | 每日 05:00 |
| CLR-002 | 全量过期清理 | 全量备份超过保留周期 | 删除过期全量备份及其关联增量链 | 每周 {日} 05:00 |
| CLR-003 | 归档转储 | 全量备份超过归档阈值 | 转入冷存储/合规归档存储 | 每月 1 日 |
| CLR-004 | 失败备份清理 | 备份状态为失败且超过 3 天 | 删除失败的备份文件 | 每日 06:00 |

### 4.3 归档规则

| 归档级别 | 存储类型 | 存储位置 | 访问延迟 | 成本 | 适用数据 |
|---------|---------|---------|---------|------|---------|
| 热存储 | 本地 SSD / 高性能云盘 | {主存储位置} | < 1秒 | 高 | 最近 7 天备份 |
| 温存储 | 标准云存储 / NAS | {温存储位置} | < 10秒 | 中 | 7天 - 12个月备份 |
| 冷存储 | 归档云存储 / 磁带 | {冷存储位置} | < 4小时 | 低 | 12个月 - 7年备份 |
| 合规存储 | 不可变存储 | {合规存储位置} | < 24小时 | 极低 | 超过 7年的合规归档 |

## 5. 备份存储选择决策树

### 5.1 存储架构选型

```
开始
 ├── 是否需要跨地域容灾？
 │    ├── 是 → 多地域/混合架构
 │    │        ├── 主地域 + 从地域实时同步
 │    │        └── 冷备地域异步同步
 │    └── 否 → 继续
 ├── 数据量是否超过 {阈值} TB？
 │    ├── 是 → 云端存储优先
 │    │        ├── 对象存储（S3/OSS）
 │    │        └── 云数据库备份服务
 │    └── 否 → 继续
 ├── 是否有合规/数据主权要求？
 │    ├── 是 → 本地存储 + 合规云存储
 │    └── 否 → 继续
 └── 默认 → 混合架构
              ├── 热数据：本地高性能存储
              ├── 温数据：NAS / 标准云存储
              └── 冷数据：对象存储归档
```

### 5.2 存储方案对比

| 存储方案 | 可靠性 | 成本 | 恢复速度 | 运维复杂度 | 推荐场景 |
|---------|:-----:|:---:|:-------:|:--------:|---------|
| 纯本地存储 | 中 | 低 | 快 | 中 | 数据量小、无合规要求 |
| 纯云端存储 | 高 | 中 | 中 | 低 | 数据量适中、快速扩展 |
| 混合存储 | 高 | 中高 | 快-中 | 高 | 生产环境推荐方案 |
| 多地域存储 | 极高 | 高 | 中-慢 | 极高 | 金融/医疗等高合规要求 |

| 数据类型 | 存储方案 | 主存储位置 | 备存储位置 | 存储容量规划 | 增长预估 |

## 6. 备份加密和访问控制规范

### 6.1 加密策略

| 加密阶段 | 加密方式 | 算法 | 密钥管理 | 说明 |
|---------|---------|------|---------|------|
| 传输加密 | TLS 1.2+ | AES-256-GCM | 证书管理 | 备份数据在传输过程中必须加密 |
| 存储加密 | 静态加密 | AES-256 | KMS 密钥管理服务 | 备份文件存储时必须加密 |
| 密钥轮换 | 定期轮换 | - | 每 {90天} 轮换一次 | 密钥轮换时需重新加密热备份数据 |

### 6.2 访问控制

| 权限级别 | 角色权限 | 操作范围 | 审批要求 |
|---------|---------|---------|---------|
| 只读 | 审计人员 | 查看备份列表和元信息 | 无需审批 |
| 恢复 | 运维工程师 | 从备份恢复数据 | 需技术负责人审批 |
| 删除 | 系统管理员 | 删除过期备份 | 需总指挥审批 + 双人确认 |
| 密钥管理 | 安全管理员 | 管理加密密钥 | 需安全负责人审批 |

### 6.3 安全检查项

- 备份存储账户使用最小权限原则
- 备份传输通道使用专线或 VPN
- 备份文件设置不可变锁（Immutable Lock），防止勒索软件篡改
- 定期审计备份访问日志，异常访问需告警

## 7. 备份监控和告警规则

### 7.1 监控指标

| 指标 | 采集方式 | 正常范围 | 告警阈值 | 说明 |
|------|---------|---------|---------|------|
| 备份成功率 | 备份任务状态 | 100% | < 100% 连续 2 次 | 备份任务执行是否成功 |
| 备份耗时 | 任务执行时间 | <= 预计时间 | > 预计时间 150% | 备份执行效率 |
| 备份大小 | 文件大小统计 | 符合预期 | 偏差 > 30% | 异常增长可能预示数据问题 |
| 备份存储利用率 | 存储空间监控 | < 80% | > 80% 预警 / > 90% 严重 | 存储空间充足性 |
| 恢复测试成功率 | 定期恢复测试 | 100% | < 100% | 备份数据的可恢复性 |
| 备份延迟 | 时间戳对比 | < 1分钟 | > 10分钟 | 备份数据的新鲜度 |

### 7.2 告警规则

| 告警编号 | 告警名称 | 触发条件 | 告警级别 | 通知方式 | 响应时限 |
|---------|---------|---------|:-------:|---------|---------|
| ALT-001 | 备份任务失败 | 备份执行返回非零退出码 | 严重 | 电话 + 短信 + 邮件 | 15分钟 |
| ALT-002 | 备份超时 | 执行时间超过预计 150% | 警告 | 短信 + 邮件 | 1小时 |
| ALT-003 | 备份异常增长 | 备份大小偏差 > 50% | 警告 | 邮件 | 4小时 |
| ALT-004 | 存储空间不足 | 利用率 > 85% | 严重 | 电话 + 短信 | 30分钟 |
| ALT-005 | 备份校验失败 | 完整性校验未通过 | 严重 | 电话 + 短信 + 邮件 | 15分钟 |
| ALT-006 | 连续备份失败 | 连续 3 次备份失败 | 严重 | 电话 + 短信 + 邮件 | 立即 |

### 7.3 监控面板

建议在运维监控平台（如 Grafana）中创建备份专用 Dashboard，包含以下面板：

- 备份任务状态总览（最近 7 天）
- 备份存储空间趋势（最近 30 天）
- 备份成功率趋势
- 各数据类型的备份时间线

## 8. 与 DevFlow 的集成

### 8.1 Git 原生备份策略

代码级别的备份由 DevFlow 的 `code-version-backup-management` 技能统一管理，采用 Git 原生增量备份替代文件级全量拷贝：

| 备份类型 | DevFlow 策略 | 说明 |
|---------|------------|------|
| 日常备份 | `git push --mirror` 远程备份仓库 | 每次推送后自动执行（post-push hook） |
| 每周快照 | `git bundle create` 创建 bundle 文件 | 保留 4 周 |
| 发布归档 | `git archive` 打包源码 | 每版本永久保留 |
| 远程仓库配置 | `.devflow/config.json` 中 `remote.backup` | 配置备份远程仓库地址 |

### 8.2 配置集成

在 `.devflow/config.json` 的 `backup` 字段中扩展非代码数据的备份配置：

```json
{
  "project": "{项目名}",
  "backup": {
    "type": "git-mirror",
    "extended": {
      "database": {
        "tool": "{备份工具}",
        "schedule": "daily",
        "retention": {
          "daily": 7,
          "weekly": 4,
          "monthly": 12
        }
      },
      "files": {
        "schedule": "daily",
        "retention": {
          "daily": 7,
          "weekly": 4
        }
      }
    }
  }
}
```

### 8.3 CI/CD 集成

备份任务通过 `cicd-pipeline-management` 中定义的流水线自动执行：

| 集成点 | 执行内容 | 触发条件 |
|-------|---------|---------|
| backup-daily | 执行每日增量备份任务 | 每日定时触发 |
| backup-weekly | 执行每周全量备份任务 | 每周 {日} 定时触发 |
| backup-verify | 执行备份完整性校验 | 每次备份完成后 |
| backup-cleanup | 执行过期备份清理 | 每日备份完成后 |
