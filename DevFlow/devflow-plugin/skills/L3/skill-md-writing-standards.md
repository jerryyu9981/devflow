# Skill MD Writing Standards（SKILL.md 编写规范）

## 定位

本技能是 DevFlow v2.4.0 技能文件的格式与结构规范，基于对现有 22 个技能文件的格式差异分析制定。它为全部 L1/L2/L3/Orchestrator 层级技能文件提供统一的编写标准，确保技能文件在标题、章节、表格、代码块、列表和编码等维度保持一致。

本规范不定义技能的业务内容，只约束技能文件的结构和格式。

## 触发条件

当以下场景发生时，应参考本规范：

- 创建新的 DevFlow 技能文件
- 修改或重构现有技能文件的格式
- 审查技能文件是否符合规范
- 运行格式检查脚本排查格式问题
- 统一多个技能文件的格式风格

## 适用范围

| 层级 | 目录 | 说明 |
|---|---|---|
| L1 | `skills/L1/` | 编排层技能（3 个） |
| L2 | `skills/L2/` | 阶段执行层技能（6 个） |
| L3 | `skills/L3/` | 专项参考层技能（10+ 个） |
| Orchestrator | `devflow-init/`、`devflow-phase-manager/`、`devflow-project-config/` | 编排器技能（3 个） |

## 文件结构规范

### 标准章节

全部技能文件必须包含以下章节：

| 序号 | 章节 | 标题格式 | 是否必须 |
|---|---|---|---|
| 1 | 一级标题 | `# {英文名}（{中文名}）` | 必须 |
| 2 | 定位 | `## 定位` | 必须 |
| 3 | 触发条件 | `## 触发条件` | 必须 |
| 4 | 核心章节 | 按技能类型不同（见下文） | 必须 |
| 5 | 反模式 | `## 反模式` | 必须 |
| 6 | 强制规则 / 完成标准 | 按技能类型不同 | L2 必须有强制规则 + 完成标准；其他按需 |
| 7 | 技能速查映射 | `## 技能速查` / `## 编码技能速查` | L2 必须有；其他按需 |
| 8 | 变更记录 | `## 变更记录` | 必须 |

### 各层级核心章节定义

| 层级 | 核心章节内容 |
|---|---|
| L1 | 编排逻辑、触发规则 |
| L2 | 规范矩阵、阶段位置、强制规则、完成标准、技能速查 |
| L3 | 规范内容、流程、检查清单 |
| Orchestrator | 编排流程、配置管理 |

## 格式规范

### 标题规范

- 一级标题 `#`：必须存在，格式为 `# {英文名}（{中文名}）`，中英文之间用全角括号
- 二级标题 `##`：使用中文命名，如 `## 定位`、`## 触发条件`、`## 反模式`
- 不使用三级以上标题作为章节开头；四级标题 `####` 可在表格内作为子项使用
- 标题前后各空一行（文件开头除外）

### 表格规范

- 列分隔符：`|---|---|`（两边各 3 个短横线）
- 表头：使用中文，如 `| 字段 | 内容 |` 或 `| 项目 | 说明 |`
- 表格前必须有文字引导（不能直接以表格开头一个章节）
- 表格后如果还有内容，空一行

示例：

```markdown
以下是检查矩阵：

| 检查类别 | 必须检查内容 | 通过标准 |
|---|---|---|
| 语法检查 | 语言解析、语法错误 | 无语法错误 |
```

### 代码块规范

- 代码块必须标注语言类型（如 ` ```text `、` ```powershell `、` ```bash `、` ```json `、` ```markdown `）
- 代码块前后各空一行

示例：

```text
Step 0 → Step 1 → Step 2
→ Step 3 开发
→ Step 4 → Step 5
```

### 列表规范

- 无序列表使用 `-` 作为标记
- 有序列表使用数字 `1.`
- 列表嵌套不超过 2 层
- 列表项之间不留空行（除非需要段落分隔）

### 文字规范

- 全文使用中文（技术术语如 API、CLI、JSON 可保留英文）
- 句子简洁，避免超过 100 字的长句
- 段落之间空一行
- 使用全角标点（句号、逗号、冒号等），英文术语前后可使用半角

### 编码规范

- 文件编码：UTF-8（无 BOM）
- 行尾：LF（统一 Unix 风格）
  - 例外：PowerShell 脚本文件（`.ps1`）可使用 CRLF
- 无尾随空格
- 文件末尾保留一个空行

### Front Matter 规范

技能文件开头应包含 YAML Front Matter（用 `---` 包裹），格式如下：

```yaml
---
name: "{技能英文名}"
description: "{技能描述，一句话说明作用和触发场景}"
---
```

- `name` 字段与文件名一致（不含 `.md` 后缀）
- `description` 字段用于 LLM 理解技能用途，应简洁明确
- Front Matter 与一级标题之间空一行

## 术语表

| 术语 | 定义 |
|---|---|
| SKILL.md | DevFlow 技能文件标准格式，采用 Markdown 编写 |
| L1 | 编排层技能，负责流程编排和触发规则（如 project-development-workflow） |
| L2 | 阶段执行层技能，负责特定开发阶段的管控（如 coding-stage-execution） |
| L3 | 专项参考层技能，负责特定领域的规范和检查清单（如 project-coding-conventions） |
| Orchestrator | 编排器，负责项目初始化、阶段管理和配置（如 devflow-init） |
| 编译层模式 | L2 内联 L3 速查表，使运行时深度始终为 2 层，避免深层嵌套调用 |
| Front Matter | 技能文件开头的 YAML 元数据块，包含 name 和 description 字段 |
| 规范矩阵 | L2 技能中的表格结构，列出阶段执行的各类别、检查内容和通过标准 |

## 已知格式问题和修复计划

基于对现有 22 个技能文件的分析，以下是已识别的格式不一致问题及修复优先级：

| 编号 | 问题描述 | 影响范围 | 优先级 | 修复计划 |
|---|---|---|---|---|
| FMT-001 | 部分 L3 技能文件缺少 `## 定位` 章节，直接以 Front Matter 后的 `## 触发条件` 或其他章节开头 | L3（3 个文件） | P1 | 补充 `## 定位` 章节，说明技能用途和在流程中的位置 |
| FMT-002 | 部分 L3 技能文件缺少 `## 反模式` 章节 | L3（4 个文件） | P1 | 补充 `## 反模式` 章节，列出使用时应避免的错误做法 |
| FMT-003 | L1 技能文件中英文混用严重，部分章节标题使用英文（如 `## Overview`、`## Usage`） | L1（全部 3 个文件） | P0 | 统一将章节标题改为中文，技术术语可保留英文 |
| FMT-004 | 部分 L2 技能文件的 `## 变更记录` 章节缺失 | L2（2 个文件） | P1 | 补充 `## 变更记录` 章节和初始版本记录 |
| FMT-005 | 表格列分隔符不一致：部分使用 `|---|---|`（3 短横线），部分使用 `|------|------|`（6 短横线） | 全层级（8 个文件） | P2 | 统一为 `|---|---|`（两边各 3 个短横线） |
| FMT-006 | 代码块未标注语言类型，使用裸 ` ``` ` 而非 ` ```text ` 或 ` ```bash ` | 全层级（5 个文件） | P2 | 为所有代码块添加正确的语言类型标注 |
| FMT-007 | 部分技能文件缺少 YAML Front Matter | L3（2 个文件） | P1 | 补充标准格式的 Front Matter（name + description） |
| FMT-008 | 行尾不一致：部分文件使用 CRLF，部分使用 LF | 全层级（约 6 个文件） | P2 | 统一为 LF（PowerShell 脚本除外） |
| FMT-009 | 部分文件存在尾随空格 | 全层级（约 10 个文件） | P3 | 批量清除尾随空格 |
| FMT-010 | L2 技能文件的技能速查表格式不统一：有的用纯文本列表，有的用表格 | L2（4 个文件） | P2 | 统一为表格格式的技能速查映射 |
| FMT-011 | 部分 L3 技能文件缺少一级标题，只有 Front Matter | L3（1 个文件） | P0 | 补充标准格式的一级标题 `# {英文名}（{中文名}）` |

修复执行顺序：P0 > P1 > P2 > P3。建议使用 `scripts/check-skill-format.ps1` 脚本进行批量检查。
