# Prototype Coverage

## When To Use

本技能用于在 Step 2（架构与设计阶段）对前端原型设计进行**系统化覆盖检查**，防止以下问题流入开发阶段：

- 遗漏了某些该有原型但未设计的页面或弹窗
- 原型只覆盖"正常态"，缺少空态、错误态、加载态等关键状态
- 页面间跳转存在流程断点（点了没反应、去了不该去的地方）
- 需求中的用户故事与原型文件之间没有可追溯的映射关系
- 设计阶段未预埋测试关注点，导致测试阶段频繁返工

**触发场景**：
- 用户要求"检查原型是否有遗漏"
- 设计阶段需要"原型覆盖率检查"
- 需要"原型走查"或"用例场景演练"
- 需要建立"前端页面清单"或"交互状态覆盖检查表"
- 设计评审前需要系统化的原型验证

## Core Workflow

执行以下七个步骤，按顺序进行，不得跳过：

### Step 1: 建立前端页面清单（Page Inventory）

从需求文档中系统提取所有涉及用户界面的需求项，建立页面清单。

**执行动作**：
1. 读取 Step 1 需求文档（用户故事、用例规约）
2. 识别每个涉及用户界面的需求项
3. 为每个页面/弹窗/抽屉分配唯一ID（PG-/MD-/DW- 编号）
4. 记录页面名称、路由、用户角色、对应需求ID、优先级
5. 建立页面间的入口-出口关系图

**通过标准**：
- 所有 P0/P1 涉及界面的需求项均有对应页面记录
- 无孤立页面（每个页面至少被一个需求引用）
- 页面ID按 PG-{三位数字}（页面）、MD-{三位数字}（弹窗）、DW-{三位数字}（抽屉）规则编号

**强制产出**：`{项目名}-前端页面清单-v{版本号}.md`

---

### Step 2: 执行交互状态覆盖检查

检查每个有原型的页面是否覆盖了关键交互状态。

**必须覆盖的状态**：

| 状态类型 | 定义 | P0 要求 | P1 要求 |
|---|---|---|---|
| **空态（Empty State）** | 页面/列表无数据时的展示 | 强制 | 建议 |
| **加载态（Loading State）** | 数据正在加载时的展示 | 强制 | 建议 |
| **错误态（Error State）** | 加载失败或操作失败时的展示 | 强制 | 强制 |
| **成功态（Success State）** | 操作成功后的展示 | 强制 | 建议 |
| **边界态（Edge Case）** | 极端数据量或极端条件下的展示 | 建议 | 可选 |
| **权限态（Permission State）** | 无权限时的展示 | 涉及权限时强制 | 涉及权限时强制 |

**执行动作**：
1. 遍历页面清单中的所有 P0 页面
2. 检查每个页面原型是否包含上述六种状态
3. 对缺失状态记录具体原因和修复计划
4. 计算状态覆盖率

**通过标准**：
- P0 页面：空态、加载态、错误态、成功态 四种状态必须全部覆盖
- P1 页面：至少覆盖空态、错误态 两种状态
- 涉及权限的页面：必须覆盖权限态

**强制产出**：`{项目名}-前端原型覆盖检查表-v{版本号}.md`

---

### Step 3: 执行原型走查（Prototype Walkthrough）

以用户角色视角，在原型中模拟真实操作，暴露流程断点。

**执行动作**：
1. 按用户角色分组（管理员、普通用户、访客等）
2. 每个角色选择 3-5 条最高频的核心用户路径
3. 从入口页面开始，一步一步在原型中模拟点击/操作
4. 记录每一步的预期结果 vs 实际原型表现
5. 标注断点："不知道该点哪里"、"点完后不知道会去哪"、"去了不该去的地方"

**走查记录必须包含**：
- 走查路径名称和用户角色
- 每一步的"当前页面 → 操作 → 预期结果 → 原型表现 → 结论"
- 断点严重度（严重/中等/轻微）
- 修复计划和责任人

**通过标准**：
- 所有 P0 用户路径走查通过（无严重断点）
- P1 路径可以有轻微断点，但必须有修复计划
- 严重断点：导致用户无法完成核心目标的流程中断

**强制产出**：`{项目名}-原型走查记录-v{版本号}.md`

---

### Step 4: 执行用例场景演练（Scenario-Based Validation）

基于需求文档中的用例规约，在原型中验证基本流程和所有异常分支。

**执行动作**：
1. 从需求文档提取所有 P0 用例规约
2. 每个用例在原型中完整演练基本流程
3. 逐个验证每个异常分支
4. 验证前置条件（如"已登录"、"购物车有商品"）
5. 确认后置状态（如"订单状态=已支付"、"库存-1"）

**演练报告必须包含**：
- 用例ID、需求ID、优先级、主要参与者
- 前置条件检查表
- 基本流程演练步骤表
- 异常分支演练表（分支ID、触发条件、预期行为、原型表现、结论）
- 后置状态确认表
- 整体结论和修复项

**通过标准**：
- P0 用例：基本流程 100% 通过，异常分支覆盖率 >= 80%
- P1 用例：基本流程 100% 通过，异常分支覆盖率 >= 50%
- 任何"不通过"项必须在设计阶段内修复并重新演练

**强制产出**：`{项目名}-用例场景演练报告-v{版本号}.md`

---

### Step 5: 执行元素级交互标注（可选，P0 页面强制）

对 P0 页面中每个可交互元素进行详细行为标注。

**必须标注的属性**：
- **触发事件**：click / hover / focus / blur / change / submit
- **前置条件**：什么情况下元素可用/不可用
- **条件判断**：触发后系统做什么判断
- **成功路径**：正常情况下的走向
- **错误处理**：异常情况下的反馈
- **边界限制**：长度、大小、频率等限制
- **加载状态**：操作进行中的展示
- **权限控制**：无权限时的展示

**强制要求**：
- P0 页面中所有**主操作按钮**必须有完整交互标注
- P0 页面中所有**表单输入框**必须有校验规则标注
- P1 页面中涉及**资金/数据安全**的操作必须有错误处理标注

**强制产出**：`{项目名}-元素级交互标注-v{版本号}.md`

---

### Step 6: 执行设计-测试预映射

从设计文档中提取测试关注点，为后续测试用例设计提供结构化输入。

**执行动作**：
1. 从页面清单、状态检查表、走查记录、场景演练报告中提取测试关注点
2. 按功能测试 / 性能测试 / 安全测试 / 兼容性测试 / 并发测试 等分类
3. 标注优先级和预估测试方法
4. 提交给测试代表审阅并签字确认

**预映射表必须包含**：
- 需求ID、页面ID、测试类型、测试关注点、优先级、预估测试方法

**通过标准**：
- 所有 P0 需求项均有至少一个测试关注点
- 测试代表在设计评审前签字确认

**强制产出**：`{项目名}-设计-测试预映射表-v{版本号}.md`

---

### Step 7: 输出覆盖检查报告

汇总以上所有检查的结果，形成最终报告。

**报告必须包含**：
1. 检查概览（页面总数、已覆盖数、覆盖率、状态覆盖率、走查路径数、用例数）
2. 问题清单（按严重度排序：严重/中等/轻微）
3. 修复计划（责任人、截止时间）
4. 风险评估（哪些遗漏可能流入开发阶段）
5. 是否允许进入设计评审的结论

**通过标准（全部满足方可进入设计评审）**：
- [ ] 前端页面清单已建立且 P0 页面映射率 100%
- [ ] P0 页面原型覆盖率 100%
- [ ] P0 页面四种交互状态全部覆盖
- [ ] 所有 P0 用户路径走查通过（无严重断点）
- [ ] P0 用例基本流程 100% 通过，异常分支 >= 80%
- [ ] 设计-测试预映射表已提交并获测试代表签字

## Integration With DevFlow

### Step 2 设计阶段集成

当本技能在 Step 2 设计阶段被调用时：
- 以 `design-stage-execution` 为阶段控制器
- 本技能只负责原型覆盖检查这一专项领域
- 不替代设计评审或需求-架构审计
- 发现的 P0/P1 设计缺口必须在 Step 2 内修复，更新相关设计文档和追溯矩阵后重新检查

### 协作技能

| 场景 | 应调用技能 |
|---|---|
| 需要创建/修改原型 | `frontend-design`、`prototyping`、`ui-ux-pro-max` |
| 需要 Figma 设计稿转代码 | `figma`、`figma-integration` |
| 走查发现交互问题 | `frontend-design`（修改）、`dogfood`（复现） |
| 用例场景演练 | `test-driven-development`、`e2e-test-gen` |
| 设计-测试预映射 | `testing-stage-execution` |

## Example Invocation

### 示例 1: 执行完整的原型覆盖检查

用户指令："请检查当前项目的前端原型覆盖率"

执行流程：
1. 读取当前项目的需求文档和现有原型文件
2. 执行 Step 1-7 的完整检查流程
3. 输出覆盖检查报告，指出遗漏页面、缺失状态、流程断点
4. 给出修复建议和优先级排序

### 示例 2: 仅执行原型走查

用户指令："对登录 → 首页 → 下单这条路径做原型走查"

执行流程：
1. 读取指定路径涉及的所有页面原型
2. 按用户角色模拟操作，记录每一步的预期 vs 实际
3. 标注断点并输出走查记录
4. 给出修复建议

### 示例 3: 建立前端页面清单

用户指令："从需求文档提取所有页面，建立页面清单"

执行流程：
1. 读取需求文档中的用户故事和用例规约
2. 识别所有涉及用户界面的需求项
3. 生成带唯一ID的页面清单
4. 建立入口-出口关系图
5. 输出页面清单文档
