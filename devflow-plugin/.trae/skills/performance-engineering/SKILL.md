# 性能工程

## 定位

本技能定义项目性能工程的全流程方法论，从性能需求定义到容量规划，覆盖性能生命周期各阶段。它是性能领域的专项参考技能，被 `coding-stage-execution` 和 `testing-stage-execution` 在编码和测试阶段引用。

当前性能领域覆盖已从 ★★★★☆ 提升至 ★★★★★（v2.5.0）。

## 触发条件

当以下情况时调用本技能：
- 需要定义性能需求、SLA/SLO 或性能验收标准
- 需要建立性能测试基准
- 需要分析性能瓶颈（前端/后端/数据库/缓存）
- 需要制定性能优化方案
- 需要进行容量规划或资源评估
- 需要在代码审查或测试阶段进行性能相关检查

## 一、性能需求定义

### 1.1 性能指标体系

| 指标类型 | 指标名称 | 说明 | 典型目标值 |
|---------|---------|------|-----------|
| 响应时间 | P50（中位数） | 50%请求的响应时间 | < 200ms |
| 响应时间 | P95 | 95%请求的响应时间 | < 500ms |
| 响应时间 | P99 | 99%请求的响应时间 | < 1000ms |
| 吞吐量 | RPS（每秒请求数） | 系统单位时间处理能力 | 视业务而定 |
| 并发数 | 并发用户/连接数 | 同时活跃的请求数 | 视业务而定 |
| 资源使用 | CPU/内存/磁盘/网络 | 资源消耗占比 | CPU < 80%，内存 < 70% |
| 错误率 | Error Rate | 错误请求占比 | < 0.1% |
| 可用性 | Availability | 服务可用时间占比 | ≥ 99.9% |

### 1.2 性能需求模板

定义性能需求时，必须包含以下要素：

```markdown
### 性能需求：{功能名称}

| 要素 | 描述 |
|------|------|
| **场景** | 描述性能要求的业务场景 |
| **指标** | P50 / P95 / P99 / 吞吐量 / 并发数 |
| **目标值** | 量化目标（如 P50 < 200ms） |
| **当前基线** | 当前实际值（如已有） |
| **测试环境** | 测试环境配置（CPU/内存/网络） |
| **数据量** | 测试数据规模 |
| **验收条件** | 通过/不通过判定标准 |
```

### 1.3 SLA/SLO 定义规范

- **SLA（服务等级协议）**：对外承诺的性能保障，违约有商业后果
- **SLO（服务等级目标）**：内部性能目标，用于容量规划和告警设置
- **SLI（服务等级指标）**：衡量SLO的具体指标（如请求延迟、错误率）
- **错误预算（Error Budget）**：SLO允许的不可用时间，用于平衡可靠性和发布速度

## 二、性能测试基准建立

### 2.1 基准测试流程

```
基准测试（单用户） → 负载测试（预期并发） → 压力测试（极限） → 稳定性测试（持续运行）
```

| 阶段 | 目的 | 并发策略 | 持续时间 | 关注指标 |
|------|------|---------|---------|---------|
| 基准测试 | 建立单请求性能基线 | 单用户 | 5分钟 | P50/P95/P99 |
| 负载测试 | 验证预期负载下性能 | 渐增至目标并发 | 15-30分钟 | 响应时间、吞吐量、错误率 |
| 压力测试 | 发现系统极限 | 超过预期并发至失败 | 15-30分钟 | 最大吞吐量、崩溃点 |
| 稳定性测试 | 验证长时间运行稳定性 | 目标并发 | 1-24小时 | 内存泄漏、响应时间漂移 |

### 2.2 基线建立方法

首个版本在生产环境运行压测 3 次取中位数作为基线。后续版本对比基线判断性能退化或改进。

### 2.3 推荐工具

| 工具 | 特点 | 适用场景 |
|------|------|---------|
| k6 | 脚本化压测，支持JS | 通用后端压测 |
| Locust | Python编写，分布式支持 | 复杂场景模拟 |
| wrk | 轻量HTTP压测 | 快速基准测试 |
| ab (ApacheBench) | 简单易用 | 入门级压测 |
| Lighthouse | 前端性能评测 | Core Web Vitals |
| Chrome DevTools | 实时性能分析 | 前端渲染/网络瓶颈 |

## 三、性能瓶颈分析

### 3.1 前端瓶颈

| 瓶颈类型 | 表现 | 分析工具 | 常见原因 |
|---------|------|---------|---------|
| 渲染阻塞 | 首屏加载慢 | Lighthouse/DevTools | 大量同步JS、未优化图片、未代码分割 |
| 重渲染 | 交互卡顿 | React Profiler/DevTools | 状态更新粒度过大、缺少memo |
| 内存泄漏 | 长时间使用后卡顿 | Chrome Memory | 闭包引用、事件监听未清理、DOM引用 |
| 网络瀑布 | 串行请求过多 | Network面板 | 未合并请求、未预加载、HTTP/1.1 |
| 包体积 | 加载时间长 | webpack-bundle-analyzer | 未tree-shaking、重复依赖 |

### 3.2 后端瓶颈

| 瓶颈类型 | 表现 | 分析工具 | 常见原因 |
|---------|------|---------|---------|
| 数据库查询 | 接口慢 | EXPLAIN/slow query log | N+1查询、缺少索引、全表扫描 |
| CPU密集 | 响应时间长 | profiling工具 | 复杂计算、正则回溯、序列化 |
| 内存 | OOM或GC频繁 | heap dump | 内存泄漏、大对象缓存、连接池过大 |
| I/O阻塞 | 吞吐量低 | iostat | 同步文件操作、日志写入 |
| 连接池 | 请求排队/超时 | 连接池监控 | 连接池过小、连接泄漏 |

### 3.3 数据库瓶颈

| 瓶颈类型 | 表现 | 分析工具 | 常见原因 |
|---------|------|---------|---------|
| 慢查询 | 单查询耗时高 | EXPLAIN ANALYZE | 全表扫描、索引失效、JOIN过多 |
| 锁竞争 | 并发时超时 | pg_locks/SHOW ENGINE INNODB STATUS | 长事务、死锁、锁粒度过大 |
| 连接数 | 连接耗尽 | pg_stat_activity/SHOW PROCESSLIST | 连接泄漏、连接池配置不当 |
| 磁盘I/O | 写入慢 | iostat | 大量写入、WAL/binary log过大 |

### 3.4 缓存瓶颈

| 瓶颈类型 | 表现 | 分析工具 | 常见原因 |
|---------|------|---------|---------|
| 缓存穿透 | 大量未命中 | 缓存命中率监控 | 查询不存在的数据 |
| 缓存击穿 | 热点key过期时雪崩 | QPS监控 | 热点key无过期或无互斥锁 |
| 缓存雪崩 | 大量key同时过期 | 过期时间分布 | 过期时间集中 |

## 四、性能优化决策树

```
开始性能优化
├── 1. 确认性能目标是否已定义？→ 否：先定义SLA/SLO和性能需求
├── 2. 建立基准 → 运行基准测试，获取P50/P95/P99
├── 3. 定位瓶颈 → 使用分析工具确定瓶颈类型
├── 4. 分析根因 → 根据瓶颈类型深入分析
├── 5. 制定优化方案
│   ├── 前端优化：代码分割/懒加载/缓存/减少重渲染
│   ├── 后端优化：异步/连接池/批处理/算法优化
│   ├── 数据库优化：索引/查询优化/读写分离/分库分表
│   └── 缓存优化：多级缓存/预热/失效策略
├── 6. 实施优化 → 最小化变更，一次优化一个维度
├── 7. 验证效果 → 重新运行压测，对比基准
└── 8. 回归或进入下一轮 → 性能达标则结束，否则回到步骤3
```

**优化原则**：
- 先测量再优化，避免过早优化
- 优先优化最大瓶颈（二八法则）
- 每次只优化一个维度，便于验证效果
- 优化后必须回归验证，确认无退化

## 五、容量规划指南

### 5.1 资源评估

| 资源类型 | 评估指标 | 计算方法 |
|---------|---------|---------|
| CPU | 峰值利用率 | 压测峰值 × 安全系数(1.5~2.0) |
| 内存 | 峰值使用量 | 单请求内存 × 预期并发 × 安全系数 |
| 磁盘 | 数据增长量 | 日增量 × 保留天数 × 压缩比 |
| 网络 | 带宽需求 | 峰值RPS × 平均响应大小 |
| 数据库 | 连接数/IOPS | 并发数 × 平均连接时长 |

### 5.2 扩容策略

| 策略 | 适用场景 | 特点 |
|------|---------|------|
| 垂直扩容 | 单机资源不足 | 简单，有上限 |
| 水平扩容 | 吞吐量不足 | 需要无状态设计 |
| 读写分离 | 读多写少 | 降低主库压力 |
| 分库分表 | 数据量大 | 架构复杂度高 |
| CDN/缓存 | 静态资源/热点数据 | 降低源站压力 |

### 5.3 降级方案

| 降级级别 | 触发条件 | 措施 |
|---------|---------|------|
| P0 | 核心服务不可用 | 紧急修复或回滚 |
| P1 | 非核心功能超时 | 关闭非核心功能 |
| P2 | 响应时间劣化 | 降级非实时数据 |
| P3 | 资源预警 | 提前扩容 |
