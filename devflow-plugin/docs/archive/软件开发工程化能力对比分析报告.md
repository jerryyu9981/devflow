## 一、执行摘要

DevFlow、Superpowers 和 gstack 并非彼此替代的关系，而是覆盖 AI 辅助软件开发不同剖面的三层互补框架。

| 框架 | 开发者 | ⭐ 影响力 | 定位 | 核心哲学 |
|------|--------|----------|------|---------|
| **DevFlow** | 你的团队 / DevFlow 维护者 | 私有仓库 | 全生命周期工程规范框架 | 规范驱动（22 个分层技能） |
| **Superpowers** | Jesse Vincent（obra） | ~170K ⭐ | Coding Agent 工作流方法论 | 纪律驱动（HARD-GATE 铁律） |
| **gstack** | Garry Tan（YC CEO） | ~117K ⭐ | AI 开发团队决策把关层 | 角色驱动（23 个斜杠命令） |

简单来说：

- **DevFlow** 覆盖最广——从版本规划到部署运维的 Step 0-5 全生命周期，以及文档、模板、追溯矩阵、CI/CD、可观测性等工程管理能力；
- **Superpowers** 执行最深——HARD-GATE 禁止跳过规划、子代理两阶段评审、worktree 隔离、TDD 内嵌于计划模板；
- **gstack** 决策最强——CEO 视角判断投入产出比、浏览器真实 E2E 测试、23 个工程师角色分工。

三者结合，才能匹配 Anthropic Harness 架构的最佳实践：决策与执行分离、生成与评估分离、知识跨会话沉淀。

## 三、架构对比

### 3.1 DevFlow 三层联邦架构

```
┌─────────────────────────────────────────────────────────┐
│              L1 总控调度（3 技能 — 运行时预加载）         │
│  devflow-init · devflow-phase-manager · devflow-project-config │
├─────────────────────────────────────────────────────────┤
│              L2 阶段执行（6 技能 — 运行时预加载）         │
│  version-planning · requirements · design               │
│  coding · testing · operations                          │
├─────────────────────────────────────────────────────────┤
│              L3 专项参考（10 技能 — 按需加载）            │
│  coding-conventions · static-quality · logic-review     │
│  cicd-pipeline · observability · api-contract           │
│  prototype-coverage · backend-coverage                  │
│  document-templates · version-backup                    │
├─────────────────────────────────────────────────────────┤
│              Skill Config（3 技能）                       │
│  project-development-workflow · project-document-management │
│  project-role-management                                │
└─────────────────────────────────────────────────────────┘
```

**加载策略**：L1/L2 启动时预加载在所有会话中可用；L3 按需加载，仅当触发条件匹配时加载。

### 3.2 Superpowers 会话流架构

```
SessionStart Hook
  └─ 注入 bootstrap（< 2K tokens）
       └─ using-superpowers/SKILL.md（1% 强制规则）
            └─ 流程图：是否适用任何技能？
                 ├─ 是（即使只有 1% 可能）→ 调用 Skill
                 └─ 否 → 进入 Brainstorming（HARD-GATE 禁止跳过）
                      └─ 提出设计方案 → 用户批准
                           └─ writing-plans（TDD 内嵌 + 禁止占位符）
                                └─ subagent-driven-development
                                     ├─ 每个 task 派发独立子代理
                                     └─ 两阶段评审（规格 → 质量）
                                          └─ verification-before-completion
                                               └─ finishing-a-development-branch
```

### 3.3 gstack 7 阶段流水线

```
/office-hours → /plan-ceo-review → /plan-eng-review
     → 编码 → /review → /qa → /ship → /reflect
```

每个步骤的输出自动成为下一步的输入，类似工厂流水线。

## 六、各框架独特优势

### DevFlow — 8 项不可替代的能力

1. **全生命周期覆盖**：Step 0 版本规划到 Step 5 部署运维，22 个技能无死角
2. **工程文档体系**：49 种文档类型 + 19 个文档模板，团队产出标准化
3. **追溯矩阵**：需求 → 设计 → 开发 3 层关联矩阵，可审计可回溯
4. **技术栈适配**：Python(FastAPI) / Java(Spring Boot) / Go / Node.js + Vue/React 全覆盖
5. **API 契约管理**：6 个环节（设计→编码→Mock→测试→CI→部署）全链路管控
6. **CI/CD 流水线**：5 阶段 + 8 质量闸门 + 性能基线管理
7. **版本备份**：3 种分支策略 + Git 原生 mirror + 自动 backup hook
8. **可观测性**：日志/指标/追踪三大支柱，14 种关键指标，6 个 Dashboard

### Superpowers — 6 项不可替代的能力

1. **HARD-GATE 铁律**：模型被禁止跳过设计步骤，不允许"偷懒"
2. **1% 强制规则**：只要有 1% 的可能性技能适用，就必须调用
3. **子代理两阶段评审**：每个 task 用全新子代理实现 + 先规格审查后质量审查
4. **worktree 隔离**：每个 feature 独立 git worktree，互不干扰
5. **TDD 内嵌于 plan 模板**：每个 task 默认 RED-GREEN-REFACTOR，不是建议是强制
6. **禁止占位符**：TBD/TODO/implement later/fill in details 等全部是 plan 失败

### gstack — 6 项不可替代的能力

1. **CEO 评审**：产品视角判断需求价值、投入产出比，会说"你不要做这个"
2. **浏览器真实 E2E 测试**：启动真实 Chromium 浏览器做用户全流程操作验证
3. **23 个角色分工**：从 CEO 到 QA 到安全官，覆盖完整工程团队角色
4. **设计变体生成**：一次性生成 4-6 个设计方案，设计师评审打分
5. **安全系统测试**：OWASP Top 10 + STRIDE 威胁模型，首席安全官角色
6. **自动发布**：跑测试 → 开 PR → 等合并 → 部署全自动化

## 八、结论与推荐

### 按团队类型推荐

| 团队场景 | 推荐组合 | 原因 |
|---------|---------|------|
| 小型团队、需要全流程规范化 | **DevFlow 即可** | Step 0-5 全覆盖，22 个技能涵盖了从规划到运维的所有能力 |
| 已有 DevFlow + 需要编码执行纪律 | **DevFlow + Superpowers** | DevFlow 提供规范和文档，Superpowers 提供 HARD-GATE 和子代理执行 |
| 已有 DevFlow + 需要决策把关 | **DevFlow + gstack** | DevFlow 提供工程治理，gstack 提供 CEO 评审和浏览器测试 |
| 极致全栈 | **DevFlow + Superpowers + gstack** | 三层互补：gstack 把方向 → Superpowers 执行 → DevFlow 管全生命周期 |

### 关键决策建议

1. **如果你最头疼的是项目流程混乱、文档缺失、追溯困难** → 优先上 **DevFlow**
2. **如果你最头疼的是 AI 编码时跳过设计、不做测试、质量不可控** → 优先上 **Superpowers**
3. **如果你最头疼的是方向拿不准、上线有 Bug、需要决策把关** → 优先上 **gstack**
4. **如果你三者都头疼** → 按 "gstack → Superpowers → DevFlow" 的顺序依次接入

### DevFlow 的演进方向

DevFlow v2.3.0 的 22 个技能已整合了部分 Superpowers + gstack 的思想（TDD 铁律、完成前强制验证、文件范围保护、系统化调试、跨模型审查），但仍可从两者吸收更多能力：

| 待吸收能力 | 来源 | 优先级 |
|-----------|------|:------:|
| 子代理两阶段评审 | Superpowers | P1 |
| 浏览器真实 E2E 测试 | gstack | P1 |
| 产品决策评审 | gstack | P2 |
| 知识沉淀/跨会话复用 | Compound Engineering | P2 |
| worktree 隔离开发 | Superpowers | P3 |
